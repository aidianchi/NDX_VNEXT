## 施工清单（逐项，最小改动）

### N2-1 竞争假说清单进 IA

- `IntegratedSynthesisReportBuilder.build()` 已有 `event_layer_summary` 参数；新增逻辑：从 run 目录 `synthesis_packet.json` 读 `competing_hypotheses`（build 没有该参数就由 `write_integrated_synthesis_report` 读取后传入，或在 build 内接受 `competing_hypotheses: Optional[list]=None`）。
- `_llm_adjudication(...)` 增加 `competing_hypotheses` 参数；payload 加 `"competing_hypotheses": [{hypothesis_id, hypothesis_text, status, source}]`（截断 ≤12 条，文本每条 ≤300 字符；字段名以实读 synthesis_packet 为准）。
- `integrated_adjudicator.md` 输入清单加一行：`competing_hypotheses`：治理链的竞争假说清单（数据侧内部的对质结果，用于判断事件卡与哪些假说相关）。
- 测试：合成 final/cards/questions，build/`_llm_adjudication` 用 Fake llm_caller 跑一次，断言 payload 含该键且条数/字段正确。

### N2-2 ESS（事件报告）进 IA

- `_llm_adjudication` 增加 `event_layer_summary` 参数；payload 加 `"event_layer_summary"`：取 `event_layer_summary` 里的 governed 总结正文/摘要字段（以实读 `event_layer_summary.json` 结构为准，如 `governed_summary`/`summary_text`/`cards` 的摘要；把可用文本截 ≤1500 字符，空则 `{"summary": "", "cards_available": false}`）。
- 提示词输入加一行：`event_layer_summary`：第二层自己的事件报告（与逐卡材料同属候选材料层，可与数据判决对质）。
- 测试：断言 payload 含该键且文本来自传入 summary。

### N2-3 question_answers 事件侧引用通道

- `contracts.py` 的 `IntegratedQuestionAnswer` 加可选字段 `event_refs: List[str] = Field(default_factory=list, description="事件侧引用（仅第三层对质可用，不得进第一层）")`；model_validator 的 `answered_by_data` 判据**不变**（事件 ref 不能替代数据 ref）。
- `_llm_adjudication` 组装 questions 时，把 `cross_layer_questions.questions[].event_refs` 一并带进 payload（≤20 个/题）；`_parse_and_validate`/`_sanitize_*` 对 `answer.event_refs` 做存在性清洗：只保留出现在 payload 事件卡 id（`event:` 前缀）或本 question 的 event_refs 里的 id，非法丢弃并记 note `rejected_unknown_event_ref:`。
- `integrated_adjudicator.md` 的 question_answers 说明加：`event_refs` 可选；`answered_by_data` 仍必须有 `data_refs` 或 `investigation_refs`；事件 ref 只用于解释事件侧来源。
- 测试：合成 question 带 event_refs，Fake 响应 answer 带合法+非法 event_refs，断言合法保留、非法进 notes；`answered_by_data` 且只有 event_refs 仍降级/打回（按现有判据）。

### N2-4 失败调查占位进 IA（A6）

- `build()` 传给 `_llm_adjudication` 的 investigation_reports 改为**全量**（不再 `not r.get("is_deterministic_stub", True)` 过滤），但 payload 内分两栏：
  - `investigation_reports`：非 stub 报告的 compact（现有 `_compact_investigation_for_prompt`，≤3 条）；
  - `investigation_gaps`：stub/失败报告的占位 `[{investigation_id, status: "deterministic_stub"/"llm_failure", note: "本调查未返回有效报告"}]`。
  - `allowed_investigation_ids` 保持非 stub 报告 id（stub 不可引用为查证依据）。
- 提示词输入加：`investigation_gaps`：有调查委托但未返回有效报告，不得当作已查证。
- 测试：合成 3 份报告其中 1 份 stub，断言 payload 两栏正确、allowed_investigation_ids 只含非 stub。

### N3 外部世界章节标签化

- `vnext_reporter.py` 的 `_event_mechanism_report_section`：
  - 每条事件卡 `event_row` 增加标签：`<span class="tag sans">候选材料</span>`，并在 meta_line 追加"未经第三层对质"（已有 tier/read_state 并列）。
  - 章节开头（section-note）加声明："本节展示的是第二层候选材料，带认识论标签，未经第三层综合裁决；判断以数据层为准。"（brief 与完整模板共用该函数，两处都覆盖）。
- 测试：合成 mechanism 卡 + artifacts，渲染 brief 相关 section（或直接调 `_event_mechanism_report_section`），断言输出含"候选材料"与"未经第三层对质"、含声明句；已有 reporter 测试不破坏。
