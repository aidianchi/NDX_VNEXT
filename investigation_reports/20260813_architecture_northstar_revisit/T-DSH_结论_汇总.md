# T-DSH 结论汇总（2026-08-15，待所有者过目）

来源：`T-DSH_A面_架构需求.md`、`T-DSH_B面_DSH剖析.md`、`T-DSH_红队_独立意见.md`（三路独立、互不读对方），根线程对质汇总。证据细节在三份底稿，本文只写结论与失效条件。

## 结论（三选一：②）

**DSH 不能当 v1 数据链/治理链的编排器；v1 继续用现有 Python 编排器。DSH 是第二层 agentic 补采的候选运行时（不是唯一选项），且带硬条件。**

## A × B 对质摘要

| A 面硬需求 | DSH 本机证据判定 |
|---|---|
| 可复现重跑 / 按 effective_date 批量回测（P0） | 需自造。会话日志可重放，但工作流明文"无 journaling/resume"、无 timestamped 产物目录；headless 只是"一次任务的一次性会话"。 |
| 每站隔离可事后证明（落盘-grep）（P0） | 需自造。DSH 是事前可见性/文件权限边界，不是按站 prompt 审计；默认全文检索关、zstd 压缩、无按站目录。 |
| effective_date / 时间窗口全链强制（P0） | 当主编排器＝根本冲突：DSH 无此概念，且 agent 可自由用 bash/Python 读"现在"，拦不住未来信息；当第二层可降为"每条来源带时间戳"的自造镣铐。 |
| Python 数据层（Wind/pandas/SEC）原样可编排（P0） | 可等价达成：bash shell out 调用 Python，数据层不必重写。 |
| 治理纪律 / 发布闸门 / 证据白名单机械校验（P0） | 需自造：这些都在现有 Python 骨架（schema、校验器、证据注册表）里，DSH 不原生提供。 |
| 失败软着陆 + 降级留痕 + 断点续跑（P1） | 需自造。工作流无 checkpoint/resume；jobs 进程内。 |
| 第二层 agentic 补采隔离接口 + 来源标签词表（P2） | 部分原生契合：子代理、目标循环、持久会话正好是补采层需要的东西；文件沙箱和来源词表仍需自造。 |

## 特别必答：DSH 当第二层 agentic 补采的可行性

**可行，但只是候选运行时，带硬条件（缺一条则不可行，退回自建 Python 小循环）**：

1. 补采产物只进 IA/展示位，永不进第一层；DSH 会话日志必须导出到 run_dir 归档（否则审计分裂在 ~/.dsh 里）。
2. 每条采集材料必须带来源等级 + 采集时间戳（四条镣铐），DSH 的自由工具调用不能绕过这条。
3. 回测模式下 agentic 补采整体可关闭（否则污染校准底账）。
4. 先用 20 条真实任务测试集 + 五项度量验收 DSH 原型，不达标退回自建。

## 失效条件（出现任何一条，推翻本结论）

1. 若有人证明能在 DSH 侧完整重建现有 Python 骨架（固定 DAG、阶段 schema、sha256 断点、effective_date 闸门、证据注册表）且 DSH 只跑固定 DAG——则"不能当编排器"被推翻（但那时 DSH 只是进程容器，收益仍待证）。
2. 若第二层自建 Python 原型被证明无法满足三档补采，且 DSH 原型跑通并通过五项度量 + 四条镣铐的验收——DSH 在第二层从候选升为采用。
3. 若 DSH 会话日志导出到 run_dir 的桥接被证明不可行，或沙箱写边界不可靠，或第二层最终不需要 agentic 循环——连第二层也退回自建，结论走向 ③。

## 对 C7 的直接含义

C7 补采原型按 T48 原方案"自焊小循环（复用 llm_engine）"开工，**不**为原型引入 DSH 作运行时；把 DSH 留作"自焊原型验收后、若需要更强 agentic 能力再对质的候选"。harness 选型因此不再是 C7 的前置，C7 可立即施工。
