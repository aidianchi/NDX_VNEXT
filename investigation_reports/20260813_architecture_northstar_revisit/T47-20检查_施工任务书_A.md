## 检查清单（每条公式；具体字段名以 03 报告 §3 与实读代码为准）

**PC-01 critic/risk 分料身份检查（A1 的 C3 版）**
读 `prompt_audit/critic/attempt_1.payload.json` 与 `prompt_audit/risk/attempt_1.payload.json`（若目录下有 retry 则各取最新 attempt）。断言：
- critic 的 `governance_input.thesis_main` 非空且含字符串；
- risk 的 `governance_input.thesis_main == ""`，且 `thesis_key_support_chains == []`、`thesis_hypothesis_responses == []`；
- 两个 governance_input 序列化后不逐字节相同。
任一不满足 → failed。

**PC-02 治理站引用全集对账（A2 的 C3 版）**
- 从 `thesis_draft.json` 收集全部 evidence_refs（遍历 key_support_chains、hypothesis_responses、portfolio_actions、time_horizon_views、reader_conclusion、principal_contradiction、secondary_contradictions、price_reflection_map 等字段，与 `_build_governance_input_packet` 的收集面一致）；从 `synthesis_packet.json` 的 `competing_hypotheses` 中 source=="counter_thesis" 的假说收集 support/counter/diagnostic_evidence_refs。
- critic/reviser/final 的 governance_input.key_evidence_refs 必须 ⊇ 上述并集（只对引用名存在于 evidence_index 的条目比对，不存在于索引的名字不算漏——那是另一条检查）。
- risk 的 key_evidence_refs 必须 ⊇（冲突 evidence_refs ∪ layer_summaries.indicator_refs）∩ evidence_index；risk 不得包含仅 thesis/counter 引用、且冲突/层摘要都没引的 ref。
- 任一不满足 → failed，detail 列出缺失 ref 的前 5 个。

**PC-03 final 输入含修订内容（A3 + 拍板②）**
- 读 `analysis_revised.json` 与 final 的 payload。final 的 thesis_* 应等于 `analysis_revised.revised_thesis` 对应字段（degraded_fallback 时允许等于原稿）；`revision_summary` 应非空或存在 `thesis_original` 键。装配点②尚未上线前，若 `thesis_original` 不存在，判 `passed=False, detail="thesis_original 未上线（待 C6 装配点②）"`——诚实报缺，不许当通过。

**PC-04 IA ref_authority unknown 占比告警（A5）**
读 IA 的 prompt payload（`src/integrated_synthesis_report.py` 装配，产物在报告目录，具体文件用 grep 找到其 prompt_audit 落点或从 `integrated_synthesis_report.json` 旁审计字段推断；找不到就 failed=缺失 artifact）。`ref_authority` 中 usage=="unknown" 的占比 > 50% → failed（阈值写在模块常量，注释标明来自 03 报告 A5）。

**PC-05 委托调查 vs 进 IA 报告数对账（A6）**
`inquiry_router_output.json` 的 agent_specs 数量 vs IA payload 的 allowed_investigation_ids/investigation_reports 数量（stub 也算报告）。不等 → failed，detail 注明"失败调查静默缺席（C8 待修占位装配）"。

**PC-06 CI 材料闭合性 + 立场字段检测（A7）**
读 controlled_investigation 各 attempt 的 payload/prompt：每个 `[M#]...[/M#]` 块内 JSON 必须可解析闭合；材料文本中不得出现 `dominant_side`、`action_implication`、`不宜重仓`、`触发核心仓` 等立场/仓位字段（装配点未修前会 failed，detail 注明"待 C6 装配点"）。

**PC-07 事件字段恒空（A9 反向断言）**
bridge 与 critic/risk/reviser/final 的 payload 中 `event_refs`/`key_event_refs` 必须缺失或为空集合；非空 → failed（三明治：非空即污染事故）。ESS/IA 不在此检查范围。

**PC-08 同名指标多值检测（A11）**
扫描 L1-L5 层 payload 与 layer_cards，同一 metric/指标名（PE、OBV、expected_return 等）在不同条目出现且数值不一致 → failed，列出指标名与两个值。

**PC-09 约束/指令引用键存在性（B1/B10）**
扫描各站 prompt 正文中 `raw_data`、`NO_DATA_AVAILABLE`、`analysis_required` 等指令点名，与 payload 实际键对账：指令点名且 payload 没有、也没有明确"可选"说明 → failed。

**PC-10 事件站措辞矛盾共存检测（B2）**
扫描 event_card_interpreter 与 event_section_summary 的 prompt 正文，检测 03 报告 B2 点名的成对矛盾措辞共存（以报告原文为准，例如"必须带指定词"与"措辞完全由你决定"类）。矛盾对共存 → failed。
