## 三、发现的问题（按严重度排，P1-1 / P3-1 请带着上面的态度读）

### 🔴 P1-1：第三层"批评-回应"没跑成——商榷：高度怀疑是校验规则过严

- **事实**：第三层综合总判决（IA）的对质环节调了两次 GLM，两次都成功返回、内容也写得完整（第一次的产出我看过，写得挺像样），但**两次都卡在解析校验**，整体降级为空——报告里"综合裁决"章节用的是确定性兜底的版本，不是 AI 对质产物。给第三层配的"批评者"（草稿→挑刺→定稿回应）也没轮到执行，"批评者真挑刺"验收项悬空。
- **老板的看法**：**这不是模型的错，是校验规则本身很可能有毛病**。两份内容完整的响应被死规矩卡掉，是"实际上没问题的东西白费"的典型。规矩应该放宽，而不是去修模型。
- **待办方向（改）**：立专项，**重审第三层对质的解析校验规则**——看卡的是什么、哪些条件不合理、怎么缩减/放宽/重构。不是"查模型为什么不合规"。顺带一个小工程改进：校验失败在日志里是静默的、没有痕迹，重审时让失败原因落盘，方便判断到底是真违规还是规矩冤枉人。

### 🔴 P1-2：太慢，一半时间其实是白等的（并行提案见第四节）

- 五层分析师 28 分钟、十张事件卡 32 分钟，全是**一个接一个排队**，而这两组各自内部互不依赖，可以同时跑。

### 🟡 P2-1：报告开篇排版不友好（老板亲测"懒得看"）

- 开篇大标题 145 个字（历史最长：08-17 是 72 字、08-26 是 98 字），字号 31px 还大。
- 正文 1292 字一整段（历史最长，08-26 是 703 字），不分段。
- **为什么现在不分段（08-28 考古结论，别赖模型）**：渲染层 `_reasoned_verdict_html`（`vnext_reporter.py:6603`）是**按空行（\n\n）切段**的——模型输出里带空行就分段，不带就一整段。07-28 那版（DeepSeek 跑的）输出自带 3 段空行分隔，所以显示成 3 段；08-27 这版（GLM 跑的）输出一整段无换行，就成 1 段。**分段一直靠模型自觉**：①提示词 `final_adjudicator.md` 从头到尾没有"分段/分条"要求（grep 零命中）；②渲染层没有兜底切段逻辑，模型不给空行就一团。这是"关键排版赌在模型心情上"的系统脆弱点，不是模型变笨了。
- **改法（老板已确认，只动排版不删字）**：大标题字号调小（31 → 24px 左右）；大标题允许换行；正文渲染时按"第一条/第二条/第三条理由"锚点切成多段——**不再依赖模型输出格式，分段从运气变确定**。

### 🟢 P3-1：三处契约失败——商榷：很可能是规矩太苛刻（"必涨必跌"例外，要再审）

## 四、并行省时提案（人话版）

### 为什么慢
整个流水线像**只有一个窗口的银行**：二十多个岗位排队办业务。其中两段最冤：
- 五个数据分析员各看各的账本，互不搭界，却排队一个个办（28 分钟）；
- 十张事件卡各对照自己的新闻，也排队一个个办（32 分钟）。

### 改什么（只改两处，约 50 行）
1. 五层分析师**同时跑**（28 分钟 → 8~10 分钟）；
2. 十张事件卡**同时跑**（32 分钟 → 5~8 分钟）。
依赖链（分析→对质→调查→辩论→事件卡）一根不动。

### 一个先说清的误会
"事件卡和五层能不能也同时跑？"——**不能**。事件卡干活前必须拿到"正反方假设清单"，而清单要等五层→对质→调查→辩论全部走完才生成（代码 `orchestrator.py:1653` 明明白白）。硬等，没得商量。

### 怕什么、怎么防（四件事）
| 怕什么 | 防法 |
|---|---|
| API 公司限流（同时要数据被拒） | 先开 3 个窗口试水，确认不被打再开到 5 |
| 台账记串（各窗口同时往同一本账上记） | 记账加锁，一个人记完另一个再记 |
| 断点续跑失灵 | 专门写测试验证：续跑时该跳过的全跳过 |
| 出问题难排查（日志混在一起） | 每条日志标上窗口名 |

### 怎么证明没搞坏（四步）
假模型测试（不花钱，验证不丢文件不串账）→ 真模型冒烟（花几毛钱看拒不拒绝）→ 对照跑（同一份数据串行 vs 并行，比耗时比质量）→ 灰度上线（先 3 个窗口跑真实 run，稳了再放开）。
