# event_section_summary 上下文体检报告

## 结论

本站基本健康：无 P0/P1 硬伤，D1 越权扫描干净，输出闭环完整（10 张卡全部被引用、边界句落位、无死指令）。Runtime Input 占 89.4%（18,761 字符）装的是 **10 张事件卡的全文**（每卡含 fact_summary + interpretation + limitations + needs_data_confirmation 全字段），这是本站的任务对象而非冗余搬运，属合理设计；但 limitations/needs_data_confirmation 约 3.7k 字符存在可压缩空间。主要病灶均为 P2：时间红线措辞过严导致输出字面违规（幸为良性）、任务描述宣称的「机制假设」字段在输入中不存在、上游卡片黑话向输出轻度传染 1 处。

## 体检明细

### A. 顺序

- **A1 段落编排** — 判定：合理 — 证据：结构为 System 纪律（L1-11）→ User 任务+铁律（L13-31）→ Runtime 数据（L34-267）→ 输出规格（L269-271）→ Response Rules（L273-278）。任务定义在数据之前、输出规格紧贴 Response Rules 收尾，主干未被数据切碎。输出规格离任务描述稍远（隔了 18.7k 字符数据），但规格仅 2 个字段且 User Message 末尾（L28-29）已就地复述 `summary_text` 要求，洼地风险低。
- **A2 数据时序** — 判定：合理 — 证据：10 张卡按 published_at 严格新→旧排列（9/2 15:34 → 9/2 13:08 → 9/1 → 8/28 → 8/27，L46/194/200/222/244），与「本轮这几天发生了什么」的收束语义一致。
- **A3 few-shot 打断** — 判定：无示例，不适用。
- **A4 重试差异** — 仅 1 个 attempt，不适用。

### B. 体量与冗余

- **B1 体量账本** — 判定：合理（带 P2 优化项）— 证据：段落目录显示 Runtime Input 18,761（89.4%）、User Message 1,413（6.7%）、其余 4 段合计仅 3.9%。按 payload 实测，Runtime 内 10 张卡字段量为：fact_summary 4,807 + interpretation 4,269 + limitations 2,050 + needs_data_confirmation 1,697 + 元数据（id/citation/tier/source/日期）约 1,563。**这不是「卡片摘要」，是上游 event_card_interpreter 产物的全文搬运**——对本站是必要的：段落摘要必须基于卡内容，fact_summary+interpretation（约 9.1k）是核心燃料；needs_data_confirmation（1.7k）也与任务句「这些事件在给数据层出什么题」（L14）直接对应，算活。可压缩的是 limitations（2.1k）：10 张卡中 9 张的 limitations 首条都在重复 tier=reliable_mainstream_report 已含的「第三方转述、非官方披露、未经核对」语义（如 L50、L72、L94），顶层 boundary.note（L265）又做了第三次汇总。
- **B2 站内重复** — 判定：P2 — 证据：① title_only 规则写了两遍：User Message L24「如果输入里 title_only_card_count 超过卡片总数一半…」与 boundary.note L265「本轮 10 张卡中有 1 张 raw_text_available=false…」近义重复；② 引用规则两遍：L20 与 boundary.citation_rule L264 几乎逐字（「代码会从正文里的 [card:...] 标记自动提取」两处全同）；③ 每卡 citation 字段（290 字符）是 event_id 的机械拼装，10 处共 290 字符冗余。均为小体量，无同一数字多处冲突。
- **B3 粒度错配** — 判定：未发现 — 输入是散文卡片而非行情序列，无逐行 dump 问题；卡内数字已由上游 interpreter 消化成结论句。

### C. 质量

- **C1 指令冲突** — 判定：P2（1 对措辞级冲突）— 证据：时间红线（L22）「绝不能写出晚于 `effective_date` 的日期」为字面全禁；但卡片 needs_data_confirmation 自带未来检验点（L165「2026-09-04公布的8月非农就业报告」、L166「2026-09-10的PPI与2026-09-11的CPI」），且任务要求写「给数据层出什么题」必然要提这些未来日期。输出（output.validated.json）因此写了「9月4日非农就业、9月10日PPI、9月11日CPI三组尚未公布的数据和9月15-16日的FOMC会议」——**字面违反红线、意图上完全正确**（全部标注「尚未公布」，未把后见事实写成已发生）。规则该写的是「不得把晚于 effective_date 的事实写成已发生」，而非禁止出现日期本身。
- **C2 死指令** — 判定：未发现（抽查 5 项全活）— ① `summary_text`：输出有，1,861 字符 2 段；② `[card:...]` 引用：输出含 10 个，与 L20/L36 规则一致；③ `cited_event_ids`：输出有 10 项，与 L271「由代码正则提取」闭环；④ 结尾边界句：输出以「以上事件材料不构成主证据，判断以数据层为准。」收尾，与 boundary.must_end_with（L263）逐字一致；⑤ title_only 承认义务：仅 1/10 张卡仅标题（L258），未过半数红线，输出仍主动交代「另有一张仅有标题、未读到正文」——超额合规。另注：L31「口径说明（代码侧回退，不属于你的职责）」整段是写给代码的注释，对模型是纯噪声，可移出 prompt。
- **C3 黑话词典** — 判定：P2 — 清点（「法典」经全文检索 **0 次**，不在本站）：系统自造词全部藏在 Runtime Input 的卡片 interpretation 里，prompt 自身（System/User 段）不产黑话：「建设性对抗假说」×4（首现 L64，卡2 interpretation）、「主线假说」×3（首现 L42，卡1）、「吸收引擎」×5（首现 L64）、「多头对抗假说」×1（L152）、「收束员」×1（L14，语境可自释）、「数据对质」×1（L14）、「第三层综合裁决」×1（L26，「第三层」编号无解释）。**全部无首次解释**，一个新模型只能靠上下文猜「主线假说/建设性对抗假说」是两个竞争假说框架。这些是上游 event_card_interpreter 的产出词汇，本站属受害者而非传染源；但它们确实流入了输出（见 E1）。
- **C4 数据新鲜度** — 判定：合理 — 证据：effective_date=2026-09-02（L36），卡片 event_date 区间 8/27–9/2，最旧 5 天且卡内自带分寸（L51「持仓为截至6月末的快照…约两个月的空窗」）；卡 8（L195）还主动标出「页面行情模块…与正文所述QQQ盘中跌0.9%的时间口径不一致」。无过期数据冒充当前状态。

### D. 隔离

- **D1 越权扫描** — 判定：未发现越权 — 证据：全文检索 `final_adjudication`/`thesis_draft`/`browser_sidecar`/`user_decision_profile`/`golden_pit`/`apparent_cross_layer_signals`/layer card 路径 **全部 0 命中**；boundary（L259-266）显式声明 `event_material_only: true`、`must_not_reference_l1_l5: true`，User Message L19 反向锁死「禁止提及或转述 L1-L5 数据层的任何指标、读数或结论」。作为新闻 sidecar 隔离观察的一部分，本站没有把新闻内容当可引用证据：输出中全部数字带「据报道」「若核实属实」「数字出自媒体转述」限定（如「据报道，9月1日长端美债收益率升至约4.78%的一年高位」「（数字出自媒体转述，该文对英伟达市盈率的两处表述还互相矛盾）」），并以边界句收尾。隔离设计执行到位。

### E. 输出闭环

- **E1 叙事字段体检**（叙事字段 = `summary_text`，1,861 字符，2 段，符合 L25「一到两段」要求）：

## 修复建议

1. **改时间红线措辞**（对应病灶 1）：User Message L22 改为「不得把晚于 `effective_date` 才发生或才知道的事实写成已发生；未来数据检验点可以提，但必须标明『尚未公布/待公布』」。消除字面冲突，保住意图。
2. **对齐任务描述与输入 schema**（病灶 2）：L14「每张卡含事实摘要、解读、机制假设、来源等级」改为与实际字段一致（「事实摘要、解读、机制归类（financial_link）、来源等级」），或上游补齐字段——二选一，别让描述指向不存在的字段。
3. **黑话治理在上游做**（病灶 3）：event_card_interpreter 的输出规格里要求假说框架词（主线假说/建设性对抗假说/吸收引擎）首现给半句解释，或改用中性表述（如「多头叙事」「需求消纳能力」）；本站 prompt 可加一句「卡片中的假说框架词在正文中改用平语」。
4. **压缩 limitations**（病灶 4）：喂给本站时把每卡 limitations 折叠为一句（首条多与 tier 重复），预计省约 1.2k 字符；或顶层只保留 boundary.note 汇总。
5. **去重规则与清噪**（病灶 5、6）：boundary 与 User Message 二选一保留 title_only/citation 规则（建议留 User Message、boundary 只留机器可校验字段）；删除每卡 citation 字段与 L31 口径说明段（后者移到代码注释）。
