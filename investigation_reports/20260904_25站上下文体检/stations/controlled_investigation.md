## 结论

有病灶，病灶在**材料供给侧与任务路由**，不在模型执行。最重两条：① **材料按固定预算截断且只给源 artifact 的 ~7.5%**，截断点切在词和值的中间，尾部还用无解释的「甲」字符填充到定长——5/5 实例的 `cannot_establish` 各有至少 1 条把「材料截断」列为无法确认的原因，这正是上游 risk 站已实锤的「调查员污染市场风险叙事」因果链的源头（本次从源头逐例验证成立）；② **4/5 的调查问题是 bridge memo 自己 `unresolved_questions` 的原文，材料又是同一份 memo**——自指循环：调查员用一次 LLM 调用，把 memo 里已经写明的「当前数据无法区分」复述一遍，信息增量为零。模型本身执行优秀：14 处数字/引语抽查全部可溯源，无编造（E1 通过）。

## 体检明细

- **A2 数据时序** — 判定：合理（但见 C4）。材料是快照型综合产物而非时序序列，无旧→新倒置问题；真正的时序问题是材料**完全没有时点标注**，归 C4。
- **A3 few-shot 打断** — 判定：无 few-shot，不适用。
- **A4 重试差异** — 不适用（全部单 attempt）。

### B. 体量与冗余

- **B1 体量账本** — 判定：合理。以 inv_480530965a5d（总 5,281 字符）为例：模板 1,032（19.5%）、调查问题 52（1.0%）、材料 4,197（79.5%）。inv_f938b9165cc0（总 9,272）：模板 1,032（11.1%）、问题 41（0.4%）、材料 8,199（88.4%，两份材料）。模板 5 实例逐字相同（各 1,032 字符），是合理的固定任务书；最大段是材料本身，符合本站定位。问题不在占比，在材料**内容被砍剩多少**（见 B3）。
- **B2 站内重复** — 判定：P2。4/5 实例（480530965a5d、f41ad82edbe1、8d29613c190e、ef5f875d5ac2）的调查问题文本**逐字**出现在材料 preview 的 `unresolved_questions` 里（如 480530965a5d：L24 问题 = L32 preview 内第 2 条未决项，原句「CCC-BB尾部走阔是特质性再融资问题还是BB→IG系统性传染前兆——当前数据无法区分。」两处一致；8d29613c190e 同句在 preview 内出现 3 处：unresolved_questions、principal_contradiction、key_uncertainties——输出自己数了出来："被三处重复登记"）。约 200-600 字符的重复，浪费小，但它是②自指循环的直接症状。
- **B3 粒度错配（本站主菜）** — 判定：P1。材料不是「预处理好的摘要」，而是**按字符预算的位置截断 dump**：
  - bridge_memos/bridge_0.json 源文件 45,507 字节，4 个实例各只见到 preview 解码后 ~3,420-3,430 字符，**覆盖率 7.5%**；
  - layer_cards/L1.json 源 43,250 字节，inv_f938b9165cc0 的 [M1] 见 ~3,527 字符，**覆盖率 8.2%**；
  - 截断点切在词/值中间：inv_f938b9165cc0 的 [M2] 末尾是 `"counte` + 填充（L41），[M1] 末尾是 `"normalized_state": "t` + 填充（L42）——一个字段值被切成半个字母；
  - 截断后用「甲」字符**填充到定长预算**：5 实例甲填充 18-47 字符不等（480530965a5d 32 个、8d29613c190e 43 个、ef5f875d5ac2 37 个、f938 [M1] 18 个 + [M2] 47 个）。源 artifact（bridge_0.json、L1.json）中「甲」出现次数为 **0**——填充来自材料打包代码，prompt 任何位置都没有解释。垃圾 token 直接进了「只能依据以下内容」的材料区。
  - 后果实例化：信用问题实例可见的数字几乎全是利率/估值类——inv_480530965a5d 输出："可见数字均属利率与估值类，无一为信用利差"；inv_f938b9165cc0 输出：`get_fed_funds_rate_path 的 normalized_state 字段值在[M1]预览截断处中断不可读`。而 memo 里其实**有**裁决所需的部分读数（CCC-BB 8.97pp/100分位、混合OAS、IG 0.81% 稳定），是否可见取决于它落在 7.5% 窗口内的运气。

### C. 质量

- **C1 指令冲突** — 判定：P2（任务设计自缚，非条款打架）。铁律 1「只能依据材料原文推理」（L4）与材料 note「完整内容在磁盘 artifact，禁止据此补全未显示内容」（L31）组合的净效果是：系统给一份 92.5% 缺失的材料，并明文禁止补全——`cannot_establish` 的产出是结构性保证的，不是模型保守。另有一处轻度张力：L20 要求「字段名……不进叙事字段」，而材料本身全是字段名/ID，inv_f938b9165cc0 输出把 `reflected_state=unclear`、`misread_guards` 写进了叙事——轻微违反，可辩护（模板允许结构字段例外）。
- **C2 死指令** — 判定：基本全活。抽查 confidence / cannot_establish / limits / 材料编号纪律：输出均有，且被下游真实消费——`integrated_synthesis_report.json` 明文引用 `[inv_480530965a5d]`、`[inv_8d29613c190e]` 的结论组织叙事；run 根 `investigation_reports/inv_*.json` 归档了全部 5 份。发现 1 处 harness 兜底痕迹：inv_f41ad82edbe1.json 的 `normalization_notes` 记录了 7 处材料编号被归一化补齐——模型偶有漏标 [M#]，合约校验前被代码修掉，纪律实际由「模型+修复器」共同执行。

## 修复建议（对应病灶，不动手实现）

1. **（截断）按问题相关性选段，而不是按预算切位置**：打包材料时先定位与调查问题相关的节（如信用问题 → `price_reflection_map.credit` + `key_uncertainties` 全文），预算花在刀刃上；截断处改用显式 `«…截断 N 字符…»` 标记，禁止切在字段值中间。
2. **（甲填充）删除填充逻辑**：预算不满就留白，或注明「此处为预算填充，无信息」；任何进材料的字节都必须要么是 artifact 原文、要么是显式标注。
3. **（自指循环）改问题路由**：若问题所需数据在其他 artifact（如 L2 layer card 的信用读数），把**该 artifact 的相关节选**入包——本 run 4 个信用问题没有一个拿到 L2.json，全部只拿到提出问题的 memo；若问题的答案就是「缺数据」，别派 LLM 调查，memo 里已经写了，直接让综合链引用原文。
4. **（JSON 断裂）输出规格加一条**：字符串内引用原文须用中文引号或转义；harness 修复器增加「断句合并」步骤，碎片条目不得入库。
5. **（时点）材料包头加 `effective_date` / 数据截止字段**：一行元数据即可消灭 5/5 实例的时效类 cannot_establish。
