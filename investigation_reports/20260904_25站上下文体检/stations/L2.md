# L2 风险偏好分析师 上下文体检报告

> 站：L2（全链第二肥站）｜原文 508,119 字符 / 16,978 行｜投影压缩到 15.6%
> 材料：`prompt_audit/L2/attempt_1.prompt.txt`（下称原文，行号+字符 offset 均出自此文件）、`output.validated.json`（输出存在，走正常路径）

## 结论

L2 有一个巨大的、单点性的体量病灶：**prompt 的 84.6%（430,096 字符、2,490 行日线序列）是 VIX 期限结构 raw_series 的逐行全量 dump**，而模型做本层判断所需的聚合值（分位、样本数、contango 状态、阈值）全部已由预处理算好并在场——模型输出从头到尾没有引用过序列中的任何一行。除此之外材料质量相当好：隔离干净、时序正确、无指令冲突，输出端叙事质量高（复读机检测 0 命中）；唯一被证实的「材料→输出」因果是内部代号「法典」无解释直出叙事散文 7 次。

## 体检明细

### A. 顺序

- **A1 段落编排** — 判定：合理 — 证据：指令块占 char 0–24,802（4.9%）：System 约束（L1-6）→ Canon → few-shot → 层契约 → L2 角色纪律（Output Discipline，原文 L725-737 区段）；Runtime Input 占 char 24,802–506,279（94.8%）；输出字段规格 + Response Rules 在最尾部（char 506,279–508,119）。输出规格贴着生成点（recency 位），任务定义在头部，安排是标准的「指令-数据-规格」三明治，未见重要指令被埋进数据中段。
- **A2 数据时序** — 判定：合理 — 证据：raw_series 按旧→新升序（2016-08-25 → 2026-08-25，最新行在原文 L16730）；FGI 提供 previous_close/1w/1m/1y 递推序列；无过期段落冒充当前状态。唯一时序瑕疵归入 C4。
- **A3 few-shot 打断** — 判定：合理 — 证据：4 个 Example（get_vix/vxn/hy_oas_bp/ig_oas_bp）位于原文 L434-456（char 约 9-10K），在层契约与运行数据之前，未把「任务定义→数据→输出要求」主干切碎。
- **A4 重试差异** — 不适用：本站仅 attempt_1。

### B. 体量与冗余

- **B1 体量账本** — 判定：P1（单点失衡）— 账本（字符量/占比）：
  - `get_vix_term_structure.value.percentile_context.raw_series`：**430,096 字符（84.6%）**，char 67,408–497,504，原文 L1794-16735；
  - Runtime Input 其余部分（context_brief + layer_facts + 其余 12 个指标的 raw_data）：约 51,381 字符（10.1%）；
  - 指令块（Canon/契约/镜头/纪律）：24,802 字符（4.9%）；
  - 输出规格 + Response Rules：1,840 字符（0.4%）。
  - 必要性判据（「删掉判断会变差吗」）：不会。判断所需的全部聚合值已在同一段落内预计算——`percentile_5y=76.6 / percentile_10y=67.4`、`sample_count=1232/2490`、`term_structure_state="contango"`、状态阈值 ±0.5% 缓冲带（原文 L1811-1850 区段）。序列 dump 自带的使用说明也只声称审计用途：「足以独立重算 windows.5y / windows.10y 两个分位」（原文 L16736）。输出验证：模型 11 条 indicator_analyses 无一处引用序列历史行，仅用了最新行与预计算分位。
- **B2 站内重复** — 判定：P2 — 证据：
  - 同一数值三层复读：`2.65` 出现 12 次、`16.34` 12 次、`8.97` 9 次、`1.1786` 9 次，分布在 context_brief.layer_highlights → layer_facts.core_signals(+summary) → layer_raw_data（value + notes + methodology + formula）四处；
  - 每个指标的 methodology 与 formula 字段逐字相同（如 get_vix 原文 L959-960），再与 notes 三写同一句话；
  - `metric_authority.reason` 用英文复读 IndicatorCanon 的 misread_guards（get_vix：原文 L972 "high is not a buy signal and low is not proof of safety" ≈ L55 "VIX 高本身不是买入信号，VIX 低也不自动等于安全。"）——同一教学点中英各讲一遍。
  - 体量影响有限（重复块约几万字符，主要在 data_quality 样板 ~30 字段 × 13 指标），故 P2 不升 P1。
- **B3 粒度错配（本站主菜）** — 判定：P1 — 精确数字：
  - **序列是什么**：`^VIX / ^VIX3M` 每日收盘内联表，**2,490 行 × 每行 4 字段**（data_date / vix / vix3m / ratio_vix3m_over_vix），覆盖 **2016-08-25 → 2026-08-25 整整 10 年**（原文 L1794-16735）；
  - **体量**：每行 6 行文本、平均 172.7 字符，合计 430,096 字符 = prompt 的 **84.6%**、Runtime Input 的 **89.3%**；行数占 prompt 总行数 **88.0%**（14,942/16,978）；
  - **模型本层判断真正需要的**：最新比值 1.1786、状态 contango、5y/10y 分位 76.6/67.4、样本量与阈值——共约 15 个标量，全部已由预处理提供。min/max（vix 9.14-82.69）在原文里**连摘要都没有**（投影工具自己补的 stats 块原文中不存在）；
  - **定性**：这是把「预处理该干的活」（序列→统计量）以审计之名整体推给了模型注意力。430K 字符买来的唯一能力是让模型「可以手工重算分位」——一个下游永远不会做的动作。若删除，本站 prompt 从 50.8 万字符降到约 7.8 万（-84.6%），L2 将从全链第二肥站变成正常体量站。

### C. 质量

- **C1 指令冲突** — 判定：P2 — 冲突对 1：输出字段规格（原文尾部，「输出字段规格」char 506,279 起）把 `permission_type, canonical_question, misread_guards, cross_validation_targets, falsifiers, canon_dispute` 列为 IndicatorAnalysis 形状的一部分；而 Canon Output Hints（原文 L381）说这六个字段「不用你填；填了也会被法典值覆盖」。模型实际填了（输出 22,902 字符中 2,148 字符是这组 echo），无害但白费输出 token。未发现 P0 级冲突对。
- **C2 死指令** — 判定：P2 — 抽查结果：`local_conclusion`（233 字符，≤500 守约）、`core_facts`、`quality_self_check`、`cross_layer_hooks`（4 条，覆盖强制要求的 L4/L3 + 条件触发的 L5/L1）、`canon_dispute` 均活。死引用嫌疑：IndicatorCanon 的 `cross_validation_targets` 指向 **本层上下文中不存在的 7 个指标**（`get_advance_decline_line`、`get_qqq_technical_indicators`、`get_atr_qqq`、`get_net_liquidity_momentum`、`get_copper_gold_ratio`、`get_ndx_ndxe_ratio`、`get_percent_above_ma`，原文 L57-60 等多处）——在隔离上下文里是「不可见的交叉验证对象」。模型正确处理为「待 Bridge 验证」，未编造，故只算设计瑕疵。
- **C3 黑话词典** — 清点：
  - **「法典」**：prompt 出现 3 次，首现原文 L381（「填了也会被法典值覆盖」），**无任何解释**它指什么（只能猜是 Deep Research Canon / RESEARCH_CANON 的口语化）。新加入的分析师模型只能靠猜。**列入传染源**（且确实传染了，见 E1）。
  - 「分层降噪」：21 次，首现 L447 few-shot「分层降噪V5.8」，紧随其后给出机制示例（MA5 vs MA20），半解释状态；未渗入输出散文，不算传染源。
  - 「4C」：1 次，标题后紧跟展开「语境化、精炼化、典范化、因果化」（原文 L432），有解释，不算。
  - VIX/OAS/contango 等通用金融术语不列。
- **C4 数据新鲜度** — 判定：P2 — `get_vix_term_structure` 的 data_date=2026-08-25，距运行时点 09-02 **滞后 8 天**，而其 `effective_date` 却填 2026-09-02（原文 get_vix_term_structure.data_quality 块）——字段名暗示「生效于今天」，值却是一周前的；context_brief 的 data_summary 有预先免责（「早于运行时点属正常时点纪律」）。模型本次靠自查发现并显式降置信（输出 risk_flags `term_structure_data_stale_by_a_week`、narrative「读数截至8月25日…降低置信」）。另：CFTC/FINRA 两项官方数据因上游 SSL 错误不可用，已按数据边界诚实保留，未补估。

### D. 隔离

- **D1 越权扫描** — 判定：合理（未发现越权）— 证据：`final_adjudication`/`thesis_draft`/`browser_sidecar`/`user_decision_profile`/`golden_pit`/`layer_card` 关键词在原文中 **0 命中**；`apparent_cross_layer_signals` 为空数组；context_brief 与静态五层本体均明确「只用于路由，不代表当前状态」；隔离纪律条款在位（L484-488）。输出端 cross_layer_hooks 全部是提问式（「待L4验证」「待L3验证」），无跨层结论越权。

### E. 输出端闭环

- **E1 叙事字段体检**（对象：local_conclusion / layer_synthesis / internal_conflict_analysis / 11 条 indicator_analyses 的 narrative/reasoning_process/first_principles_chain）：
  - **黑话传染**：命中。「法典」在输出中出现 **7 次**，其中 5 次在读者可见的叙事散文里（get_hy_oas_bp.reasoning_process「按法典它是核心信用事实」、get_vix_term_structure.narrative「按法典contango不是看多证据」、get_cnn_fear_greed_index.reasoning_process「法典明确」等）。材料侧无解释（L381）→ 输出直出，因果成立。P1。
  - **复读机检测**：以 25 字符窗口对全部叙事字段与原文做重叠扫描，**0 命中**（比清单要求的 15 字符更严）。6 个逐字 echo 字段（canonical_question 等）属 Canon 装配义务，不算背题。叙事是 composed 不是 recited。
  - **簿记语言密度**：数字全部嵌在因果链里服务比较（如 local_conclusion「混合HY OAS 2.65%（≈265bp，3.7分位）极紧…构成名义risk-on；但CCC-BB分层利差8.97个百分点（≈897bp）处于100分位且走阔」），枚举/ref/ID 住在结构字段，符合文风约定。
  - **长度纪律**：local_conclusion 限 500 字符，实际 233 ✓；其余叙事字段无长度要求。
- **E2 因果对**：
  1. **成立（P1）**：材料缺陷「法典首现无解释（原文 L381）」→ 输出毛病「叙事散文直出未解释内部代号 7 次（output.validated.json：indicator_analyses[9].narrative、[2]/[4]/[5]/[10].reasoning_process、[10].first_principles_chain[3]、quality_self_check.confidence_limitations[3]）」。
  2. **不成立（明说）**：430K raw_series dump → 本 attempt 输出**未观察到**对应缺陷：复读机 0、叙事全部基于预计算聚合、模型甚至主动发现序列尾部滞后 8 天并降置信。它目前是成本与风险敞口（注意力稀释、token 成本），不是已兑现的输出毛病——但把「模型会不会在 43 万字符噪音里失焦」当系统性赌注，一次 attempt 的好结果不构成豁免。
  3. **轻微（P2）**：「不用你填」提示（L381）被模型无视 → 输出携带 2,148 字符 canon echo（约 9.4%），下游会被覆盖，无实际伤害。

## 修复建议

1. **（对应 P1-B3）把 raw_series 移出 prompt**：预处理端补一行统计摘要（min/max/最新 N 行/样本数——分位与 sample_count 本来就算好了），序列本体落 artifact 文件供审计下载，不进模型上下文。预期本站 prompt 508,119 → 约 78,000 字符（-84.6%），「足以独立重算分位」的审计诉求由文件满足。
2. **（对应 P1-C3）「法典」正名**：首次出现写成「指标法典（RESEARCH_CANON，即上文 Deep Research Canon）」，或在「叙事字段文风约定」的禁入清单里把「法典」与验证等级/字段名并列为簿记语言。
3. **（对应 P2-C1）统一 canon 字段填写义务**：输出规格中给这 6 个字段标注「（由代码装配，可省略）」，或直接从模型可见 schema 中移除。
4. **（对应 P2-B2）data_quality 瘦身**：methodology 与 formula 二选一；metric_authority.reason 与 IndicatorCanon.misread_guards 去重（同义只保留中文一处）。
5. **（对应 P2-C2）cross_validation_targets 附目标层标注**（如 `L3.get_advance_decline_line`），让模型一眼知道这是「待 Bridge 路由」而不是「本层应找到」。
6. **（对应 P2-C4）为滞后指标加显式字段** `latest_available_date` + `stale_days`，把「滞后一周」从模型自觉发现变成结构化事实。
