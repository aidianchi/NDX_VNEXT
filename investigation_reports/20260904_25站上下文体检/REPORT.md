## 二、真问题清单（每项：是什么 / 证据 / 为什么是病 / 修法）

### 问题 1｜原始数据整车进 prompt（搬运病）——唯一的大杠杆

**是什么**：行情/财报的原始序列与逐成分股明细整段塞进 prompt，而输出对它们零引用。模型岗是判读指标，不是当人肉 Excel。

**证据（站级明细，全部实测）**：

| 站 | 零消费字节 | 占本站 | 内容 |
|---|---:|---:|---|
| L2 | ~430K | 84.6% | VIX 期限结构 2016→2026 十年日线 ×4 字段逐行（原文 offset 67,408–497,504）；输出 11 条指标分析零引用 |
| L4 | ~280K | 44% | `get_ndx_earnings_revision_metrics` 逐成分股 dump（96-102 条 × 多份副本，连 `archive_path` 都带进去了）+ 24 年财报日期史 |
| critic | ~105K | 28% | 装配时 5 个 L4 ref 被换成逐股全量变体（根源见下） |
| reviser | ~100K | 46% | 标为「对照用」的 53 条全字段证据卡（真正的反馈只占 3.9%——主菜倒挂） |
| thesis | 29.5K | 10% | M7 公司级逐季明细（聚合版 `#m7_aggregate` 明明已单独存在） |
| risk | ~60K | 17% | 4 张逐股 dump（risk 只消费聚合值） |
| L1 | 23K | 29.9% | `get_fed_funds_rate_path` 内嵌 130 条期货逐日观测，输出零引用 |
| L5 | ~20K | 30-40% | 同一数值（ADX/ATR/现价）各重复 7 次、O10 notes 同文 4 处 |

**膨胀根源（第四遍复审定位）**：governance 重建 `key_evidence_refs` 时，5 个 L4 ref 选了**逐股全量变体**（thesis 侧同 ref 是聚合版）：`#slope_30d` 5,017→57,554、`#breadth_30d` 3,399→23,772、`m7_capex#companies` 14,787→32,775、`m7_buyback#per_company` 14,699→25,352、`m7_capex#m7_aggregate` 3,722→7,540，合计膨胀 **~105K**。这也解释了「critic 的包（205.9K/53 键）为什么比 thesis 的菜单（152.4K/93 键）还大」——critic 的 53 键全部是 thesis 93 键的子集，48 键逐字相同，差就差在这 5 个变体。

**为什么移出 prompt ≠ 信息丧失**（2026-09-04 老板之问，正面回答）：

原始序列「可以转化成一个东西」的理解是对的，但精确说法是：**不是转化成结论，而是转化成判读量**（分位、斜率、拐点这类测量值）——结论仍由模型下。做到不丧失要满足三个条件：

1. **档案不删，只出注意力。** 全量序列整体留 artifact 落盘。「事实扎实」支柱要的是数字**可独立重算**——落盘回查即可满足，不需要塞进模型注意力。反过来说：让模型从 43 万字符里心算分位才是不可审计的；代码预计算的统计量每个都能重算，反而更符合宪法。
2. **预计算停在测量层，不碰判断层。** 预先算什么不由人拍脑袋，由各层指标法典（`RESEARCH_CANON.md` 及各层法典）已定义的判读量决定——latest / 分位 / 斜率 / 关键拐点。L4 现成机制 `_summarize_l4_raw_data_for_prompt`（`orchestrator.py:8118`）就是这个形态（latest/start/end/count/percentile/拐点）。若预计算直接产出「贵/便宜」式结论即违宪（指标不得越权）——那是模型的岗。
3. **缺口有路可回查。** 预计算没覆盖模型需要的新角度时，走受控调查员按需调材料，或下个 run 改法典。⚠️ 注意：这条路目前是断的——调查员材料包正被截断到 7.5%（问题 3），**修建议 #7 是移出 prompt 的安全网前提**。

**如实记录一个真实残余风险**：预计算嵌入假设——窗口/特征选错，模型就看不到某个角度。缓解：口径与法典绑定（法典演进走人工决策流程）+ 拐点保留 + artifact 全量兜底。

**修法（建议 #1，已从「造机制」降为「推广机制」）**：
① 把 L4 现成的序列摘要机制推广到 L2/L1/L5（路由 `orchestrator.py:7758` 扩两层）；
② governance 重建 `key_evidence_refs` 改选与 thesis 相同的聚合变体（critic/risk 各 -~105K）；
③ reviser 53 条对照卡同路径受益。
预期收益：砍真 dump ~89 万字符（~24%），多站同时受益，机制现成、风险低。

**正面样板**：L3——Runtime Input 仅 26.9K 覆盖 6/6 指标，全靠上游预处理到位。**其他站该长的就是 L3 那样。**

### 问题 2｜final 重试整套重发

- **证据**：final_adjudicator 首次 attempt 输出未过验证后重试，attempt_2 整套重发 ~20 万字符上下文，实际只追加 1,024 字符反馈（重复 >99.5%）。且磁盘上两次 attempt 实为两次独立 invocation，**第一次失败的原始响应已被覆盖丢失**——重试链路自己的账都记不清。
- ** probable 根因（推断性质，已标注）**：单次返回 27 字段、成功样本 52,600 字符的巨型输出规格，首次解析失败概率高（「材料→输出」因果对 #8）。
- **修法（#5）**：重试只发增量（验证错误 + 反馈），不重发全量；重试成本 -99%。顺带修重试的留痕（保留失败响应）。

### 问题 3｜采集侧脏料：事件卡与调查员（脏料病重灾区）

1. **网页抓取噪音**：10 张事件卡的 `raw_text_excerpt` 有 8 张混入 24-62% 的导航/广告/页脚/行情挂件（a691a49a 45%、5d714693 62.2%、c5ee0104 62%、69b3ccdf 42%）。两张卡（5d714693/c5ee0104）的页面行情组件里有**两个互相矛盾的比特币报价**（77,132.93 vs 63,925.97，差 21%）——铁律允许「逐字收录材料里有的数字」，换个弱模型行情挂件价格就进事件卡。多张卡是模型主动在 limitations 里拆弹——**正确性目前靠模型注意力，不靠材料质量**。
   **根源（2026-09-04 追溯定位）**：这批全文是 8-31 T68「Yahoo 正文打通（代理+解析守卫修复）」后的**第一批**——此前这些事件均为仅标题（T47 的 70% 缺口），不是以前干净、是以前没正文可吵。噪音不止 Yahoo 自家页面（Goolsbee / Berkshire 两张卡开头就是「Oops, something went wrong Skip to navigation」错误模块），还包括 Yahoo 聚合的第三方站（Benzinga 全站语言菜单/登录栏、24/7 Wall St. 站头、fool.com）；账本 10 事件 9 条 `raw_text_available=True`，全部经 `_fetch_article_body` 新通路抓取。清洗器 `_ReadableTextParser` 的跳过名单（`news_event_ledger.py:265`：script/style/noscript/svg/nav/header/footer/form）**缺 `aside` 与行情挂件模块容器**，且摘录取可读文本**头部** 8000 字符（`_clean_text` 即 `text[:8000]`）——商业站把导航/模块放页头，噪音恰好全落在开头。对照组：federalreserve.gov 的卡干净，官方源无此病。
2. **时态拼接矛盾**：69090f89 摘录开头「英伟达财报超预期」与后文「财报发布前下跌」无过渡拼接，模型把财报当未来检验点，漏读了开头已给的事实（因果对 #6）。
3. **仅标题材料进主链**：91736ca4 零正文零数字（`raw_text_available: false`）被标 mainline + `upgrade_candidate: true`，输出近半是「不能确认」的元讨论。「弱来源不进主链」宪法字面只管最弱档，是否违宪存疑待定性（建议 #9 前置准入检查）。
4. **调查员材料截断**（risk 污染链的源头）：bridge_0.json 只给 7.5%、L1.json 给 8.2%；截断点切在词/值中间（`"counte甲甲甲`、`"t甲甲甲`），尾部用无解释的「甲」字符填充到定长——复审核实 **32-65 处/实例**（5 实例全部命中，源 artifact 中甲=0）；5/5 实例的 cannot_establish 各有 ≥1 条截断归因，一路污染进 risk 的市场风险叙事。（注：调查员「材料不足如实答 cannot_establish」本身是设计行为——不编造铁律的正确执行；病在材料包被截到 7.5% 还拿去出题。）
5. **调查员自指循环**：4/5 的调查问题是 bridge memo `unresolved_questions` 原文，材料又是同一份 memo——产出是把 memo 已写的「当前数据无法区分」复述成 JSON，信息增量为零。只有 f938（L1 缺口体检）是匹配良好的调查。

**修法**：#3 剥 boilerplate（采集端修一次，10 卡受益）；#7 修甲填充与切词截断、自指问题改由 bridge 先自查；#9 仅标题事件准入前置检查。

### 问题 4｜黑话传染（「为什么不说人话」的实锤）

机制：prompt 里反复出现又无解释的内部词，输出叙事跟着直出。完整词典见第四节；传染源规律很清楚——**基本都来自「竞争假说块」和段标题级黑话**。输出端文风纪律本身执行得不错，挡住了大部分，但挡不住高频无解释词。修法（#4）二选一：首现处加半句解释，或从 prompt 里删词（优先：法典、三明治口径、竞争假说块全套）。

## 三、经四遍复审确认「不是病」的（防误伤清单）

### 3.1 正面确认（实测有效的机制，施工时别动）

1. **层间隔离零 P0**——架构命脉干净，25 站越权扫描零命中。
2. **论证盲分料实测守住**：risk 的 237,719 字符材料包里 thesis 论证字段**零个**——08-15 的分料设计在真实 run 里有效。这个正面确认当初 agent 都没报，因为它是「没坏的东西」。
3. **risk 七字段分流零死链**：四个叙事字段（`must_preserve_risks`×10 / `opportunity_costs`×4 / `confirmation_costs`×3 / `false_safety_risks`×6）渲染级实锤进 reviser 与 final 的 prompt——这是「修订者不许把风险哨兵坚持要保留的改没了」与「风险报告完整（含反向风险）」的机制载体（`risk_sentinel.md:92` 自述下游读者）；三个状态字段（`failure_conditions` / `boundary_status` / `conflict_matrix_check`）**按合约就不进模型**（`contracts.py:2102-2106` 的 reviser/final 包明文不含这三键），走代码消费：`vnext_reporter.py:3431-3484 / 4727-4750`（报告 watch_items=给读者的「何时认错」、边界状态区块）、`outcome_review.py:35`（事后校准回环）、claim_ledger 枚举、`legacy_adapter.py:454`（兼容导出）。**设计→合约→指令（`reviser.md:50/134`）→装配→渲染，五层对齐。**
4. **顺序与编排基本合格**：各站编排符合「指令头尾、数据居中、输出规格贴响应端」，few-shot 均未打断主干；唯一例外是 final 重试（问题 2）。输出端纪律整体好：thesis 45 个 evidence_ref 全部合法、hypothesis_id 回填闭环、复读机检测各站基本零命中、事件卡 fact_summary 数字逐项回查原文零编造。
5. **两个现成正样**：L3（瘦得健康，26.9K 覆盖 6/6 指标）；L4 序列摘要机制（`orchestrator.py:8118`，只差推广）。

### 3.2 撤诉清单（初判有病、终判没病；依据见附录 A）

**「三关」方法论（体检结论过三关才算数，已沉淀为标准）**：

1. **字节账**：量出现象（第一遍）。
2. **设计口径**：先查架构原文「当初为什么这么设计」，再判算不算病（第三遍）。判「重复算不算病」之前必读《系统说明书》对应节。
3. **数据流全通路**：追到消费端才算数——字段名 → payload → prompt 渲染三重验证；内容级追踪的探针必须用**数据原文片段**（JSON 序列化串当探针必假阴性：dict 字段重渲染后键序/格式变化）。
