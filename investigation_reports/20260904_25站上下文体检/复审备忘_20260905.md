- **第二关（设计口径）**：`src/tools_L2.py:560` 白纸黑字——"raw_series 覆盖至多10年……足以独立重算 windows.5y / windows.10y 两个分位"。设计意图=「把原始序列给模型以便独立重算」；该意图可由「artifact 落盘 + 代码预计算测量值」等价满足且更可审计，与 #1 修法兼容。L4 侧 `orchestrator.py:8118` docstring 同口径："长序列留在 artifact，prompt 只保留 latest/start/end/count/percentile/关键拐点"——预计算停在测量层，不碰判断层，合宪。
- **第三关（全通路）**：路由 `orchestrator.py:7759` —— `if layer.upper() == "L4": raw_data = self._summarize_l4_raw_data_for_prompt(raw_data)`，其余层只过 `_filter_layer_raw_data_for_prompt`（`orchestrator.py:8088`，只丢跨层指标与簿记字段，本层原始序列原样放行）。「路由只接 L4 一层」实锤。

### #7 调查员截断与「甲」填充

- **甲计数**：5/5 实例命中，32/43/37/32/65 处——正落报告「32-65 处/实例」区间 ✓；源 `bridge_memos/bridge_0.json` 甲=0 ✓。
- **形态细化**：甲不是散布，是每实例 1-2 个**连续甲串**垫尾（如 `"四个独立度量家族的甲甲甲…`、`"normalized_state": "t甲甲甲…`）；5 个 prompt 总长全部卡在 ~5,280 字符——**定长截断**实锤，切点在词/值中间。
- **第二关（设计口径）**：截断代码 `orchestrator.py:2637-2670`。设计意图本身体面：单块材料 4,000 上限、总额 12,000、发「合法截断信封」（`_material_truncated: true` + note「完整内容在磁盘 artifact，禁止据此补全」）；代码注释自书「不发半截 JSON」「绝不用切片切断 JSON」。**但 `excerpt[:preview_budget]` 恰恰把 JSON 切在任意字符**——信封靠 preview 是字符串字段保住语法合法，内容层是半句话+甲垫；甲填充是为「每块恰好贴住 4000」的对齐手段。设计标准语法层达标、内容层失守——报告判定成立，且修复不必推翻信封设计（切点回退 token 边界 + 甲换明示占位即可）。
- **占比口径**：实测材料块 3,954 字符 / 源 29,369 字符 = **13.5%**；报告「7.5%」未复现（口径疑为字节/含信封开销之差，方向一致——材料被截到约 1/8）。

### #5 final 重试整套重发

- **两层重试机制**（比报告更精确的形态）：
  1. `llm_engine.py:747` `for attempt in range(2)`——失败后**原 prompt 原样盲重发**（连反馈都不带）；
  2. `orchestrator.py:6145` 校验失败重试——`f"{prompt}\n\n上一次返回未通过结构校验，错误如下：\n{last_error}..."` 把反馈拼在**整套 prompt 尾部**再发，prompt_audit 的 attempt_2.prompt.txt（292,472 字符）尾部即此结构（错误定位 + 上次响应尾片段 + 「请仅输出修正后的 JSON」），反馈块合计 ≈1K。「整套重发、只补小额反馈」三层实锤（字段名级 6145 / payload 级 193,068 / 渲染级 292,472）。
- **留痕丢失**：attempt_1 文件 mtime 04:05-04:10（续跑成功 invocation），attempt_2 mtime 02:02-02:12（原 invocation 第二次失败）——**时间序倒挂**，续跑把原失败 attempt_1 槽位覆盖；现存 meta.json 只记录成功 invocation（attempts:1、retry_feedback:false）。「第一次失败的原始响应已被覆盖丢失」实锤（其残片仅存 debug_archive）。
- **巨型输出规格**：`attempt_1.response.raw.txt` 恰好 52,600 字符；`output.validated.json` 顶层字段恰好 **27 个**——「27 字段/52,600 字符」两数精确命中。
