### 教训 2：分母选错会让真问题被说成假问题，也会让假问题被说成真问题

> **权限校验覆盖 headline claims（8 条），不覆盖 supporting narrative（20 万字级）。**

### 教训 3：本次审计自身漏了一站，漏法值得记

`integrated_adjudicator`（报告里的「04·综合裁决」）**掉在七路的缝里**：③ 明确声明它不走 `orchestrator._run_stage`、不在自己领地；⑥ 只看得到渲染结果。是两路各自**如实交代了边界**，主对话才把线接上，进而查出一个真实缺陷（见 3.1）。

## 二、总结论：硬核 + 软壳

**地基比预期结实。** 八条常驻边界**没有一条是纯文档空头支票**，每条都能找到真实执行点；1055 项测试大部分是真闸门；`.env` 从未入 git、个人金额纪律真实守住；正反双方拿的是同一个 `synthesis_packet.evidence_index` 对象，代码层面做不出"给反方少发材料"。**最该担心的几种失败模式实测都不存在。**

问题不在"哪里烂了"，在**保护的分布不均匀**。同一形状反复出现：

| 维度 | 硬的部分 | 软的部分 |
|---|---|---|
| 权限校验 | 8 条可发布结论 | 20 万字支撑叙事 |
| 边界牙齿 | 层间隔离、弱来源不进主链（无现实绕过路径） | 其余 5 条部分强制 |
| 证据精度 | L1/L2/L4 有字段级登记 | **L3/L5 零登记**，永远只能整体引用 |
| 时点纪律 | 原始数据日期越界硬拦 | 模型自身后见之明拦不住（项目已诚实登记） |

**这不是设计失误，是自然演化**：能被硬拦的都被硬拦了，剩下的是"要么难拦、要么没人想到"的。

## 三、主方向 T38：上下文供给从"预先塞满"改为"渐进披露、按需取用"

### 3.1 问题的形状：不是一个案例，是 20 个（根因已定位）

**发现路径**：先在 `integrated_adjudicator`（报告里的「04·综合裁决」）提示词里发现一处自相矛盾——

```
"L2.get_vxn",                       ← 引用名在
"L2.get_vxn": "supporting_only",    ← 引用许可在
"…实际利率、VXN 和信用利差有没有同步支持？"   ← 必须回答的问题在
```
而 `30.84`（VXN 值）与 `87.2`（10 年分位）在这份提示词里出现 **0 次**。模型答"**本轮输入未提供 VXN 指数数值和分位，无法验证**"——**它说的是准确的实话**；同一份报告的 L2 层却完整显示 `VXN=30.84，10年百分位87.2%`。

**然后扫全站，发现 VXN 只是唯一被抓到的那个。** 主对话独立复算（脚本判据：该 ref 的所有出现行是否都只是清单项 `"ref",` 或许可项 `"ref": "权限",`）：

> **26 个 `L#.get_*` 形式的 allowed ref 中，20 个"有名无实"——只给了名字和引用许可，没给任何数值。**
> L1×4、L2×4、L3×3、L4×3、L5×6。分路 agent 按更宽的 34 条分母报 59%，主对话按 26 条报 77%；**绝对数 20 一致**。

**VXN 之所以被发现，只因为它恰好是一道直接提问的主语，模型不得不当场交代。另外 19 条没有同等力度的追问兜着——系统这次是被模型的诚实救的，不是被机制救的。**

**根因（分路 agent 定位，代码已核）**：`integrated_synthesis_report.py:644-674` 的 `_allowed_data_refs` 扫描的是**未裁剪的完整对象**（含 `claim_ledger`/`key_support_chains`/`price_reflection_map`），而 `:299-318` 的 payload 构造只复制 **7 个叙事字段**。**两个函数各自独立决定"该看什么"，从未对齐，也没有任何测试断言"许可清单 ⊆ 实际传输内容"。**

量化：`final_adjudication.json`（47,282 字符）中 **86.2%（40,762 字符）未传给 integrated_adjudicator**，最大单块是 `claim_ledger`（24,978 字符，占 52.8%）——**幽灵 ref 恰好采集自这未传的部分**。

**"裁掉多少"是有意设计**（`_llm_adjudication` 明确只挑 7 个字段控 token，与 `GovernanceInputPacket` 同一压缩哲学，7 倍差距方向正确）；**"裁掉之后许可清单没跟着裁"是遗漏**。两者要分开评价。

跨 7 次 run 扫描：同类"VXN 缺失"措辞 0 次复现 → 该症状本次为新发，但产生机制是结构性的。

### 3.1b 同一根因的第二个实例：预算截断砍掉唯一带数值的材料

`controlled_investigation` 的三条调查中，`inv_e75efe82e7c0` 问的是"半导体链条、AI 权重股和盈利预期有没有同步改善"，但拿到的三份材料**全部是事件层摘要、零 L1-L5/Bridge 数值**。

链条：`orchestrator.py:1239-1244` 声明 4 个 `allowed_context_refs`，**唯一带数值的 `bridge_memos/bridge_0.json` 排在第 4 位**；`orchestrator.py:1877` 硬编码 `max_source_refs=3`；`orchestrator.py:2156` 做**位置截断、不做相关性重排** → 第 4 条被无条件砍掉。真实产物记录 `llm_failure` 后降级为 stub。

同批 `ADJUDICATION_GAP` 类消息因只声明 1 条 ref 未受影响——**同一预算上限，不同消息类型命运不同**。

**这与 3.1 是同一个病**：声明"你可以用这些"的地方，和决定"实际给你什么"的地方，是两处独立代码，中间没有闸门。

**"缺"和"冗"是同一个机制的两面：一次性全量推送 + 拼装点各自为政。**

### 3.2b 前缀缓存这条路当前基本拿不到（但原因是可修的）

主对话独立复算六站提示词的**逐字符最长公共前缀**：

> **仅 368-388 字符**，而各提示词长 209,854-247,717 字符——**公共前缀占 0.16%。**

根因是拼装顺序：`_compose_prompt`（`orchestrator.py:6384`）固定"**角色模板在前、数据在后**"，而各站角色模板长度不同，天然把高度重复的公共数据块挤到互不相同的偏移量（实测 `key_evidence_refs` 起始偏移 critic=1407 / risk=1613 / reviser=1223 / final=1688）。

**结论有两层**：
1. **现状**：内容高度重复，但标准前缀缓存一个字节都吃不到。任何"靠缓存省钱"的估算，在改变拼装顺序之前都是空的。
2. **但这是排序问题，不是架构问题。** 把共享数据块前置、角色模板后置，那 116K 字符就变成四站真正的公共前缀。**这是一次重排，不是重写。**

**与主方向的关系：两者互补而非互斥。** 前缀缓存优化**稳定部分**，渐进披露缩小**可变部分**——前提是稳定部分排在前面。若先做渐进披露而不管顺序，增加的往返轮次会进一步破坏前缀稳定性，两条路互相拆台。**顺序必须先定。**

### 3.3 思想：广度与成本必须解耦

**全量推送这个机制本身强加了一个两难**：

- 塞满 → 贵，且稀释注意力
- 剪枝 → 丢失未来可能需要的材料，且把菜单固化成"这一跑的视角"

T37 就卡死在这里：想砍那 68 条，但按引用率砍会让下次行情反转时反方需要的材料已经不在册，而**「菜单不得先天偏科」是常驻边界**。

**用户提出的第三条路（本次方向的思想来源）**：这个问题的解法很像 **Skill 的核心机制**——

> 常驻上下文里只有 name + 一行 description；模型判断"这次用得上"，才加载完整 SKILL.md；再往下还有 references，需要时才读。**三层递进。**

**关键洞察：「知道有这个东西」和「知道这个东西的全部内容」是两件事，成本差两个数量级。而前者已经足够让 agent 判断"我需不需要它"。**

证据菜单现在是**一层全展开**。改成分层供给，广度与成本就解耦了：**一条都不砍，只对真正用到的付全价。**

省的钱也比剪枝更多——剪枝省的是未引用条目那 28%，分层供给省的是菜单块那 67% 里的绝大部分。

### 3.4 三条设计原则（思想层）

**原则一：广度常驻，深度按需。**
菜单条目一条不砍。常驻的只有「编号 + 一句话它能回答什么」。这直接保住「菜单不得先天偏科」：反方下次需要的材料永远在册，只是不预先展开。

**原则二：索引即许可——把四个拼装点合并成一个。**
现在"引用许可"与"数值供给"是分开拼的，VXN 就死在这条缝里。改成按需取用之后，**"能取到"就是"有许可"，取不到就是没许可**。两件事合并成一件动作，缝在物理上消失。

这正是项目自定的「轨道 > 导出 > 规矩」第①档——**接口能强制的放进接口，模型零注意力成本，想违反都写不出来**。当前上下文是**手工拼的**，不是**导出的**；本方向就是把这条既有原则往上再走一层。

**原则三：筛选必须留痕——但"谁来筛"是一个必须先拍板的分叉。**

**⚠️ 2026-08-04 更正（外部调研纠正了本文件初稿的一处说法）**：初稿写"哪一站想用哪条，**它自己开口要**"。**这在当前结构下做不到。** 已核实：`_run_stage`（`orchestrator.py:5230`）每次尝试只调用一次 `call_with_fallback`，取 `tool_calls[0].function.arguments` 当**输出**——**工具通道是用来"交答案"的，不是用来"要数据"的，没有把工具结果回灌再问一轮的循环。** Skill 那种"agent 自主决定读不读某个文件"依赖多轮工具循环 + 文件系统权限，本项目两者都不具备。

因此有两条变体，**必须先选一条**：

| | **变体 A：代码侧检索**（调研推荐） | **变体 B：模型侧按需取用** |
|---|---|---|
| 谁决定取哪些 | 编排代码在组装提示词**之前**按该站声明的问题做相关性排序 | 模型自己发起取用调用 |
| 改动面 | 只改组装逻辑，站点仍是单次调用 | 单次调用改成循环 |
| 新增失败面 | 无 | 有（严格模式已实证 `tool_choice="auto"` 下模型可不走工具通道） |
| 前缀缓存 | 不冲突 | 增加往返，破坏前缀稳定 |
| **审计所得** | "**代码筛了哪 K 条、依据是什么、排除了哪些**" | "**它主动要了哪几条**" |

**审计价值的差别是实质性的**：变体 B 才能给出"模型想要什么"这个当前完全拿不到的信号；变体 A 给出的是"我们按什么规则筛的"——**仍然比现状（只知道塞了 102 条）强，但不是同一类信息。**

**无论选哪条，留痕都是硬要求**：这次筛选的完整结果（选中哪 K 条、排序依据、被排除的原始编号）必须作为 artifact 单独落盘，否则"为什么这一站没引用某条本该相关的证据"变得不可回溯——那才是真正的可审计性倒退。

**⚠️ 一个必须避开的陷阱（外部调研一手发现）**：相关性检索的锚点必须是「**该站声明的分析问题**」，**绝不能是「哪一方的结论」**。TradingGPT 的设计正是给多空双方各自独立的记忆库——**那会直接违反「菜单不得先天偏科」这条常驻边界**。安全做法：**正反双方用同一次检索、同一个 top-K 结果，只有立场措辞不同。**

### 3.5 已知代价与必须先想清楚的风险

诚实登记，不粉饰：

1. **【最高风险】按需取用可能成为绕过层间隔离的新通道。** 方向⑦评定「层间隔离」为"代码强制、未找到现实绕过路径"，2026-08-04 逐站实测**用真实提示词文本再次确认干净**：五层 `context_brief.apparent_cross_layer_signals` **全空**、`layer_highlights` 只含本层键、跨层 `L{n}.get_xxx` 全部出现在格式示例中且不带数值、`bridge_memo`/`thesis_draft`/`final_adjudication` 关键字**五层零命中**；counter_thesis 的"不得读取 thesis_draft"同样成立（该串 2 次命中均在禁止清单声明里）。

   **这是一份已经干净的资产，不是待修项——正因如此，引入取用接口时每一站的可取范围必须按层强制裁定。这条不解决，本方向不许动工。**
2. **与前缀缓存的先后顺序必须先定（见 3.2b）。** 现状公共前缀仅占 0.16%，缓存一个字节都吃不到，根因是"角色模板在前、数据在后"的拼装顺序。**若先做渐进披露而不先解决顺序，增加的往返会进一步破坏前缀稳定性，两条省钱路径互相拆台。** 且 `token_usage` 当前不记 `prompt_cache_hit_tokens`——**改之前先把它记进产物，否则做完也不知道有没有效。**
3. **模型可能"不知道自己需要什么"而漏取。** 需要配核心指标恒常驻的兜底档，不能全部按需。哪些恒常驻，是判断题不是技术题。
4. **增加调用轮次 = 增加延迟与失败面。** 严格模式已实证是概率性保证（`tool_choice="auto"` 下模型可不走工具通道），取用接口同样会有 opt-out 情形，必须有兜底。

### 3.6 站点全景与拼装点分布（内部实测已回，2026-08-04）

**站点穷举方法**（可复现）：全系统仅 3 个 LLM 调用入口 —— `orchestrator.py:5230/5232`（`_run_stage` 通用重试循环，14 种 stage 复用）、`orchestrator.py:1980`（`_build_investigation_report`，**不经 `_run_stage`**）、`integrated_synthesis_report.py:336`（由 `main.py:793` 调用，**整条链路不在 `VNextOrchestrator.run()` 内**）。与 `prompt_audit/` 真实落盘目录逐一互证。

**共 16 个 stage 类型**：L1-L5、bridge、thesis、counter_thesis、critic、risk、reviser、final_adjudicator、event_card_interpreter（本轮 10 实例）、event_section_summary、**controlled_investigation（不走 `_run_stage`）**、**integrated_adjudicator（不走 `_run_stage`）**。后两个正是本次两处 P0 的所在地——**与第一节教训 3 完全对应：脱离主流程的站点最容易失管。**

**拼装点：散落多处，且是两处 P0 的共同温床。** 模板层相对集中（`_compose_prompt` + 3 个专属预处理函数），但"该填什么数据"各自为政：L1-L5、bridge、thesis、counter_thesis、治理四站（共享构造函数但 4 个独立调用点）、controlled_investigation（**4 处独立手写 `allowed_context_refs`**）、integrated_adjudicator（独立文件、两个互不知情的函数）。

> **全系统没有任何一处做过"许可引用了什么"与"实际发送了什么"的交叉校验。**

这句话是本方向存在的全部理由。补上这道校验（纯集合包含关系，属身份比对、不判意思）是**代价最小、当天可做**的止血；而渐进披露是让这类缺陷**在接口上不可表达**的治本路径。

### 3.7 外部调研结论（2026-08-04 已回，全部基于一手来源）

方法：Claude Code / Anthropic 官方文档与工程博客逐篇核对；OpenAI Codex **直接 clone 源码逐文件读取**；TradingAgents 等 6 个金融多 agent 框架读论文全文 + 代码仓库；另检索 Cognition、Manus、LangChain、arXiv。

**总判断**：顶级 harness 的共识不是"更聪明的提示词"，而是把"这个 agent 该看到什么"从提示词搬到两个更硬的地方——**检索/选择层**与**协议/schema 层**。**这与本项目自定的「轨道 > 导出 > 规矩」是同一个判断**；调研的价值是找到了别人已经踩过坑、验证过的具体做法。

| 机制 | 判定 | 要点 |
|---|---|---|
| **静态前置、动态后置**（Claude/OpenAI 官方文档 + Codex 源码 + Manus 独立印证） | **能，直接可用** | 缓存要求**逐字节前缀匹配**；官方明确警告断点放在含时间戳的动态尾块会导致"每次全价重写、永不命中"。**零审计代价**（被缓存内容仍完整在 payload 里）。与 3.2b 的实测结论完全吻合 |
| **检索前置**（Claude Code MCP tool search / Codex `tool_search`，本地 BM25 非 embedding） | **需改造**，价值最高 | 两段式：常驻只给"名字 + 一句话"（Codex 硬截断到 250 字符、Skills 约 100 token），完整内容按需拉入且**统一放在提示词末尾**以不打乱稳定前缀。改造点即上文变体 A/B |
| **引用后置核验**（Anthropic 多智能体研究系统的 CitationAgent） | **能，且提升可审计性** | "引用对不对得上"不靠生成方自觉，而是**事后单设一站做定位核验**。与本项目「闸门不判意思，只判形状与身份」是同一原则的外部独立印证。已并入 T42① |
| **子 agent 默认隔离** | **验证性质，无需行动** | Codex `spawn_agent` 默认不继承父上下文，`fork_context` 是显式例外且理由是保住缓存前缀。Cognition 十个月内**推翻自己**：从"share full agent traces"改为发现干净隔离的评审 agent 表现更好（避免 context rot 与偏见继承）。**结论：本项目的层间隔离不是过度设计，比 Codex 默认更彻底。** |
| WorldState diff 式增量 | **不能照搬** | 依赖跨轮持久状态；强行引入会使"这一站当时看到了什么"无法从该站 artifact 独立还原，直接违反可审计北极星 |
| Skills 三级渐进披露 | **不能照搬**（思想已被检索前置吸收） | 依赖 agent 自主文件系统 + bash 权限；本项目站点是结构化输出调用，无此能力（见原则三更正） |

**金融多 agent 框架：先验判断部分成立，但需拆成两轴（调研独立结论，非附和）**

- **轴一（角色像不像人类职位）**：怀疑部分成立但非普遍规律。TradingAgents 论文自承 "Inspired by real-world trading firms' organizational structure"；FinRobot 代码里混着与金融无关的软件公司职位模板。但 6 个样本中**没有一个是从可推导的第一性原理反推角色数量的**——角色数普遍是拍脑袋定的。
- **轴二（上下文是否真的按角色差异化）——更本质**：TradingAgents 的 Bull/Bear Researcher 与三个风控子角色读的是**完全相同**的信息（字符级相似度实测 42%、骨架 100% 同构）；FinRobot 的 8 个 equity 子 agent 收到**完全相同**的一份提示词；StockAgent 是全员广播黑板。

> **本项目的 L1-L5 结构性隔离，比本次调研到的所有金融多 agent 框架都更接近第一性原理**——它们无一真正把"谁该看到什么"当结构性设计问题，全部退化成"共享同一黑板 + 人设标签区分立场"。
>
> **而 TradingAgents 的 Bull/Bear 重复，与本项目的 88% 重复是同一个病、同一病因——且该论文全文对此只字未提**（本次一手发现）。**本项目不是落后，是已经注意到了。**

**学术界现状：如实报告空白。** 未找到任何公开方法能自动推导"一次性、schema 约束、层间隔离的固定流水线"下每站的最小充分上下文（M2CL 需训练且面向反复讨论收敛；"Less Context, Better Agents" 自认是人工超参数经验比较；Graph-based Target Back-Propagation 需多轮迭代信号）。**本项目 schema 强制 + evidence_ref 硬编号的做法在这个问题上没有可对标的公开方案——不是落后，是这块目前没人系统解决。**

**一条命名上的收获**：MAST 论文（arXiv 2503.13657，调研方已核实原文）把"某站被要求回答问题、却没拿到对应数据"这类失败正式命名为 **FM-2.4 "Information withholding"**。3.1 那 20 条幽灵引用属于学界已归类的通病，不是孤例——**这既说明它不是本项目独有的低级错误，也说明它不会自己消失。**

**T37 正式降为 T38 的子题。** T37 问"哪些证据条目从没人引用"，那只是"给多了"的一半；VXN 是"给少了"的另一半。做完 T38 的诊断，T37 的答案会自己掉出来；单做 T37 只解决一半，而且是不太危险的那一半。

## 五、三条留给后来者的教训（与第一节的三条并列）

1. **修边界的改动最容易在边界上开新口**（T39 详述）。改动目标是加固某条边界时，顺手加的兜底/降级分支必须过同一套审查。
2. **"1055 全绿"不等于"全部被保护"**。全绿可能依赖文件收集顺序（T43①）；测试可能把真实路径全部 mock 掉（T39 的覆盖盲区）；`.gitignore` 加了规则不等于文件没进去（T43②）。**机器闸门本身也需要被审计。**
3. **模型说"数据缺失"时，先查它的输入里到底有没有那个数**。VXN 那次模型说的是准确的实话，问题在供给侧。把模型的诚实报告当成模型的毛病，会一路修错方向。
