# T47 阶段一 · H1 冗余片：跨站重复供给台账

语料根：`output/analysis/vnext/20260731_002156/context_spread/`（run 20260731_002156，25 站目录、32 个 prompt 实例，`full/` 为原文）。
本报告只回答一个问题：**同一份材料在几站重复供给、各占多少字符、消费端指令实际要求用了多少。** 只报事实与线索，不做严重度定级，不开处方。

## 方法与口径

### 检测方法（机械、可复跑）

脚本：`/tmp/dup_scan2.py`（只读语料，不写任何项目文件）。算法：

1. 递归收集 `context_spread/full/` 下全部 32 个 `*.prompt.txt`（含 `controlled_investigation/<实例>/`、`integrated_adjudicator/<实例>/` 两层子目录）。
2. 每份原文按行切开，行仅做 `rstrip()` 归一化（不动前导缩进、不动行内字符）。
3. 种子：每个连续 8 行滚动窗口取 MD5；另对单行 ≥500 字符的长行单独取 MD5（防紧凑单行 JSON 漏网）。
4. 同一种子哈希的全部出现点，双向逐行扩展，扩展到任一出现点行内容分歧为止——得到的是**所有出现点逐字一致的最长公共块**。
5. 按最终块文本哈希去重；丢弃最终不同出现点 <2 的块（排除偶然自交）；台账阈值：块 ≥2,000 字符。

复跑命令：

```
python3 /tmp/dup_scan2.py          # 终端打印块清单，结果写 /tmp/dup_blocks2.json
```

产物：`/tmp/dup_blocks2.json`，每块含 `chars / n_lines / stages / occurrences(stage,file,start_line,end_line,char_start,char_end) / head / tail`。

### 口径说明

- "站" = stage 目录（如 `critic`）；"实例" = 单个 prompt 文件（L2 有 attempt_1/attempt_2 两份）。
- "跨站重复" = 同一块出现在 ≥2 个站；"同站跨实例"（如 L2 两次 attempt 几乎整份相同）与"站内自重复"（同一份 prompt 内出现多份）单列。
- 字符数一律按原文 `full/*.prompt.txt` 计，含 JSON 缩进空白。
- 块间有包含关系（如 critic↔risk 共享的 229k 大块内含治理四站共享的 197k 子块）。为避免重复计数，后文按**材料簇**（在同一文件内字符区间有重叠的块并成一族）组织台账，每簇给出各站合并后的真实字符区间。

### 盲区（先行声明，详见末节）

- 只看逐字一致：同一份 JSON 若换键序、换缩进、改一个数字，行级比对即断裂漏报。语义级重复（同数不同字）不在本方法视野内。
- 阈值 2,000 字符以下的小块重复（短指令模板、输出契约片段）未扫。
- 散文（非 JSON）重复会被方法捕获，但本片的识别精力集中在大块 JSON 供给上。
- 消费端核查靠人工读各站指令节，覆盖主要块；小块簇（event_card 系列）只抽查代表站。

    import json

    def field_span(path, field):

        i=txt.find('"%s": {'%field); j=txt.index('{',i)
        depth=0;k=j;in_str=False;esc=False
        while k<len(txt):

                elif c=='{': depth+=1
                elif c=='}':
                    depth-=1
                    if depth==0: break
            k+=1
        return k+1-i
