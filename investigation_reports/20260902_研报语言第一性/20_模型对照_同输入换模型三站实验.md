# 20 · 同输入换模型：三站冻结对照实验（GLM 5.3 Flash vs DeepSeek V4.1 Flash）

> **本文回答一个问题**：门面写成"没有任何人类能读懂的废物语言"，是模型不行，还是系统架构不行？
>
> **方法**：把 B 侧 run（`20260911_233648`，新语料）落档的**完整 prompt 逐字冻结**，只换模型重放。
> 不重跑全链——单站一次调用，比 25 站全链便宜一个数量级，且两侧输入**完全相同**，
> 差异只可能来自模型。这才是真正干净的"单站冻结 A/B"。
>
> **状态**：2026-09-12 执行。老板 2026-09-12 裁决："如果两个模型都不说人话，那说明是我们系统架构仍需大改。"

---

## 一、结论先行

**两者都不够好，但病因不同，且结构责任更大。**

1. **模型差异真实存在，方向一致地偏向 DeepSeek**：同一份输入下，DeepSeek 用**更多、更短的句子**加显式序号（"第一约束是…第二约束是…"）组织内容；GLM 用**更少、更长的句子**把一堆并列事实粘在一起，且反复出现"让 734.58 和 702.70 给答案"这类自造拟人句法。
2. **但门面这一栏，两个模型产出的分句数完全一样（9 句）**——这说明门面长度不是模型选的，是**字段要求逼出来的**。换模型能改善读感，治不了这个病。
3. **责任链定位在终审站，不在上游**：论点站（门面草稿的产地）两个模型写出来的都是 78 字、可读的句子；到了终审站，GLM 把它加料成 **135 字**、DeepSeek 加料成 **121 字**。上游写得好，是终审环节把它改坏的。
4. **结构病根：`one_liner` 三重过载**（详见第四节）。一个名为"一句话"的字段，被三处规则同时要求装下四要素与五个类别，且重复了后面三个专职字段的内容。

**对老板那句"难道是我的架构错了吗"的直接回答**：架构的严谨性没有错，错的是**把"严谨"错误地施加在了给读者看的那个字段上**。系统里已经有 `time_horizon_summary` / `action_summary` / `invalidation_items` 三个字段专职装价格、动作、失效条件，却又要求 `one_liner` 把它们再概括一遍——**摘要与正文打架，必然膨胀**。

## 二、实验设计（可复现）

### 2.1 为什么能省钱

`_run_stage` 把每一站的**完整 prompt** 落档在
`<run>/prompt_audit/<station>/attempt_N.prompt.txt`（含 `## System Message` 与 `## User Message` 两段）。

- `attempt_1` = 全量 payload（终审站 211153 字符 → **76806 tokens**，实测）
- `attempt_2` = 精简重试（只含"上次输出 + 校验错误"，26282 字符 → 13129 tokens）

只要取出 `attempt_1` 的 User 段、配上当前代码的 System 段，就能只花**一次调用**问到"换个模型这一站会说什么"。

### 2.2 执行件

`scripts/replay_station.py`（本次新建）：

```bash
PYTHONPATH=$PWD .venv/bin/python scripts/replay_station.py \
    --from-run output/analysis/vnext/20260911_233648 \
    --station final_adjudicator --attempt 1 \
    --model deepseek-flash \
    --out output/experiments/replay_20260912
```

脚本内置三道闸：
- **System 段逐字校验**：落档 System 与当前代码的 `_load_system_constraints()` 不一致时**拒绝执行**
  （否则就不是"只变模型"了）；本次三个站校验均为 `True`。
- **模型 key 注册校验**：不接受 `MODEL_CONFIGS` 里没有的名字。
- **`--strict-tools` 开关**：默认走 `json_object`（与 GLM 同协议，公平对照）；
  加该开关则走 DeepSeek 专属的 beta strict function calling（真实全链条件）。
  两者语义不同，不可混读。

### 2.3 冻结性证据

- 输入 prompt：`user_prompt_sha256` 落盘在每组产物的 `meta.json` 里。
- 采样参数：两侧同为 `temperature 0.2`、`max_tokens 65536`、`stream False`（`_call_ai` 固定）。
- 唯一变量：`model`。

### 2.4 边界（必须与结论一起读）

- **这是单站重放，不是全链重跑**：它复现的是"这一站收到同一份输入时的产出"。
  终审站没有下游 LLM 站，故重放结果不会传导；但若换成有下游的站（如 thesis），
  重放产物**不会**自动流向下游——那是需要另行设计的链路。
- **只测了 3 个站**（21 个 LLM 站中的 L1 / thesis / final_adjudicator），覆盖"最上游—门面草稿—门面终产"三点。
- **每个组合只采样 1 次**，未测同模型重复运行的稳定性。所以本文结论只支持"模型间的方向性差别"，
  不支持"某模型必然产出某形态"的强断言。
- `--strict-tools` 路径是**显式 opt-in**（`NDX_STRICT_TOOL_CALLING_STAGES` 环境变量 + `final` 在白名单内），
  默认关闭。即真实跑全链时 DeepSeek 也走 `json_object`——本文的公平对照版**就是真实条件**。

## 三、逐站结果

### 3.1 L1（最上游分析站）

| 字段 | GLM 5.3 Flash | DeepSeek V4.1 Flash |
|---|---|---|
| `local_conclusion` | 199 字 / 8 分句 / 均句长 **25 字** | 327 字 / 16 分句 / 均句长 **20 字** |
| `internal_conflict_analysis` | 540 字 / 29 分句 / 均句长 19 字 | 669 字 / 41 分句 / 均句长 **16 字** |
| `layer_synthesis` | 451 字 / 21 分句 / 均句长 21 字 | 554 字 / 30 分句 / 均句长 **18 字** |

**关键**：DeepSeek 写得更长，但**均句长更短**——它是用更多的短句把事情讲清楚，
而不是用一个长句把一堆并列事实粘住。GLM 的 `local_conclusion` 是**一整句 199 字、8 个分句、零序号**；
DeepSeek 同字段用"第一约束是…第二约束是…第三约束是…"组织。

> GLM（199 字一句）：
> "L1为"绝对偏紧、边际收紧"：实际利率2.42%处10年99分位且上行，通胀预期2.35%（78分位）走高，
> 期货定价未来12个月约+54bp净加息（supporting_only），净流动性4周减少492亿（十亿美元）且RRP缓冲已耗尽；
> 对冲项仅政策利率回落至一年低位3.63%（已暂停）与M2回到一年高位5.41%。压力源是贴现率而非增长
> （铜金比10年14分位），宏观端在边际抽走NDX估值燃料。"
>
> DeepSeek（327 字，分层）：
> "L1 是「绝对偏紧、边际分化」，不是宽松。第一约束是实际利率 2.42%（十年约 99% 分位、仍在 20 日均线上方）……
> 第二约束是政策预期……第三约束是边际流动性……缓冲项是曲线回到 +41bp、深倒挂解除……"

### 3.2 thesis（门面草稿的产地）

| | GLM 5.3 Flash | DeepSeek V4.1 Flash |
|---|---|---|
| `reader_conclusion.one_liner` | 78 字 | 78 字 |

**两个模型在这一站都写得能读。** 这是全实验最关键的一条对照：

> GLM：`这是一段没有安全垫的横盘：核心仓可以拿着但别加码，短线别猜方向、等734.58或702.70给答案，空仓的钱不着急进场——盈利上修和利率，谁先松动谁说了算。`
>
> DeepSeek：`现在不是便宜的位置：长期利率在十年极值、股票的补偿已经薄到几乎没有安全垫，涨不涨要看盈利上修能不能继续兑现——所以不追价、也不恐慌减仓，等利率方向、信用和盈利广度先给出确认。`

DeepSeek 的三条理由还呈现出稳定的「短结论 + 冒号 + 展开」结构，可直接当小标题用：

- `约束是真的但不新：……`
- `支撑是真的但有条件：……`
- `价格没有给出答案：……`

**所以门面草稿环节不是病灶。**

### 3.3 final_adjudicator（门面最终产地）

| 指标 | GLM 5.3 Flash | DeepSeek V4.1 Flash |
|---|---|---|
| 门面字数 | **135** | **121** |
| 门面分句数 | **9** | **9** |
| 三条理由字数 | 106 / 138 / 130（合计 374） | 93 / 107 / 90（合计 **290**） |
| `final_stance` | 136 字 | 161 字（上限 200，均合规） |
| `reasoned_verdict` | 2221 字，21 处方括号引用 | 2848 字，21 处引用 |
| `reader_final.three_reasons` 引用数 | 0 / 0 / 0 | 0 / 0 / 0 |
| 契约校验（`FinalAdjudication`） | ✅ 通过 | ✅ 通过 |
| 顶层字段数 | 27 | 27（无缺字段） |

**分句数完全相同（9）**——这是本文最重要的一个数字。两个不同厂商的模型，
在同一份输入、同一个字段上，产出了同样"烂"的句子结构。这不是巧合，是**字段要求决定的**。

**数字交代方式的差别（质的差别）**：

- GLM：`短线别猜方向，让734.58和702.70给答案`
- DeepSeek：`短线别猜方向——站上 734.58 或跌破 702.70 再动手`

同样两个裸数字，GLM 用了拟人化的"给答案"（读者不知道这两个数是什么、该干什么），
DeepSeek 给出了**方向词 + 动作**（站上/跌破、再动手）。后者是可执行的。

### 3.4 strict 协议版（opt-in 条件，附一条独立缺陷线索）

终审站在 strict 白名单内（`_STRICT_TOOL_CALLING_ELIGIBLE_STAGES` 含 `final`），
但该路径是**显式 opt-in**（`NDX_STRICT_TOOL_CALLING_STAGES` 环境变量），默认关闭。
为看清"若打开开关会怎样"，额外跑了一次 strict 版，结果暴露两条独立问题：

1. **首次直接 400**：手工传 pydantic 原生 schema 时，DeepSeek 报
   `Invalid tool parameters schema : unknown variant 'date-time', expected one of 'email','hostname','ipv4','ipv6','uuid'`
   ——strict 模式不认 `format: date-time`。改用系统自己的
   `sanitize_json_schema_for_strict_tool_calling`（`llm_engine.py:110`）清洗后，200 通过。
   **说明系统里那个清洗函数是必需的，不是装饰。**
2. **退回 content 后 JSON 非法**：调用虽成功，但引擎警告
   `strict tool call 未返回 tool_calls，退回 content`——DeepSeek 没走 function call，
   而是把 JSON 写在正文里。而正文里出现了**未转义的 ASCII 双引号**：

   ```
   但这不等于"利率水平没被定价"——恰恰相反
   ```

   这个半角 `"` 直接截断 JSON 字符串，`json.loads` 在第 6 行失败
   （对比：公平协议 json_object 版一次解析成功）。

**结论**：**strict 路径（opt-in）当前对 DeepSeek 不可用**；默认的 json_object 路径才是可用路径，
而本文 3.3 那一节用的就是它——即**公平对照版就是真实条件**。
（这条属独立缺陷线索，建议单独立项，不混进本轮"模型 vs 架构"的结论。）

## 四、结构病根：`one_liner` 三重过载

门面为什么必然是长句？因为三处规则同时压在这一个字段上。

**第一处 · 契约层**：字段名叫 `one_liner`，描述是"给普通读者的一句话结论"。
（`contracts.py:1753`）

**第二处 · 提示词层（要素要求）**：要求它"概括**状态、价格、赔率和动作**"四件事。
（`prompts/final_adjudicator.md:221`）

**第三处 · 提示词层（赔率规则）**：

```
【赔率语言：双向对称的举证负担】
`final_stance`、`reader_final.one_liner`、`payoff_assessment` 必须方向一致，且：
- 写"高赔率/赔率有利"：必须点名五类（价格反映、估值/ERP、信用、趋势、盈利/流动性）
  中哪些支持补偿变厚，并列出仍然反对的类别。
```

**这条规则同样作用于 `one_liner`**——也就是说，那一行文字被要求**点名五个证据类别 + 列出反对方**。

**再叠加第四重压力 · 风险保留纪律**：系统要求门面必须保留残余风险。
实测结果：两个模型都把这条限定塞进了门面末尾——
GLM 写"记住这套打法默认预警会赶在急跌前出现，这一点没有保证"（自毁逻辑句），
DeepSeek 写"整套打法都默认预警会赶在急跌前出现，这一点没有证据保证"（稍好，但同样难读）。
它其实是 `reasoned_verdict` 里那句严谨表述被硬压缩的产物：
"等待与持有共同押注『预警先于急跌出现』，该先后关系本轮无数据支持"。

**核心矛盾**：`reader_final` 里**已经有** `time_horizon_summary`（分时间尺度判断）、
`action_summary`（核心仓/战术仓/等待者动作）、`invalidation_items`（失效条件）三个字段
专职装载价格、动作与失效条件。而 `one_liner` 又被要求"概括状态、价格、赔率和动作"——
**这是在要求摘要重复正文**。摘要越完整，句子越长；句子越长，越不可读。

**渲染端也无法救**：`vnext_reporter.py:2572` 是
`<h1>{_escape(reader.get('one_liner') or ...)}</h1>`——整句直接当大标题，不做任何切分。
模型写多长，读者首屏就是多大的字块。

## 五、A 档语料改造的实测代价（补记）

同一次 run 的前后对照（均为 GLM，同一份输入数据）：

| | 门面字数 | 门面分句数 |
|---|---|---|
| 旧语料（`20260906_105915`） | 106 | 7 |
| 新语料（`20260911_233648`） | **135** | **9** |

**改词之后门面反而更长了。** 换掉黑话（`兑现桥`/`零垫子`/`这座桥近端宽远端窄`）的代价是模型改用更多白话去解释，
字数涨约三成，而**句法可读性毫无改善**——106 字与 135 字，对读者是同一种折磨。

这印证：**语料换词这条路的收益是"术语消失"，它压根没碰到句法病。** 两者是不同层面的问题。

## 六、给老板的裁决项

1. **要不要做门面字段瘦身**（治句法病的第一性动作）：
   `one_liner` 只留「状态 + 动作」并设短上限，价格/赔率/失效条件交给已有的三个专职字段；
   删掉赔率规则对 `one_liner` 的"点名五类"要求（该要求只保留给 `payoff_assessment`）。
   这是改**结构**，不是改文字——按宪法口径属"导出层"，不是症状补丁。
2. **要不要换模型**：DeepSeek V4.1 Flash 在同输入下可读性明显更好（更短句、有序号、数字带动作），
   但**不能治愈**门面病。换模型是改善，不是解决。
3. **`final_stance` 200 字上限是否仍合理**：GLM 第一跳因 300+ 字被拒、触发重试（两跳均 14461 输出 tokens）。
   本次 DeepSeek 一跳 161 字合规。该上限在门面瘦身时应一并复核。
4. **要不要扩测**：本文只覆盖 3 站、每组合 1 次采样。若要把"模型差异"做成可依赖的结论，
   建议补测（同站多次采样 + 覆盖更多站）。
5. **strict 路径要不要修**（独立线索，见 3.4）：DeepSeek 在该路径下既不走 `tool_calls`，
   退回的正文又含未转义引号导致 JSON 非法。默认关闭故当前无害，但若计划改用它，
   需先修 schema 清洗与转义两条。**建议与本轮"模型 vs 架构"结论分开立项。**
