# 范文深拆与人话差距定位（05，2026-09-04）

> 起因：老板评审 T70 交付——"远好于上次，但仍然是垃圾；外部指南的范文在人话程度上和现有 run 完全不是一个等级，我作为用户能看懂"。并指示研究 github.com/MrGeDiao/shuorenhua 作为灵感。
> 本文回答：范文为什么能看懂（逐机制拆到可施工）→ 我们的 run 差在哪一层 → 修改方案（减法优先）。
> 边界（老板已裁决，本文不再讨论）：不要 Cause→Pricing→Action 强制三段式；不要任何编造的概率数字；不要"禁用词黑名单/语义强制转换/违者打回"那一整段契约；范文的精确数字表演（41.9%、7.2 亿美元这类来源可疑的精度）不学。

## 一、范文为什么能看懂：七个可施工的机制

对照对象：外部指南范文（执行摘要/博弈情景/失效边界三节）vs 我们 run t70_glm_check_20260902 的判决正文与假说卡。

**M1 读者模型换位**。范文每句话假定读者是"投委会成员"——懂利率、估值、利差这些行业通语，但完全不知道我们系统内部的分析框架。我们的判决正文第一句就是"约束端（折现率、估值补偿、信用尾部）边际占优，吸收端（盈利上修）仍在运转"——"约束端/吸收端"是这一轮模型自造的分析框架词，通篇当主语用（判决正文里"约束端"2 次"吸收端"4 次），读者要先破译框架才能读判断。范文从头到尾没有自造框架词。

**M2 数字三件套分家**。范文写数字的固定节奏是两句一组：先现象句（"10年期实际利率录得 2.44%，处于 99.6% 的历史极端分位"），再含义句（"高陡的折现率对权益资产的风险补偿形成了严重挤压"）。我们把同样的内容塞进一句 87 字平均、最长 195 字的复合句里（判决正文 25 句实测）。**一句话一个意思；数字句和"所以呢"句分开**——这是范文可读性的最大单点来源。

**M3 标题是内容视角的判断句，不是工序视角的流水号**。范文："1. 估值与折现率：无风险利率处于历史极端，估值安全垫极度匮乏"。我们："01 · 正方主论证"、"02 · 反方"、"谁在竞争解释权"——读者不关心我们的工序。

**M4 情景有名字**。范文：基准情景/乐观情景/结构情景，各带一段叙事+核心证据 bullet+驳回理由。我们：假说甲/假说乙 + "它的主张/最强证据/主线怎么回应/什么会让它赢"四栏目——这是审讯记录格式，不是情景分析格式。四栏目的信息一个不少，但版式把读者放在了审讯员的位置。

**M5 动作写成纪律，不写成俚语**。范文："恪守右侧突破确认纪律，不盲目左侧抄底"。我们："谁先眨眼"（首屏标题）、"不接刀"。这一条分寸要注意：老板认可的既有样板（"拿着，等市场自己亮牌"）也是生活化语言——所以不是"俚语清零"，是**俚语要少而准，一句比喻顶一段解释时才好**；标题和动作句优先用纪律语言。

**M6 对照由表格承载**。执行摘要四列表（维度/状态/驱动与数据/纪律）、事件对质清单表、技术防线刻度图——密度全在表里，段落因此可以保持轻。我们已有全部结构化字段（price_reflection_map 五类、conflict_matrix、双向触发线），只是没排版成表。

**M7 元数据物理隔离**。范文面没有 run id、没有"未记录"占位、没有"可信度 中"这种内部仪表盘。我们门脸上挂着"运行 t70_glm_check_20260902"和"赔率 未记录"空徽章——全是代码渲染的，一个模型字都不经过。

## 二、shuorenhua 的启发（github.com/MrGeDiao/shuorenhua）

它的核心流程：**改写前先锁定事实（数字/归属/条件一律保留）→ 句式与段落结构优先，短语表只作兜底 → 双向回读验证 → 防误杀（57 条正常文本必须放行）**。

对我们的三点校准：

1. **人话的主杠杆是结构，不是词表**。它的 210+ 词条只是兜底——印证老板"减法"直觉：我在 P-A 织的翻译词表应该随上游变干净而收敛，不能膨胀。
2. **锁定事实 ↔ 我们的事实卡**：同构。它的"双向回读"（改写后每个结论在原文有出处）↔ 我们的数字忠实自检。这条路我们走对了。
3. **防误杀 ↔ 我们的分区纪律**：审计区不动、英文标题不碰、未知 token 原样保留——继续做。

## 三、差距定位：三层病灶按杠杆排序

| 层 | 病灶 | 机制出处 | 施工性质 |
|---|---|---|---|
| 段落层 | 假说卡是审讯格式不是情景格式；工序标题不是判断标题；摘要/对质/触发线没有表格化 | M3/M4/M6 | **纯代码排版**（字段不变，版式变） |
| 句子层 | 数字句与含义句不分家，平均句长 87 字 | M2 | 提示词文风契约补一句（终审+IA） |
| 词层 | 模型自造框架词（约束端/吸收端）当正文主语反复用 | M1 | 提示词一句：少造框架词，造了首次必须一句人话定义 |
| 门面层 | run id、空值徽章上脸 | M7 | 纯代码减法（不渲染） |

## 四、方案（减法优先，待老板圈定）

1. **假说卡改情景格式**（渲染层）：假说名用模型起的短名（counter 提示词加 `short_name` 结构字段，四字内人话，如"盈利暂态""派发顶部"）；"它的主张/最强证据/主线怎么回应/什么会让它赢"四栏目改为：情景名（判断句标题）+主张段落+核心证据 bullets+"主线的回应"一段+"什么会推翻它"一行。字段零改动，只是版式。
2. **区块标题去工序化**（渲染层）：从各区块已有的判断字段装配内容标题（主要矛盾区用 summary 首分句，取不到保留中性短题）；"谁在竞争解释权"→"市场在争什么"；"还没吵完的争议"→"没吵完的事"；"如果发生这些事，我就改判断"保留（这是我们自己的人话）。
3. **数字三件套分家**（提示词，终审+IA 各一句）："数字句和它的含义分开写——先一句话给数字与历史语境，再一句话给'所以呢'；一句话只装一个意思。"
4. **框架词纪律**（提示词一句）："少造分析框架词；非造不可的，第一次出现用一句人话定义，之后用人话引用，不把框架词当句子主语反复用。"
5. **门面清场**（渲染层）：run id 进审计区；空值徽章（"赔率 未记录"类）不渲染。
6. **摘要四列表+触发线刻度图**（渲染层）：用 price_reflection_map/双向触发线等现有结构字段排版。

每条红灯测试先行。1/2/5/6 是纯代码排版（报刊原则：文章专家写，代码只排版装配），3/4 是提示词一句话级别的补充。
