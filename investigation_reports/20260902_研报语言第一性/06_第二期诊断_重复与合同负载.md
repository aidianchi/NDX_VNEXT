## 一、结论（先答老板三问）

1. **05 定位得对不对？** 七条机制 M1-M7 逐条核验**全部属实**，方向没错。但它是症状学：量到了句子和词，没量到文档结构；两处低估（M1 私词总量、M7 泄漏面），一处看漏（假说卡"最强证据"栏只有芯片没有正文）。
2. **为什么改完还是狗屎？** 05 找到的是四个症状，漏了两个更深的病根：**重复**（同一事实全文复述 12-23 遍，文档没有"单一事实源"）和**合同负载**（一句话被合同要求同时扛 4-7 件事）。两个病根都在内容生成端——排版减法够不着，提示词补一句也够不着。
3. **模型有没有责任？** 基本没有。同一模型、同一 run：L1-L5 指标卡和事件叙事段写出全场最好的人话（"流动性尚未到危险水平，但安全垫没有了，边际燃料在减少"；"同一句话既说明 AI 开支正在转化为真实用电负荷，也提示电力与站点周期可能拖慢巨头资本开支向收入的转化"）；最上层的判决正文写成 9.7 次/千字黑话密度的天书。差异变量只有一个：**每个生成单元背的义务数量**。02 号文档"担子决定文风，模型无原罪"获得第二次实证——这次是同 run 内部对照，证据更硬。

## 四、05 漏掉的两个病根（本文主增量）

### 病根一：重复——文档没有"单一事实源"（SSOT）

**现象**：数字重复 12-23 次；事件链五连讲；假说卡"什么会让它赢"与改判条件区几乎逐条重复（同一组触发条件两种格式各写一遍）。

**成因三层**：①每个区独立生成、各自自带证据义务——层间隔离在分析层是资产，在阅读层变成了重复税；②每个下游 agent 为自证都要重新引用上游数字（自包含叙事惯性）；③装配层只做拼接、不做编制。

**软件工程视角**：这是 SSOT/DRY 在文档级的违例。代码里同一事实存两份会出 bug，报告里同一事实讲五遍会出"狗屎"。报刊业的答案早就有：一个事实出现两遍是编辑失职——编辑的活儿，就是装配层缺的那道"编制"工序。

**宪法边界（必须钉死）**：能合并的只是"**同一事实的复述**"；冲突、反证、未解决张力一个字不许抹。合并前先回答一个问题："这是重复，还是张力？"拿不准就不动。

### 病根二：合同负载——一个生成单元背几件事，语言就长成什么形状

三个铁证，全在本次 run 和现行合同里：

1. `reader_final.one_liner` 合同（final_adjudicator.md:221）要求**一句话**概括"状态、价格、赔率和动作"——四件事挤一句，输出必然是 160 字长句（门脸标题实测）。范文的做法是拆成三小行（策略观点｜风险收益比｜配置建议），每行一件事。不是模型不会拆，是合同没让它拆。
2. 判决正文合同（final_adjudicator.md:246-257）每条理由背五件事→450 字段落、平均 72 字的句子。
3. **同 run 反例**：卡片一卡一指标一问题、事件解读一卡一事五小节——义务单一，语言就是人话。

**软件工程视角**：god function 反模式。把判决装在一个大 string 字段里，等于让一个函数返回整篇论文。"机械字段不出答卷"的对称延伸就是解法：**需要判断的答案也按格子出**——把 verdict 拆成一组小字段（每条理由拆四格：主张一句／数字与含义／反面一句／边界一句），每格是一个小问题，模型每格只答一件事，代码装配排版。这不违反"闸门不判意思"——格子管的是"哪类内容住哪里"，不判内容对错。

## 五、外部指南批判性吸收

按老板裁决扔三样（不再论证）：三段式强制链（用新八股换旧八股，恰恰制造它自己诊断出的"机械填表感"——02 法典第 8 条早有此训"一指标化必八股化"）；编造概率；"语言语气与语义转换契约"整段（黑名单=语义闸门，违反"闸门不判意思"宪法，且猫鼠游戏永远追不上；强制转换对照=把上下文敏感的语义问题当字典问题）。

留下五样（全部核实过）：

1. **四大症状的外部印证**：术语侵蚀／语气混搭／数据裸露／机械填表，与本文实测完全对上——病灶是读者可见的，不是我们的幻觉。这是该指南最大的价值：一个不知内情的读者视角。
2. 元数据隔离进审计附录＝我们的 M7／分区纪律，方向一致。
3. "量化指标融进因果链"＝文风法典第 2 条，一致。
4. 表格承载密度＝法典第 8 条／M6，一致。
5. **范文是一份"风格迁移存在性证明"**：经逐数核对，范文的市场数字几乎全部来自本 run 的数据（2.44%、99.6 分位、-1.42、8.97、609亿、SKEW 149.2、702.7-703.4、718、682.22……无一杜撰），它真正编造的是三个情景概率（55/30/15）和情景名。这意味着：**我们的数字不用改一个，换一种讲法就能被人话读**——数据从来不是问题，讲述层才是。学手艺，不学编造，正如老板划界。

## 六、shuorenhua（实测仓库后）

05 的转述基本准确：核心流程确为"锁定事实→结构优先→词表兜底→双向回读→防误杀"；210+ 词条只是兜底而非主武器；120 条评测集（63 该改／57 防误杀）；L1 硬约束／L2 风格／L3 观察三层验收。三条增量启发：

1. **它是改写侧工具，我们是生成侧系统**。生成侧修一次，胜过改写侧修万次——这直接反驳指南"正则黑名单＋自动触发重写"的方案：把生成问题推给改写管道，每多一层多一次失真（P-D 保险丝同理）。事实锁定＋双向回读的思想我们已有同构物（事实卡＋数字忠实自检），这条路走对了。
2. **可搬一：结构反模式自查**。它的 25 类结构反模式（结构过满／动词名词化／无源权威断言／过度承接……）比词表杠杆高——对照本 run："结构过满"正中判决正文，"无源权威断言"正中伪概率。
3. **可搬二：保护样本机制**。它用 57 条"本来正常的文本"防止误杀；我们的对应物是**样板段落清单**——06-24 v1 选段、"拿着，等市场自己亮牌"、本次 run 的卡片散文。未来任何文风手术先跑一遍"样板不被碰坏"，防止修复把好的部分也洗掉（09-04 芯片位置回退已经演示过一次这类事故）。

## 七、第一性原理：人话的四个物理条件

一段文字能被一口气读完，背后是四个物理约束在起作用——不是文风偏好，是读者侧的硬件限制：

1. **工作记忆预算**：一句装一个意思，一段装 4±1 个组块。超了，读者就得倒回去重读——"不说人话"的第一现场。我们的判决区 44% 的句子超 80 字，等于每两句要求读者回读一次。
2. **词汇共享**：只有读者和作者共享的词才是通道。私词每多一个，读者付一次查表税；20 个私词等于让读者先背字典再读报告。私词预算：全文 ≤3 个，首次出现用一个日常句子定义，之后不当句子主语。
3. **事实单一锚定**：同一数字第二次出现不是强调，是怀疑信号。一数一个家，他处引用不说数。
4. **单元任务单一**：一段被要求同时陈述＋论证＋自辩＋留痕，句法必然纠缠——因为四件事的宾语不同，硬装进同一条主谓宾就只能套嵌。一段一个义务，留痕走审计区。

文风法典十条是这四条的应用层。生成系统的任务不是"求模型说人话"，是**让合同的形状服从这四条物理约束**——担子怎么分，语言就长成什么样。

## 九、可施工清单（减法优先，待老板圈定；本文未动代码）
