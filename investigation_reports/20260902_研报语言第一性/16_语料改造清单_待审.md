**由此得出四条判定规则**：

1. **范文正文 0 次、报告有** → 私词，要治（上表上半段）。
2. **两边都高频** → **行业通语，不许动**（安全垫、兑现、口径；利差、分位、久期同此列）。特别注意：**"安全垫"范文用得比报告还密（9.19 vs 2.12）**——问题从来不是这个词，是报告把它截断成"垫子""零垫子"。
3. **技术定义词** → 不动，且**要自带解释**（见第三节）。
4. **查它有没有真名**（2026-09-11 老板提问后补立，最锋利的一条）→ 见下。

### 零·一 补立的第四判据：别问"业内懂不懂"，问"它有没有真名"

**起因**：老板 2026-09-11 问——"近端、绝对水位这些都是金融学业内人士能看懂的，只是我看不懂吗？"这句话问到了要害，因为它决定的是**改词还是加注释**，方向完全相反。查完证据，结论推翻了我原先的推测。

**核查方法与结果**（可复现：查字段定义 → 查上游原文 → 查报告页面）：

| 词 | 它本来是谁的 | 业内真名是什么 | 判决 |
|---|---|---|---|
| **安全垫 / 兑现** | 真概念（margin of safety；价值投资核心） | 就是它自己 | **留**。老板 09-11 自己判定"不要紧"——直觉是对的 |
| **近端 / 远端** | **不是借来的行业话，是 FY1／FY2 的外号** | **FY1 / FY2**，中文说"当年 / 次年" | **换掉** |
| **绝对水位** | **代码里的审计字段注释**，不是任何人的行业话 | 无——它压根不是词，是零件 | **删**（修 bug，见第四节 C2 组） |

**"近端"那条为什么定性变了**：我原先推测它是从债券圈借来的行话（收益率曲线的短端/长端，front end / back end）。**实测推翻了**——查该 run 的原始产物，它的真身是：

```json
"breadth_30d": { "value": { "0y": 62.421368, "+1y": 40.492277 },
                 "unit": "percentage_points" }
```

`breadth_30d` 是**测量窗口**（过去 30 天），`0y` / `+1y` 是**财年口径**（当年 / 次年）。而 **L4 分析员自己在 `key_evidence` 里写出过标准叫法**：`"30日修正广度：近端FY1净+62.4pp、远端FY2净+40.5pp"`。

到报告页面上，FY1 / FY2 没了，"30 日"也没了，只剩"桥的近端宽、远端窄"。

**所以它不是"业内术语被搬进报告"，而是"业内术语被换成了自造外号"。** 外号是从"兑现桥"这个比喻里长出来的——桥有两端，数据就也得叫两端。**真名在同一句话里出现过，是被丢掉的，不是没人懂。**

**第四判据的用法（一句话）**：凡是你看不懂的词，**先去系统字段和上游原文里搜它有没有真名**。
- 有真名且在业内通用 → 用真名（近端 → FY1/FY2，或直接"当年盈利 / 次年盈利"）
- 有真名但纯技术定义 → 保留 + 自带括号解释（C1 组）
- **查不到真名 → 它不是词，是零件（代码注释、闸门警告、字段标识），不该出现在读者眼前**（C2 组）

**这条判据的底层理由**（也是本清单唯一不需要论证的一条）：**这份报告的读者只有老板一个人。业内懂不懂，不构成一个词留下来的理由。**"换成大白话信息有没有损失"才是唯一的尺子——零损失就是纯门槛，换掉。

**口径提醒**：报告是对整份 brief HTML 统计的（含审计区、证据区），范文把审计收进附录——两边不是完全同口径。同口径只取"门面 + 判决正文"的复算，列为本清单的验收动作之一。

## 三、B 组：五站共用的"叙事字段文风约定"（**这里有一个必须你裁决的分叉**）

### 现状：这条约定**已经存在**，而且已经写过一轮

`l1_analyst.md:93`、`l2_analyst.md:93`、`l3_analyst.md:89`、`l4_analyst.md:147`、`l5_analyst.md:96` 五个站各有一份约定。实测指纹：**L1/L2/L3/L5 四站逐字相同（264 字）**，**L4 多一句括号补充**（303 字，多了"`source_tier`、`usage` 这类发言权信息照常由结构字段承载"）。原文：

> ### 叙事字段文风约定
> 叙事字段（散文）说人话：`narrative`、`reasoning_process`、`layer_synthesis`、`internal_conflict_analysis` 的主要下游读者是跨层桥接（Bridge）与 Thesis Builder，以及本层指标卡片的报告读者。
> - 判断先行、每条一个意思；数字嵌在因果链里、服务一个比较或判断，不陈列。
> - 行业通语（利差、分位、久期）直接用，生僻术语首次出现给半句解释；**验证等级、字段名、编号这类内部簿记语言不进叙事字段**（它们住结构字段）。
> - 不知道就写不知道。结构字段（编号、枚举、ref、ID）保持机器形状不变，不受本条约定影响。

**它管住了什么**：字段名、编号、验证等级——这些确实没在报告里泛滥。
**它没管住什么**：比喻私词。因为在写这条约定的人眼里，"近端/远端/安全垫"不是"内部簿记语言"，它们是判读术语甚至行业通语。

**所以真正的问题不是"模型不听约定"，是"内部簿记"这条线画漏了一整类东西。**

### 分叉（请你选一条）

**路线甲（我建议）——只换源头，不扩约定。**
- A 组、C 组、D 组照改；B 组这条约定**不加"不许写什么"**。
- 依据：你否决过"提示词加措辞规矩/禁用词黑名单"；而"把私词列入内部簿记语言"实质上就是一张软性黑名单。
- 代价：模型可能继续从上游现场造词（承重墙/兑现桥就是这么来的），见效慢，需要靠换 few-shot 语域带动。

**路线乙——扩约定范围（只加"必须交代什么"，不加禁令）。**
- 在上面那条约定里加一句**产出要求**（不是禁止项）：
  > 凡是期限、范围、部位，必须写全称——"未来 30 天""未来 12 个月""前十大权重"；不写"近端""远端""最大权重一家"。能一句话直说的关系，不另造名词。
- 依据：`AGENTS.md` 写"提示词只约束'必须交代什么'"，"必须写全称"属于交代要求，不属于禁令。
- 代价：离你否决过的那条线只差半步，**需要你亲自判**。

**我的判断**：先走甲，把 A/C/D 三组改完 + 重跑一次全链看数据；如果私词密度只降不归零，再拿数据回来找你批乙。**不过这条属于方向性结论，按规矩要交给另一只 AI 独立再审之后再落地。**

### C2 · 读者面上暴露的内部零件（**必改，但它不属于"语料改造"**）

报告页面上实测有 3 处"绝对水位"，其中 **2 处是系统在读者眼前自我否定**，原文：

> "绝对水位随窗口起点平移，**不用于判读**。"
> "OBV 绝对水位不是语义出口，**不得引用水位数字**论证资金流入流出。"

**这两句是作者对写作者说的话，不是对读者说的话。** 读者看到会先愣一下：我为什么要引用它？

**溯源结论**：这两句是 L5 分析员把 `l5_analyst.md:34` 的作业说明**搬进了"证据发言权 / 不能越权证明什么"那个字段**，再被装配层原样印成读者可见的卡片。

**所以这一组的性质是**：
- **设计意图是对的**——让读者知道"这条证据不能证明什么"，正是 `AGENTS.md` 常驻边界"指标不得越权"的落地，**要保留**。
- **措辞是内部作业语言**——"不得引用其数值"改写成读者语言即可，例如："这个数只是对账用的中间量，不能拿来判断资金流入还是流出。"
- **字段名不该上页面**——"OBV 绝对水位"里的"绝对水位"是字段标识，读者面上应该直接说"OBV 的这个数"。

**改判**：C2 不是语料改造能解决的（语料本身是对的），它属于**装配层与表达层**，与 15 号 §2.4"内部簿记语言不上台面"同一族。**建议单列一件小工单，不混进本轮语料改造**——否则重跑一次全链也测不出它，因为它压根不经过模型。

## 四·补：一条通则（本次核查的副产品）

**"这个数在不同窗口下会变"这类说明，是给模型看的；读者只需要知道"该用哪个数、不该用哪个数"。**

凡是页面上出现"不用于判读""不得引用""仅供审计对账"这类句子，一律是内部零件泄漏——**因为读者本来就不会去判读它，是代码担心模型判读错误才写的。**
