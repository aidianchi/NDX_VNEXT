## 一、五个信息源的核心主张（各自是什么、怎么做的）

### 1. PI（earendil-works/pi，86.8k star，MIT）——"原语优于功能"

定位：极简终端 agent harness。它的设计宣言是一张"我们**不做**什么"的清单：不做 MCP、不做子代理、不做权限弹窗、不做计划模式、不做内置待办。

与我们相关的三个机制：

- **反 MCP 的理由是上下文税**：热门 MCP server 会把 13,700+ token 的工具描述**不管用不用都灌进每次会话**。PI 的替代：CLI 工具 + README，agent 用到才读——token 成本只在真正需要时支付。
- **Skills 按 Agent Skills 标准实现，机制就是"渐进披露"**：启动时只把每个技能的 name + description 放进系统提示（XML 清单）；任务匹配时才用 read 加载完整 SKILL.md；技能目录里的 references/scripts/assets 全部按需再读。三层披露：描述常驻 → 说明书按需 → 参考材料再按需。
- **AGENTS.md 逐级拼接**：全局 → 父目录 → 当前目录，全部命中拼接进上下文；可用 `AGENTS.override.md` 覆盖。

来源：github.com/earendil-works/pi（README、docs/skills.md、docs/index.md，2026-08-11 读取）。

### 2. OpenAI Codex——"沙箱隔离 + 任务进 PR 出"

- **物理隔离是默认态**：云端任务跑在独立容器里，**默认断网**；本地跑也有 Seatbelt/seccomp 沙箱。隔离不靠模型自觉，靠环境做不到。（GPT-5.3-Codex System Card §3.1）
- **AGENTS.md 是最高杠杆的单点投入**，但有明确预算帽：根到叶逐级读取、就近覆盖，**合计超过 32 KiB 就直接截断不读**（OpenAI AGENTS.md 指南，2026）。
- **上下文预算是明账**：标称 1M token 的模型，Codex 里封顶 400k、实测可用约 258k；每连接一个 MCP 工具**每轮**都付 schema 税。第三方实测结论："尺寸不是杠杆，窗口越满准确率越降（context rot），要靠修剪工具定义和精简 AGENTS.md 买回可用窗口"。（getunblocked.com Codex 上下文实测，2026-07-03）
- 交互模型：异步任务队列，每个任务独立沙箱，产出 PR 供人审。

### 3. Anthropic《Effective Context Engineering for AI Agents》(2025-09-29)

核心公式：**"找到能最大化目标结果概率的最小高信号 token 集"**。要点：

- 工具要 token 高效、职责不重叠——"如果一个工程师都说不清什么情况该用哪个工具，agent 更说不清"；
- 少放规则清单，多放**精心策划的典型示例**（examples are pictures worth a thousand words）；
- 长时程任务三件套：**compaction**（临近窗口上限时高保真压缩重开——最安全的轻量形式是"清掉古早工具调用的原始返回"）、**结构化笔记**（agent 自己写进度文件）、**多智能体**（仅当任务可并行分解）；
- "更大的上下文窗口"不是答案——任何尺寸的窗口都有 context pollution 问题。

### 4. Anthropic《How We Built Our Multi-Agent Research System》(2025-06)

这是"第二层如果 agentic 化"最对口的参照系——它就是干"开放信息采集"的：

- **架构**：orchestrator-worker。LeadResearcher 规划 → 并行派 3-5 个子代理分头搜索（各带独立上下文窗口）→ 子代理压缩成果返回 → lead 决定要不要追加 → 最后**单独的 CitationAgent** 把报告里的主张逐条对回原文位置。
- **硬数字**：多代理系统在内部研究评测上比单代理 Opus 4 高 90.2%；BrowseComp 上 **token 用量一项解释 80% 的表现方差**（工具调用次数和模型选择解释其余大部分）；代价是多代理系统**约 15 倍**于普通对话的 token 消耗。
- **关键教训**：① 编排者必须教会"怎么派活"——模糊的子任务描述会导致子代理重复劳动或漏覆盖；② 精力要跟问题复杂度分级（简单查询 1 个代理 3-10 次工具调用；复杂研究 10+ 代理），写进提示词防"杀鸡用牛刀"；③ 搜索策略"先宽后窄"；④ **来源质量启发式必须显式写**——人类测试者发现早期 agent 系统性偏爱 SEO 优化的内容农场而非权威但排名低的来源（学术 PDF、个人博客），靠提示词启发式才纠正；⑤ 评估：小样本立刻开始（约 20 条真实查询），LLM-as-judge 按 rubric 打分（事实准确、引用准确、覆盖完整、**来源质量**、工具效率），人评兜底。

### 5. Cognition《Don't Build Multi-Agents》(2025-06，Walden Yan) 与 2026 软化

反方立场，两条原则：

- **原则 1：共享上下文，且要共享完整的 agent 轨迹，不是只转述结论**——子代理只拿到任务碎片时，各自的理解偏差会在合并处爆炸；
- **原则 2：动作隐含决策，冲突的隐含决策产出坏结果**——两个子代理并行干活时，各自基于未声明的假设行动，成品互相不匹配。

2026 年的软化（Latent Space 播客，2026-05）：模型能力拐点后"有些多代理设置确实能跑了"，但社区一年的实践共识是——**瓶颈不在框架，在共享状态与决策所有权的纪律**；有效的模式是"角色清晰 + 否决权 + 入站事件当作硬任务边界，保证事后可审计"。

### 6. 金融场景的现成做法

- **virattt/ai-hedge-fund**：19 个专业代理组成"决策委员会"，LangGraph DAG 编排；数据层 → 研究层 → 策略层 → 风险层（VaR/回撤制动）→ 执行层，分层严格。
- **高频交易多代理论文**（techrxiv，2025）：news agent / spike detector / strategy agent **三条管线分离、资金隔离、统一执行**——新闻代理独立成管线在金融业已有实践，与三明治同构。
- **StackAI × Lone Pine 式的基本面研究代理**：最对口的两件是 **catalyst calendar agent**（维护财报/监管/解禁日历 + 每个催化事件挂情景假设 + 跟踪什么新证据改变情景概率）和 **post-mortem agent**（决策后复盘：论点变化时间线、预期 vs 实际、被忽视的信号）——前者正是我们第二层"官方日历 + 待确认钩子"的工业版，后者是我们的 T09 方向。
- **大成基金《AI 能力工程发展及投研实践》(2026-06)**：中文资管视角确认 Skills 范式（"用自然语言写的方法论/SOP，按需加载"）已从 coding 向投研渗透。

## 二、跨阵营收敛的六条共识（这才是调研的主要产出）

1. **上下文是稀缺预算，不是免费仓库。** Anthropic 的"最小高信号 token 集"、Codex 的 32KiB 帽和 MCP 税实测、PI 的反 MCP 立场，三家独立得出同一结论。→ **直接适用**：我们 T47 的 A10（巨型材料、72% 逐字重复块）就是这个病的我们的版本；T38"渐进披露"方向被一线实践独立验证。
2. **渐进披露是主流实现：描述常驻、详情按需。** PI 的三层技能披露、Anthropic 的 just-in-time retrieval、Codex 的 AGENTS.md 就近覆盖，结构惊人一致。→ **直接适用**于配餐单与 T38 设计。
3. **并行多代理只在"广度优先、可分解"的任务上赢；深度顺序任务用单线程。** Anthropic（研究系统赢 90%）与 Cognition（并行子代理脆弱）看似对立，实则画出了同一条边界：**任务形状决定架构**。→ **直接适用**于第二层形态判断（见下节）。
4. **隔离要物理保证，不靠标签自觉。** Codex 默认断网沙箱、PI 建议容器化、我们自己 T47 的 A7（立场声明与实物矛盾——模型拿不住标签）。→ **佐证三明治**：管线级隔离是 LLM 时代的正确实现。
5. **可审计性 = 完整轨迹留痕。** Cognition 的"share full traces"、PI 的 session 树、Anthropic 的 production tracing——出问题时能回放"它当时看到了什么"。→ **直接适用**：第二层若引入主动查询，必须全程留痕（查了什么、抓到哪个 URL、什么时候）。
6. **来源质量是显式工程问题，不会自动好。** Anthropic 的 SEO 农场教训、我们 T47 的 C9（事件数据质量百病）。→ **直接适用**：第二层的来源分级、标题党降级必须写成显式规则 + 检查，不能指望模型自觉。

## 三、对 T48 的映射：三种形态用调研证据过一遍

**判据（从共识 3 推出）：看子任务的形状。**

第二层其实包含两个形状完全不同的子任务：

| 子任务 | 形状 | 调研支持的实现 |
|---|---|---|
| **底账采集**（每期固定渠道：官方日历、财报、监管、主流报道——"有没有、是什么"） | 固定节奏、可复现、可审计优先 | **确定性流水线**（现状的骨架）。可复现性是它的信用基础；Anthropic/Cognition 都不会用开放 agent 干这个 |
| **补采与升级**（仅标题事件追全文、来源升级、"某渠道本周是否真空"） | 开放探索、路径不可预知、广度优先 | **agentic**（Anthropic 研究系统的正面对口场景：多步动态搜索碾压静态抓取） |

**形态评估：**

- **形态 A（现状纯流水线 + 小修）**：底账合格，但升级能力为零——仅标题率、正文截断这些病永远修不掉。调研结论：不够。
- **形态 B（全 agentic skill 化）**：灵活，但丢掉三样我们红线要的东西——可复现性（同样的 effective_date 跑两遍，抓取路径可能不同）、成本可控（15 倍 token 警告）、时效纪律（自由搜索必须锁死信息截止窗口，否则回测被未来信息污染）。Cognition 原则 2 也警告：自由 agent 的隐含决策无处审计。调研结论：全 agentic 单独不成立。
- **形态 C（确定性底账 + agentic 补采升级层）**：两个子任务各用对的工具。这正是我在重决策讨论中的初步倾向，**调研给了它独立的证据支撑**。

**若走形态 C，从调研提炼的工程约束清单**（施工时的验收维度）：

1. 补采 agent 的每次查询/抓取**全程留痕落盘**（查询词、URL、抓取时间、正文 hash）——共识 5；
2. **来源质量启发式显式化**（官方 > 主流 > 卖方 > 自媒体），防内容农场——共识 6 + Anthropic 教训；
3. **精力分级规则**写进提示词（例行升级 vs 深度核查的调用量上限），防过度搜索——Anthropic 教训 ②；
4. **effective_date 硬锁**：补采查询必须带时间窗口参数，agent 看不到"今天"——我们的独有红线，调研对象都不需要面对这个问题（它们不做历史回测），**这一条没有现成答案，要自己造**；
5. **CitationAgent 模式**：事件报告的每条主张由独立一步逐条对回原文位置——Anthropic 研究系统的现成解法，直接回应我们"每个数字可追来源"的北极星；
6. 评估从第一天就有：约 20 条真实事件的升级任务做测试集，LLM-judge + 你抽查。

## 四、对配餐单 / T38 的附带收获（探讨轨备用）

- 配餐单可以直接采用 PI 技能的三层披露结构：**每站"描述级"常驻（职责+禁令一句话）→ 按需取详情**——这正是"渐进披露"在 25 站供给上的形态；
- Codex 的 32KiB 帽思路值得借鉴：给每站供给设**显式预算上限**，超限即需要裁决（什么该删），而不是静默膨胀；
- Anthropic 的"规则清单不如典型示例"对提示词瘦身（T33 已实证）是又一次独立确认。

## 五、如实交代：没调研到 / 存疑的

1. **effective_date 下的 agentic 补采**没有现成参照——深度研究系统都面向"现在"，不面对"假装活在过去"。这是我们的独有约束，方案要自创。
2. IterResearch（Markovian 状态重构做长时程 agent，arXiv 2511.07327）只在参考文献里扫到，未深读——若形态 C 的补采 agent 出现长任务漂移再回头看。
3. 各来源的评测数字（90.2%、15×、80% 方差）均出自 Anthropic 官方博客，无第三方复现；作为方向性证据采信，不作为精确依据。
4. 金融场景的三项（ai-hedge-fund、HFT 论文、StackAI 案例）是架构参照，均未披露对我们这种"单指数、周频判断"场景的直接效果数据。
