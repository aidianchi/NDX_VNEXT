## 一、自焊小循环（prototype_loop.py）

- 输入一个 JSON 任务：`{agenda_id, question, max_rounds≤4}`；输出 `materials.jsonl`（每条一张候选材料卡）+ `run_summary.json` + 每轮 prompt 落盘（`prototype_audit/`，能 grep）。
- 循环：planner（LLM，用 llm_engine 的 `call_with_fallback`，只给工具清单与议程）→ 执行器（只允许白名单工具，工具返回全部进下一轮上下文）→ reader（LLM，把本轮工具材料收成 0-2 张材料卡，卡结构见下）→ 机器校验（四条镣铐）→ 校验失败带错误重试 ≤2 次 → 下一轮。
- 白名单工具（首版两个，都只读、写缓存到 run 目录）：
  1. `read_local_material(path)`：只读 run 目录或 `investigation_reports/` 下白名单文件；
  2. `fetch_official_url(url, max_chars=6000)`：只允许 https、只允许官方/主流域名白名单（SEC/FRB/FederalReserve/NASDAQ/CFTC/FINRA 等，写死在脚本里），抓正文存 `fetched_cache/` 带 UTC 时间戳；网络失败返回如实错误。
- 材料卡 schema（四条镣铐，机器校验逐字段）：
  `{card_id, agenda_id, fact_summary, interpretation, source_tier(枚举：official/primary_news/aggregator_news/weak_social/unverified), source_url, collected_at_utc, needs_data_confirmation[], limitations[]}`
  校验：fact_summary 与 interpretation 必须都非空且内容分离（fact 不得含"可能/预计/暗示"类措辞，interpretation 必须含假设标记）；source_tier 必须合法；collected_at_utc 必须 ISO 且不晚于"现在+5 分钟"；needs_data_confirmation 非空。
- 不得给循环任何写数据层/第一层产物/下结论的能力；材料卡带一行"本材料是第二层候选材料，判断以第一层数据为准"。

## 二、三性判定转常驻（three_tests.py）

- 读取 `investigation_reports/20260811_layer2_research/baseline/sources_audit.json`，对每个注册源按"靠谱/必要/能死板拿"三性判定，输出 `layer2_three_tests_report.json`：每源 `{source, reliable, necessary, dead_simple, verdict(pass/撤出/转agentic/弃用), reason}`；判不过的源写进 `sources_to_remove.json` 名单（只输出名单，不实际删源）。
- 判定规则先落在 `three_tests_policy.md`：三性定义、谁裁决、新源先过审、名单与 baseline 差异要人复核。规则与脚本必须一致（脚本从 policy 读取阈值常量）。
- 配套测试用合成 sources_audit fixture。
