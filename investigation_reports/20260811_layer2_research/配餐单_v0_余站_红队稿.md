## 一、攻击清单作答

### 1. 每站必答题里，哪些依赖"必须给"之外的材料？漏给会变成"看不见就编"还是"诚实的无法确认"？

**L1（l1_analyst.md）**
- 必答题依赖：`indicator_analyses` 必须覆盖每个 `analysis_required=true` 指标（l1_analyst.md:97）；`layer_synthesis` 必须自判 L1 状态（l1_analyst.md:55-60）；`cross_layer_hooks` 至少 2 条且按条件补 L5（l1_analyst.md:71-84）。
- "必须给"之外的实际依赖：layer_facts 的 `core_signals` 预摘要并非必须给，但 T47 实测它漏掉 `get_fed_funds_rate_path` 这个必答指标（`investigation_reports/20260806_t47_context_review/phase1/L1.md:109-111`），且预置了 `state=restrictive` 答案（L1.md:111-113）。漏给（raw 无、摘要也无）→ 该指标从 manifest 消失，模型"看不见"，但契约仍要求"每个 analysis_required=true 必须有一条"——结果要么漏答，要么按 layer_facts 里半个数字编一条；**两者都是"看不见就编"的高发区**。若 raw 有但标 NO_DATA/error，提示词有诚实出口（l1_analyst.md:100：仍要分析，但 `quality_self_check` 说明限制）→ 属"诚实的无法确认"。

**L2（l2_analyst.md）**
- 必答题依赖：13 个指标逐一分析（l2_analyst.md:97）；信用利差数值必须按输入 `unit`/`data_quality` 标单位（l2_analyst.md:101）。
- 额外依赖：core_signals 只覆盖 8/13（`phase1/L2.md:69-74`）；Indicator Semantics 缺 cftc/finra 两条语义（L2.md:118-123）。只要 raw 在，模型可诚实分析；若 cftc 类 NO_DATA 哨兵在，提示词有"不得围绕空数据补写"约束（orchestrator 系统级约束，T47 L2.md:154 核实）。但若某必答指标 raw 被过滤、只剩摘要，则同 L1 → **"看不见就编"**。

**L3（l3_analyst.md）**
- 必答题依赖：top10 集中度是"硬锚"，必须读 effective_date/Top10 权重/M7 权重/超额权重/表现差（l3_analyst.md:33）；广度四件套优先级（l3_analyst.md:27-28）。
- 额外依赖：T47 实测 `key_metrics` 只列 5/6、highlights 只列 3/6，被省掉的恰是 top10 硬锚（`phase1/L3.md:88-95`）；但 raw 里 6 个指标齐全（L3.md:184-190 核验通过）。结论：**当前不构成漏给，但预摘要诱导模型跳过 top10；一旦 top10 raw 缺失，L3 会从 NDX/NDXE 等其他指标"推导"集中度 → 编**。缺失时诚实出口是 `quality_self_check`（l3_analyst.md:28）。

**L4（l4_analyst.md）**
- 必答题依赖：11 个指标 + 数据源优先级与新鲜度（l4_analyst.md:39-48）+ Data Authority Discipline 全节（l4_analyst.md:50-82）+ 历史分位"有来源且当前可用才发言"（l4_analyst.md:57）。
- 额外依赖：T47 实测 `get_ndx_forward_pe_full_constituent`（analysis_required=true 且可用）没进 core_signals（`phase1/L4.md:101-107`）；`layer_facts.state=expensive` 预置本层结论（L4.md:94-99）。Wind 不可用时提示词要求按缺口处理、不得伪装（l4_analyst.md:56）→ 诚实。但 core_signals 把 Danjuan 分位挂到 HoM 指标头上且不标来源（L4.md:109-116），模型若只读摘要会**把第三方分位当成主锚写** → 编。结论：L4 是最容易"看起来有料、其实拿错料"的站，缺料时多数有诚实出口，但摘要层张冠李戴是"看不见就编"的实锤形态。

**L5（l5_analyst.md）**
- 必答题依赖：精确价格/均线/RSI/MACD/ATR/ADX/VWAP/MFI/CMF/Donchian 必须优先以 `get_l5_deterministic_snapshot` 为准，`NO_DATA_AVAILABLE` 时不得自行估算（l5_analyst.md:27,101）。
- 额外依赖：T47 实测 snapshot 的 OBV=670,737,927，分项 OBV=353,656,127，规则却要求以 snapshot 为准（`phase1/L5.md:30-43`）；core_signals 版均线缺 ma200（L5.md:91-94）；预置 `state=uptrend` 与材料内方向数值全面相反（L5.md:55-66）。结论：**同指标双值并存，模型必须"选一个"，选不出来就会编一个调和解释**；这是"看不见就编"的变体——不是没给，是给了两个打架的值。snapshot 缺失时诚实出口存在（l5_analyst.md:27），但只对 snapshot 自身，对"分项与 snapshot 冲突"无出口。

**bridge（cross_layer_bridge.md）**
- 必答题依赖：conflicts 非空且严重度诚实（cross_layer_bridge.md:157-158）、typed_conflicts/resonance_chains/transmission_paths 每条 evidence_refs 非空且 transmission path_id 唯一（cross_layer_bridge.md:219-223）、price_reflection_map 五类齐全（cross_layer_bridge.md:200）、principal_contradiction 非空（cross_layer_bridge.md:217）。
- 额外依赖：五张 LayerCard 全套 + 候选跨层关系。T47 实测 context_brief 在卡片之前预置三句跨层结论（`phase1/bridge.md:48-64`）、冲突矩阵 A-M 只给 A/B/C/K 四行（bridge.md:82-99）、候选关系实际三条均不含 L2（bridge.md:75-81）。漏给五卡中任一卡的 `indicator_analyses` → bridge 会从 context_brief 预置结论和 highlight 摘要"补"→ **编**。五卡齐全但严重不足时，提示词有诚实出口（principal_contradiction 可空但须写 unresolved_questions，cross_layer_bridge.md:217）。

**controlled_investigator（受控调查）**
- 必答题依赖：全部答案只能来自允许材料原文（controlled_investigator.md:3-6）；数字、分位、日期只能逐字引用（controlled_investigator.md:6）。
- 额外依赖：材料 = `_read_allowed_context_notes` 关键词筛选 + 每份 4,000 字符、总计 12,000 字符预算（orchestrator.py:2220-2291）。T47 实测材料在约 3,954 字符处**硬截断、JSON 不闭合、不告知**（`phase1/controlled_investigation.md:70-79`）；与问题直接相关材料仅 838 字符（controlled_investigation.md:105-109）。结论：提示词有"缺什么写清楚"的诚实出口（controlled_investigator.md:8），**但材料被截断且不声明，模型会以为材料完整，从半个 JSON 里猜 → 编**；只有材料显式为空或明显不足时才会走诚实路径。

**event_card_interpreter（×10 实例）**
- 必答题依赖：`fact_summary` 只许出现材料逐字有的东西（event_card_interpreter.md:4）；机制只能写成假设（event_card_interpreter.md:5）；无关事件诚实输出"关联不足"（event_card_interpreter.md:8）。
- 额外依赖：事件正文。T47 实测两卡 `raw_text_available=false`、`raw_text_excerpt=""`（`phase1/event_0a457426cdb8f17f.md:35-37`；`event_1d77a2d1bb9e1d35.md:28`），全部市场数字只在 `competing_hypotheses` 里（event_0a...:90-93）。结论：标题级材料下 `fact_summary` 有诚实出口（只写标题/来源/日期），但 `interpretation`/`mechanism_hypothesis` 无字段级限制，模型会用假说里的数字"解读"标题 → **编**。有全文时正常。

**event_section_summary**
- 必答题依赖：只使用输入卡内容（event_section_summary.md:6）；至少引用 2 张、至多 5 张（event_section_summary.md:7）；结尾边界句逐字（event_section_summary.md:12）。
- 额外依赖：卡内应有 `mechanism_hypothesis`（任务书说每张卡含机制假设），但 T47 实测 10 张卡字段里无此键（`phase1/event_section_summary.md:55-67`）。材料 7/10 仅标题、有全文且相关的只有 1 张（event_section_summary.md:145-154）。结论：**"至少引用两张"在只有一张可用时逼模型把无关卡写成有关 → 编**。不足两张时代码层有诚实留白（orchestrator.py:1655-1656），但提示词没有写这条回退，模型被调用时不知道。

**reviser**
- 必答题依赖：`hypothesis_responses` 逐字一一对应（reviser.md:17-22）；evidence_refs 逐字存在于 `key_evidence_refs`（reviser.md:26-31）；保留所有 high severity 冲突（reviser.md:225-229）。
- 额外依赖：索引必须覆盖 thesis 用过的全部 ref 与数字。T47 实测 thesis 自带 3 条反证 ref 不在索引（`phase1/reviser.md:54-63`）；thesis 散文多组数字（90d +10.7%、VWAP 702.73、VIX/FGI 等）在索引无条目（reviser.md:78-84）；假说回应没有假说原文与状态（reviser.md:161-169）。结论：索引缺口时提示词给了诚实出口"退回父引用或放弃论断"（reviser.md:29），**但 `reject` 必须给反证 ref 是硬合约（reviser.md:22）——索引里没有时模型会拼一个看起来合法的 ref → 编**。

**final_adjudicator**
- 必答题依赖：三条理由每条至少一个方括号 evidence_ref（final_adjudicator.md:245）；must_preserve_risks 每条点名（final_adjudicator.md:244）；不得引入输入之外数字（final_adjudicator.md:245）；stance_label 五枚举（final_adjudicator.md:39）。
- 额外依赖：key_evidence_refs 必须覆盖判决要引的数字。T47 实测索引 116,150 字符占输入八成、其中四分之三是成分级原始数据（`phase1/final_adjudicator.md:40-55`）；thesis 散文中 90d/VWAP/VIX/FGI/10Y 等数字在索引无条目（final.md:96-103）；3 条 counterevidence ref 不在索引（final.md:83-94）。结论：**"每条理由必须带 ref"是硬要求，而最强理由要用的数字恰好没有 ref → 模型会挂一个近义 ref 写 → 编/伪引用**。诚实出口是"不确定就写不确定"（final_adjudicator.md:247），但和"三条理由各带 ref"硬要求冲突时，模型大概率先满足格式。

**integrated_adjudicator**
- 必答题依赖：`stance_echo` 逐字复制 `final_stance`（integrated_adjudicator.md:11,20）；`question_answers` 每条按三态作答，answered 必须带 ref（integrated_adjudicator.md:27）；`conflict_matrix` 每卡一行、confirmed/challenged 必须有 data_side_refs（integrated_adjudicator.md:28）。
- 额外依赖：ref_authority 权限 + 每个许可 ref 对应的数值。T47 实测 34 个许可 ref 中 23 个 `unknown`、11 个全文无数值（`phase1/integrated_adjudicator.md:62-78`）；3 个假说 ID 无定义（IA.md:99-106）；调查报告引用不存在的 [M1]（IA.md:107-116）。结论：代码有硬闸门——answered 无证据降 cannot_answer_yet、unknown ref 剔除并留痕（`src/integrated_synthesis_report.py:449-464,508-510`），所以**结构化字段基本被机器逼向诚实；但 integrated_verdict 正文里的未知 ref 只留痕不拦截（integrated_synthesis_report.py:559-577）→ 正文里"看不见就编"仍然可能，只是会被 notes 记录**。

### 2. L1-L5 层间隔离与"该给的给够"的边界：`_filter_layer_raw_data_for_prompt` 会不会把本层必答指标过滤掉？给够与隔离冲突时，安全次序？

**会不会过滤掉本层必答指标？**
- 当前主路径：`_sanitize_prompt_payload`（orchestrator.py:6747-6778）对 L1-L5 先按层过滤 raw_data；`_compose_layer_prompt` 又过滤一次并据此生成 `### 当前层指标清单`（orchestrator.py:6899-6903）。
- `_filter_layer_raw_data_for_prompt`（orchestrator.py:7046-7062）逻辑：`function_id` 有 canon 注册且 `canon.layer.value == layer_value` 才保留；`get_indicator_canon` 抛 KeyError 时**保留**（7046-7058），即"未知指标不杀"；但**canon 注册了却标错层的本层指标会被静默丢弃**（7060-7061 只保留匹配层）。
- 实测现状：本机 `deep_research_canon.py` 注册表中，L1-L5 说明书点名的指标（含 L2 的 cftc/finra、L4 的 Wind 系列、L5 的 snapshot）均注册在正确层（deep_research_canon.py:89-940，各 `Layer.*` 赋值与 `src/agent_analysis/prompts/l1-l5_analyst.md` 指标清单逐一对得上），所以**当前配置下不会把已注册的本层必答指标过滤掉**。
- 但存在两个未上锁的暗坑：
  1. **canon 漏注册/错层注册**：`_filter_layer_raw_data_for_prompt` 的 KeyError 分支只对"完全没注册"的指标安全（保留数据）；对"注册了但层标错"的指标直接静默删除。`_layer_indicator_manifest`（orchestrator.py:7163-7184）迭代的是过滤后的 raw_data，所以该指标从"指标清单"一并消失——模型连"必须分析它"都不会知道。而 `layer_facts`（预摘要）不经过这个过滤器（payload 组装见 orchestrator.py:980-984，`facts_by_layer` 单独塞入），所以摘要层仍可能露出该指标的半个数字。**结果：模型看到摘要数字、看不到 raw，又不能从清单得知要分析它——"看不见就编"的标准温床。**
  2. **L4 长序列压缩可能误伤必答字段**：`_summarize_l4_raw_data_for_prompt`（orchestrator.py:7076-7096）把长度 >10 的 list 压成 `_summarize_long_series`（7098-7161）。若未来某个必答字段本身是长列表（例如窗口清单、分位窗口），会被压成 count+recent，L4 规则"完整窗口在 `PEPercentileWindows`"（l4_analyst.md:59）就失去执行前提。当前 Damodaran 月度序列等长列表是审计明细，压缩合理；但没有机器测试锁"被压缩的字段不得被提示词点名必读"。

**给够与隔离冲突时，安全次序（红队建议）**
1. **先隔离**：其他层 raw/结论/候选跨层关系/事件一律物理移除（`_build_layer_input_policy` 的 forbidden 清单，orchestrator.py:1000-1019，已存在且 T47 证实材料层隔离成立：`phase1/L5.md:126-129` 阴性事实）。
2. **再给够**：本层 `analysis_required=true` 的每个指标，raw payload 必须完整进入 prompt（可删的只有 `PROMPT_AUDIT_BOOKKEEPING_FIELDS` 那 7 个审计键，orchestrator.py:257-265）。
3. **最后省钱**：只压缩审计级长明细（`_summarize_l4_raw_data_for_prompt`/`_slim_long_list_for_prompt`），且压缩不得触碰任何被说明书点名的字段。
4. 配套机器锁：`manifest 中 analysis_required 集合 ⊆ prompt 内 layer_raw_data 键集合 ⊆ 本层 canon 键集合`，三者必须逐层相等；不等即回退重装，不许带病跑下一层。

### 3. bridge 拿"事件 ID 仅背景"这条，在提示词与代码里是否一致？会不会把事件当证据？

**提示词与代码在"仅背景"口径上一致，但与 4.7 的"恒空"政策不一致；且没有机器闸门能阻止事件当证据。**

- 提示词：cross_layer_bridge.md:323-335——event_refs 只能是事件 ID 字符串列表，只能解释触发/背景/观察，不能替代 evidence_refs 证明数值结论，无关写 `[]`。
- 代码注入：`_run_bridge` 在 `packet.event_refs` 非空时把它塞进 bridge_payload（orchestrator.py:4304-4305）；`_compose_bridge_prompt` 在检测到 event 输入时追加同样口径的强约束（orchestrator.py:6973-7007），并防"把 dict 形态复制进输出"（7002-7006）。
- **不一致点**：`系统说明书.md` 4.7 明文"事件永不进第一层（含治理链）。桥接与治理各站的事件字段恒为空是正确隔离"（系统说明书.md:378）。代码没有把 bridge 的事件字段**强制置空**，而是"有就喂、靠提示词约束"。T47 实测该 run 事件系统有产出但 bridge 输入零事件（`phase1/bridge.md:100-115`），所以这条路径没被真实数据检验过。
- **会不会把事件当证据**：`_validate_bridge_memo_v2` 只查 evidence_refs 非空、mechanism/implication/falsifiers 齐全、path_id 唯一（orchestrator.py:6190-6225），**没有** "evidence_refs ∩ event_refs = ∅" 或 "evidence_refs 不得含 event: 前缀" 的机器检查；`_coerce_event_refs_list`（orchestrator.py:8401-8403）只防把 dict 塞进 event_refs，不防把事件 ID 塞进 evidence_refs。事件 ID 与数据 ref 同为字符串，schema 锁不住。
- 结论：提示词和代码彼此一致地说了"仅背景"，但这条规则**住在提示词里**，违反 4.1"轨道 > 导出 > 规矩"（系统说明书.md:283-293）的次序；未来执行者要么按 4.7 把 bridge 事件输入锁死为空并加机器检查，要么若允许背景引用，就必须加一条"evidence_refs 中不得出现 event: 前缀"的校验器。

### 4. 受控调查员的材料边界：它拿不到什么、会不会因此猜？失败静默缺席（T47 A6）配餐单要不要写进回退条件？

**拿不到什么（按代码）**
- 只能读 `AgentSpec.allowed_context_refs` 白名单里的 artifact，且受 `budget.max_source_refs` 限制（orchestrator.py:2003-2010；默认预算见 1072：max_source_refs=3）。
- 每份材料经关键词筛选后**最多 4,000 字符**、总预算 12,000 字符（orchestrator.py:2279-2286）；T47 实测全部材料在约 3,954 字符处硬截断、JSON 不闭合、提示词不告知（`phase1/controlled_investigation.md:70-79`）。
- 没有任何外部工具（报告 limits 固定追加 `zero_external_tools`，orchestrator.py:2113-2114）；L1-L5 原始数据不在白名单时完全不可见。
- 立场隔离靠提示词（controlled_investigator.md:5"你不知道系统当前判断"），但 T47 实测 ae/c4 材料 = bridge_0.json 切片，内含 dominant_side 与"不宜重仓/触发核心仓进一步减仓"仓位指令（`phase1/controlled_investigation.md:64`，根因见 `03_根本审查总报告.md:90` A7②）。

**会不会猜**

### 5. event_card_interpreter 十张卡共用同一条配餐单是否成立？每卡输入差异对配餐单有什么影响？"不足两张就留白"要不要写进回退条件？

**成立一半：模板可共用，但必须把"每卡输入差异"写成配餐单的变量，而不是常量。**
- 十卡共用同一模板与同一批 `allowed_financial_links`/`competing_hypotheses`（orchestrator.py:1512-1542）；每卡差异只在 `event_material`：title/source/tier/published_at/event_date/event_type/entities/raw_text_available/raw_text_excerpt/trigger_reasons（orchestrator.py:1527-1540）。
- 差异对配餐单的影响（T47 两张卡实测）：
  - **标题 vs 全文**：两卡都是 `raw_text_available=false`、正文空（`phase1/event_0a...:35-37`；`event_1d...:28`）。标题卡的事实面只有标题+来源+日期；全文卡才能有真 fact_summary。配餐单必须按 `raw_text_available` 分档：无正文卡 `fact_summary` 只许写标题/来源/日期逐字内容，`interpretation` 必须带"仅标题，降级阅读"并禁止引用假说数字当事实。
  - **来源等级**：`tier=reliable_mainstream_report` 无词表定义、无"是否弱来源"映射（event_0a...:127-139）。配餐单必须自带 tier 词表与降级档位，否则模型只能猜。
  - **标签诱导**：`event_type=mega_cap_market_news`、来源栏含 "M7"、`trigger_reasons=["mainline","inquiry_reference"]` 三处标签与标题文本（K2 Space 卫星公司融资）无涉指，把模型往"相关"方向拉（`phase1/event_1d...:76-83`），与"关联不足就诚实退出"（event_card_interpreter.md:8）对顶。配餐单必须写明：event_type/trigger_reasons 是采集标签不是事实，解读以标题+正文为准。
  - **数字全部来自假说块**：全提示词 12 组市场数值只出现在 `competing_hypotheses`（event_0a...:90-93）。配餐单必须写：`fact_summary` 不得引用假说块数字；`interpretation` 引用假说数字必须写"来自竞争假说，非本事件事实"。
- **"不足两张就留白"必须写进配餐单回退条件。** 代码已经做：`len(cards) < 2 → return None, "insufficient_cards"/"no_cards"`，不调 LLM（orchestrator.py:1655-1656），系统说明书 2.10 也写了（系统说明书.md:238）。但 `event_section_summary.md` 提示词全文没有这条（event_section_summary.md:1-16），模型一旦被调用只会看到"至少引用两张"（event_section_summary.md:7）。配餐单应写：`有效卡 < 2 → 跳过 LLM，产物字段 = insufficient_cards/no_cards；模型提示词同步声明"你只会在有效卡 ≥ 2 时被调用"`。机器检查：`card_count < 2` 时无 LLM 调用记录且 summary 字段为 null/留白。

### 6. reviser/final 在 critic/risk 分料后仍拿全量 governance_input（含 critique/risk/schema）是否合理？他们各自的必答题会不会因为拿多了而越权？

**结论：拿 critique/risk/schema 本身合理（这是他们的必答题原料）；不合理的是夹带"写给 Thesis 的指令"和"自带禁用标记的台账"，以及 key_evidence_refs 以原始成分级数据形态过量供给，诱导越权。**

- 装配代码：reviser/final 走 `_build_governance_input_packet` 默认 consumer 分支（orchestrator.py:627-635、681-689 → 5092-5134），拿到全量 thesis_*、critique_overall/cross_layer_issues、must_preserve_risks/opportunity_costs/confirmation_costs/false_safety_risks、schema_*、key_evidence_refs、synthesis_guidance、pricing_expectation_ledger、evidence_registry_summary 等 40+ 键。
- reviser 必答题"吸收 Critic/Risk/Schema 反馈修订"（reviser.md:7,113-157），所以三件套必须给。**不越权，但有两处夹带会干扰**：① `synthesis_guidance` 是写给 Thesis 的，且引用 reviser 材料里不存在的键（competing_hypotheses/evidence_index/bridge_summaries 等），措辞主语是"Thesis"（`phase1/reviser.md:148-159`）；② `pricing_expectation_ledger` 自标 `forbidden_as_core_ref`/`audit_only_effective_date_mismatch` 仍进输入且无消费指令（reviser.md:128-132）。这些不是权力，是噪音指令，会让模型误以为还有别的材料或别的任务。
- final 必答题"quality_gate 检查 Schema Guard、证据链、must-preserve risks、高严重度冲突；reader_final 写人话结论"（final_adjudicator.md:3-8,272-298），所以全量治理材料原则上合理。**越权风险点**：key_evidence_refs 116,150 字符、其中 75% 是 slope_30d/breadth_30d/m7_aggregate 的逐成分/逐季度原始表（`phase1/final_adjudicator.md:40-55`），而 final 的规则只要求"引用 ref 名与权限"（final_adjudicator.md:27-31,245）——给了 final 重新分析原始成分数据的能力，却只有一句"不能重新调用数据源"（final_adjudicator.md:305）管住工具调用，管不住它"就地重算已给明细"。T47 未见 final 真的重算（未证实），但供给形态邀请它这么做。
- 配餐单建议：reviser/final 继续拿治理三件套 + 修订稿 + key_evidence_refs（用于合法性核对），但**不给** `synthesis_guidance`（Thesis 版）、`pricing_expectation_ledger`、`evidence_registry_summary`；key_evidence_refs 对这两站只给"ref key + 权限 + 聚合读数"，不给逐成分明细（明细留给审计 artifact）。机器检查：reviser/final 的 governance_input 与 critic 包不得逐字节相同（现有 A1 已能查 critic==risk，扩到全治理站互异），且两站包内不得出现 `synthesis_guidance` 中以 "Thesis 只能…" 开头的条目。

## 二、11 类站点红队版条目

> 格式：职责一句话 | 必须给 | 不给 | 禁止碰 | 最小充分证据形态 | 回退条件。

### L1（宏观流动性）
- **职责一句话**：只回答宏观/流动性在给 NDX 估值加油还是抽油，不下买卖结论（l1_analyst.md:9）。
- **必须给**：本层 9 个指标完整 raw（function_id/value/data_quality，`analysis_required=true` 一个不能少）+ 静态五层本体 + 本层 IndicatorCanon + 本层 layer_facts（预摘要只作辅助，不得预置 state 结论）。
- **不给**：其他四层 raw/结论/状态；`candidate_cross_layer_links`；事件材料；bridge/thesis/critic/risk/reviser/final 任何产物（orchestrator.py:1000-1019）。
- **禁止碰**：把 `layer_facts.state` 当答案照抄；从期货路径反推其他层；预测政策路径；输出买卖建议（l1_analyst.md:98）。
- **最小充分证据形态**：每个指标一条 `indicator_analyses`，含 metric/current_reading/normalized_state/narrative/reasoning_process/evidence_refs；`core_facts` 至少含 metric+value（l1_analyst.md:96-97）。
- **回退条件**：`analysis_required` 集合与产物 function_id 集合不相等 → 把缺失指标 raw 加回重跑；仍失败 → 层卡带 `quality_self_check.coverage_complete=false` 并注明缺口，不崩整链（现行是崩溃退出，系统说明书.md:102——红队建议保留崩溃，但把缺口写盘）。

### L2（风险偏好/信用）
- **职责一句话**：只回答市场愿不愿冒险、这种冒险健康还是自满，不判估值也不判趋势（l2_analyst.md:7）。
- **必须给**：本层 13 个指标完整 raw（含 cftc/finra 及其 NO_DATA 哨兵）+ 本层 canon + 静态本体；cftc/finra 的语义说明补齐（T47 实测 Indicator Semantics 缺这两条，`phase1/L2.md:118-123`）。
- **不给**：同 L1 隔离清单；他层波动率/趋势/估值数据；事件。
- **禁止碰**：把低波动当低风险；把风险偏好强当市场健康；把百分比数值直接标 bp（l2_analyst.md:98-101）。
- **最小充分证据形态**：13 条 `indicator_analyses`，每条注明顺周期/反向/条件信号；信用利差数值带单位换算。
- **回退条件**：任一必答指标 raw 缺失且摘要层也没有 → 该指标标记 unavailable 并进入 `quality_self_check.missing_or_weak_indicators`，不得从其他指标"推导"读数；bp 单位违规重跑。

### L3（指数内部结构）
- **职责一句话**：只回答上涨是大部队还是少数权重硬撑，不回答盈利支撑（交给 L4）（l3_analyst.md:7,44）。
- **必须给**：6 个指标完整 raw（尤其 top10 的 effective_date/Top10 权重/M7 权重/超额权重/表现差）+ canon + 静态本体；摘要层不得省略 top10 硬锚（T47 实锤省略，`phase1/L3.md:88-95`）。
- **不给**：其他层数据/结论；L4 的盈利叙事；事件。
- **禁止碰**：把 Top10/M7 权重事实推断为盈利强；用价格强推断结构健康（l3_analyst.md:94-95）。
- **最小充分证据形态**：6 条 `indicator_analyses` + core_facts；top10 条目必须逐字段引用上述 5 项。
- **回退条件**：top10 缺失或不完整 → 本层状态只能标 `neutral` 并注明"集中度硬锚缺失"，不得输出 `healthy/extreme_concentration` 强结论；`New Highs/Lows` 或 McClellan 不可用 → 必须写进 `quality_self_check` 与 `internal_conflict_analysis`（l3_analyst.md:28）。

### L4（估值）
- **职责一句话**：只回答当前价格相对盈利/现金流/无风险替代是否有吸引力，不因趋势或情绪合理化估值（l4_analyst.md:7,153）。
- **必须给**：11 个指标完整 raw + 数据源优先级与新鲜度上下文 + Data Authority Discipline 全节可执行（每个字段的 source_tier/data_date/formula/coverage/MetricAuthority 必须在 raw 中可查，l4_analyst.md:50-82）；摘要层分位必须标来源与窗口，不得张冠李戴（T47 蛋卷分位挂 HoM 实锤，`phase1/L4.md:109-116`）。
- **不给**：其他层数据/结论；历史序列审计明细（留在 artifact，prompt 只留聚合与最近 5 条）；事件。
- **禁止碰**：Wind 不可用时用 yfinance/手工旧值伪装 Wind；历史分位无来源硬发言；technical/proxy 证明估值贵贱；mixed 父 ref 撑强结论（l4_analyst.md:56-57,70-74）。
- **最小充分证据形态**：每条估值指标 = 当前读数 + 相对基准（历史/债券/增长）+ 权限标注 + `#FieldName` 子引用（mixed 时）。
- **回退条件**：Wind 快照不可用 → 按 fallback/diagnostic 路径并显式降级（l4_analyst.md:75）；历史分位无合格来源 → 只写当前值与覆盖率，禁止 regime 强判断（l4_analyst.md:57,89）；`supplier_lookback` 占权重 100% 且 pending_validation → 盈利修正只能定性、不得作为核心估值支撑（`phase1/L4.md:155-160`）。

### L5（价格趋势）
- **职责一句话**：只回答趋势是否有效、是否过热、触发点在哪，不判估值也不给买入建议（l5_analyst.md:7,102）。
- **必须给**：11 个指标完整 raw + snapshot 优先规则可执行（snapshot 内精确数值 + 各分项指标 + 冲突说明）；`get_l5_deterministic_snapshot` 为 NO_DATA 时必须显式出现哨兵。
- **不给**：其他层数据/结论；事件；从记忆/图像印象补数（l5_analyst.md:101）。
- **禁止碰**：snapshot 缺失时自行估算价格/RSI/MACD/ATR；趋势强合理化估值；"趋势有效"与"短期过热"互相抵消（l5_analyst.md:103）。
- **最小充分证据形态**：每个技术指标 = 数值（标 snapshot 或分项来源）+ 趋势/动量/波动含义 + 失效触发点。
- **回退条件**：snapshot 与分项同指标双值冲突（如 OBV）→ 产物必须显式声明采用 snapshot 值并在 `quality_self_check` 记录冲突，禁止自行调和出第三个数；snapshot NO_DATA 却出现精确数值 → 打回。

### bridge（含反馈调查支线）
- **职责一句话**：测绘五层之间的共振与冲突并抓主要矛盾，姿态中立，不抹平也不升格（cross_layer_bridge.md:13）。
- **必须给**：五张完整 LayerCard（indicator_analyses/layer_synthesis/internal_conflict_analysis/cross_layer_hooks 全套）+ 候选跨层关系（覆盖实际层对，不得只给 3 条且缺 L2，T47 `phase1/bridge.md:75-81`）+ 冲突矩阵 A-M 完整定义（T47 只给 4 行，`phase1/bridge.md:82-99`）。
- **不给**：context_brief 里预置的"成品跨层结论"（apparent_cross_layer_signals/special_attention 预判句，`phase1/bridge.md:48-64`）；事件材料（按 4.7 恒空；若给，只给 ID 列表且见回退条件）；thesis/critic/risk 下游产物。
- **禁止碰**：把事件写成 evidence_ref；照抄历史 run 矛盾代号；把弱张力升格 high；空 conflicts（cross_layer_bridge.md:158,205-210）。
- **最小充分证据形态**：typed_conflicts/resonance_chains/transmission_paths 每条带非空 evidence_refs（父级或 #Field 子引用）+ mechanism + implication + falsifiers；price_reflection_map 五类齐全。
- **回退条件**：任一 LayerCard 缺 `indicator_analyses` → 先补卡再跑 bridge，不得用 context_brief 摘要替代；`evidence_refs` 出现 `event:` 前缀 → 打回；conflicts 空 → 打回（提示词允许 low 但不允许空）。

### controlled_investigator（受控调查）
- **职责一句话**：依据一小包允许材料诚实回答能确认/挑战/无法确认什么，不知道系统立场，不猜不补（controlled_investigator.md:1-8）。
- **必须给**：与问题直接相关的材料切片（不得"对着问题查问题"，T47 A7① `03_根本审查总报告.md:90`）；材料 JSON 完整闭合，截断必须显式标注 `[M#] ... 已截断`；每份材料带编号与来源 artifact。
- **不给**：系统当前判断/仓位指令/dominant_side（T47 材料含"不宜重仓/触发核心仓进一步减仓"实锤，`phase1/controlled_investigation.md:64`）；与问题无关的其他调查问题（T47 他案问题随包分发，controlled_investigation.md:96-104）；任何外部工具。
- **禁止碰**：数字、分位、日期不逐字引用；把"材料没写"写成"确认/挑战"；引用 [M#] 之外的材料。
- **最小充分证据形态**：`finding` + `claims_supported`/`claims_challenged`（每条带 [M#]）+ `cannot_establish`（写清缺什么）+ `confidence` + `limits`。
- **回退条件**：LLM 失败或材料不可用 → 确定性 stub 且 **stub 必须作为占位进入 IA**（`is_deterministic_stub=true`/`llm_failure` 可见），机器对账"委托数 == IA 报告数（含占位）"；材料 JSON 不闭合 → 装包器不得发送，先修包。

### event_card_interpreter（模板一条，×10 实例）
- **职责一句话**：把一条事件材料变成事实/解读分离的结构化卡片，机制只作假设，永不证明涨跌（event_card_interpreter.md:1-6）。
- **必须给**：事件材料四件套（标题/来源/时间/正文摘录，正文空必须明示 `raw_text_available=false`）+ 九渠道清单 + 竞争假说（只作背景）+ tier 词表与弱来源分档（T47 无词表，`phase1/event_0a...:127-139`）。
- **不给**：把 competing_hypotheses 里的数字当作事件材料的一部分喂给 fact_summary（T47 数字全部只在这里，event_0a...:90-93）；L1-L5 数据；其他卡内容。
- **禁止碰**：fact_summary 出现材料没有的字句或数字；把"可能通过渠道影响"写成已发生因果；标题卡写成全文口气；硬找关联（event_card_interpreter.md:4-8）。
- **最小充分证据形态**：fact_summary（逐字材料事实）+ interpretation + mechanism_hypothesis（financial_link+假设句）+ supports/refutes + needs_data_confirmation + limitations + passport（照抄来源/时间）。
- **回退条件**：标题卡（`raw_text_available=false`）fact_summary 长度超过"标题+来源+日期"可逐字支撑范围、或出现材料外数字 → 该卡重生成/降级；`event_type`/`trigger_reasons` 与标题无涉指时，允许并优先走"关联不足"退出（event_card_interpreter.md:8）。

### event_section_summary
- **职责一句话**：把本批事件卡收束成 100-1500 字"外部世界对照"，只盯问题、不下因果，以边界句结尾（event_section_summary.md:1-13）。
- **必须给**：≥2 张有效卡（含 citation/fact_summary/interpretation/tier/raw_text_available/published_at/event_date/limitations/needs_data_confirmation）+ `effective_date` + `title_only_card_count`。
- **不给**：原始新闻；L1-L5 任何指标/读数/结论（event_section_summary.md:6）；卡外事实。
- **禁止碰**：引 2-5 张之外的卡；写成"因为 X 所以指数 Y"；把弱来源写成确凿事实；写晚于 effective_date 的事后信息（event_section_summary.md:8-10）。
- **最小充分证据形态**：`summary_text`（含 [card:...] 引用 + 结尾边界句逐字）；`cited_event_ids` 由代码从正文提取。
- **回退条件**：**有效卡 < 2 → 跳过 LLM、留白并记录 `insufficient_cards`/`no_cards`（代码已做，orchestrator.py:1655-1656；必须写进提示词）**；`title_only_card_count > 总数一半` → 正文必须明示"本轮以标题为主、正文有限"（event_section_summary.md:11）；引用越界/边界句缺失 → 打回。

### reviser
- **职责一句话**：做编辑不做重写者，吸收批评/风险/结构意见修订论点，不抹平冲突（reviser.md:10）。
- **必须给**：thesis 原稿全套 + critique（overall+cross_layer）+ must_preserve_risks/双向风险 + schema 三清单 + key_evidence_refs（ref key+权限+聚合读数）+ `thesis_hypothesis_responses`（含假说原文与状态，T47 缺原文缺状态，`phase1/reviser.md:161-169`）。
- **不给**：`synthesis_guidance`（Thesis 版指令，T47 串味实锤 `phase1/reviser.md:148-159`）；`pricing_expectation_ledger`（自标 forbidden_as_core_ref）；`evidence_registry_summary`；事件材料（key_event_refs 恒空）。
- **禁止碰**：抹平 high severity 冲突；改写 conflict_id；漏掉任一非 downgraded 假说回应；自行拼接索引里不存在的 `parent#field`（reviser.md:28）。
- **最小充分证据形态**：`revision_summary` + accepted/rejected_critiques + `revised_thesis`（20 字段）+ `remaining_conflicts`（每条带 why_retained）。
- **回退条件**：`hypothesis_id` 集合与输入不一致 → carry-forward 原回应并留痕（现有 pre_validate，orchestrator.py:649-652）；`reject` 无反证 ref 且索引确实无可用 ref → 强制降为 `absorb_partially` 并写缺哪条证据；evidence_refs 越界 → 净化/打回。

### final_adjudicator
- **职责一句话**：写质量闸门 + 读者结论，姿态由证据定，不给自己放行（final_adjudicator.md:3-8,35）。
- **必须给**：修订稿（注意 T47 A3：final 拿的是修订前原稿，`03_根本审查总报告.md:86`——配餐单必须显式传 `analysis_revised.revised_thesis`，orchestrator.py:681-689）+ critique + risk 三件套 + schema 结果 + key_evidence_refs（只要 ref key+权限+聚合读数，不要成分明细）+ known_data_gaps + DataIntegrity/发布状态（T47 缺失，`phase1/final_adjudicator.md:170-174`）。
- **不给**：`synthesis_guidance`（Thesis 版）；`pricing_expectation_ledger`；`evidence_registry_summary`；事件材料。
- **禁止碰**：重新调用数据源；跳过 critic/risk/schema 另起炉灶；把谨慎当默认答案；把"风险保留完整"当唯一质量标准（final_adjudicator.md:303-313）。
- **最小充分证据形态**：`final_stance`+`stance_label`+`reasoned_verdict`（三条理由各带 ref，600-1200 字）+`price_reflection_map` 五类+`reader_final`+`quality_gate`。
- **回退条件**：`reasoned_verdict` 方括号 ref <3 或越界 → 打回/降级 `approved_with_reservations`；`must_preserve_risks` 非空却未逐条点名 → 打回；数字在散文中但无对应 ref → 该数字改写为定性或补 ref，补不出就删。

### integrated_adjudicator
- **职责一句话**：唯一对质点，把数据判决与事件卡放一桌对质，姿态逐字继承、永不改判（integrated_adjudicator.md:3-6,11）。
- **必须给**：数据判决本体（final_stance/reasoned_verdict/principal+secondary/must_preserve_risks/invalidation/payoff/priced_narrative）+ ≤10 张事件卡（含 fact_summary/interpretation/needs_data_confirmation/limitations/source_tier）+ ≤3 份非兜底调查报告 + ≤8 道 cross_layer_questions + 从实发 payload 导出的 `allowed_data_refs` 与 `ref_authority`（integrated_synthesis_report.py:300-334）。
- **不给**：白名单之外任何 ref 的数值；假说原文（若无，不得要求 IA 解释假说 ID）；事件卡作为指令来源（integrated_adjudicator.md:15）。
- **禁止碰**：改判 stance；把事件写成因果；引入输入外数字/事实/晚于 effective_date 的信息；`answered_by_data` 无 ref 硬答（integrated_adjudicator.md:11-14,27）。
- **最小充分证据形态**：`stance_echo`（逐字）+ `integrated_verdict`（600-1200 字）+ 六档归档 + `conflict_matrix`（每卡 card_id/event_side/relation/data_side_refs/note）+ `question_answers`（每条 question_id 逐字复制、answer_status 三态、missing_evidence 具体到字段与时间窗）。
- **回退条件**：`stance_echo != final_stance` → 整包打回，两次失败走确定性拼装（integrated_synthesis_report.py:555-557,362-370）；`answered_by_data` 无证据 → 自动降 `cannot_answer_yet` 并补占位缺口（integrated_synthesis_report.py:508-510）；`conflict_matrix` confirmed/challenged 无 data_side_refs → 自动降 `not_yet_testable`（integrated_synthesis_report.py:546-551）；`notes` 出现 `rejected_unknown_ref:` → 视为当轮质量警报。

## 三、如果必须按现状施工，最不能省略的三道保险

1. **层站"给够"对账（防看不见就编）**：逐层机器断言 `manifest(analysis_required=true) 集合 == prompt 内 layer_raw_data 键集合 == 产物 indicator_analyses.function_id 集合`；L1-L5 任一层的 `layer_facts.state` 预置结论必须从"答案"降级为"未验证草稿、不得直接引用"，否则预置答案会顺流污染五层（T47 A8：五站 state 全带答案，`03_根本审查总报告.md:91`）。

2. **治理链分料与引用全集对账（防挑刺站吃同一碗饭、防伪引用）**：critic 与 risk 的 governance_input sha256 必须不同（risk 零 thesis_* 键）；reviser/final 输入不得含 Thesis 版 `synthesis_guidance` 与自标 `forbidden_as_core_ref` 的 `pricing_expectation_ledger`；`key_evidence_refs` 必须 ⊇ thesis 全部 evidence_refs/counterevidence_refs（T47 A2 实锤：缺的 3 条全在反证位，`03_根本审查总报告.md:85`），缺一条即装包失败。

3. **调查与事件两条支线的存在性对账（防静默缺席）**：受控调查"委托数 == 进 IA 报告数（失败也要占位）"（T47 A6，`03_根本审查总报告.md:89`）；bridge/治理各站 event 字段必须恒空（4.7 口径，系统说明书.md:378），若未来放开为"仅背景"，必须同时上"evidence_refs 不得含 event: 前缀"的机器校验；IA 的 `allowed_data_refs` 只从实发 payload 导出、`stance_echo` 逐字全等，两条都写成会失败的机器测试，不给未来执行者留手改的口子。
