## Q1 · 形态选择：A 纯流水线 / B 全 agentic / C 混合

| 形态 | 是什么 | 致命伤 | 证据 |
|---|---|---|---|
| A 纯流水线 + 小修 | 固定采集器抓什么就解读什么 | 仅标题率、正文截断等病永远修不掉；升级能力为零 | T47 C9 |
| B 全 agentic skill 化 | 给 agent 职责宪章 + 搜索/数据工具，自由查 | 可复现性丢失（两次跑路径不同）；成本失控（多代理 ~15× token 警告）；隐含决策无处审计（Cognition 原则 2） | 调研 §一.4/5 |
| C 确定性底账 + agentic 补采升级层 | 底账保留流水线（可复现、信用基础）；其上 agentic 层只做补采升级 | 两个子系统都要维护（复杂度成本真实存在） | 调研 §三 |

**我的倾向：C。** 判据是任务形状（调研共识 3）：底账采集是"固定节奏、可复现优先"的任务，流水线赢；补采升级是"开放探索、广度优先"的任务，agentic 赢。两种纯形态各丢一半。

**收敛状态（08-11 会话）**：所有者认可 agentic 能力的价值，方向收敛于 C；争议点从"要不要 agentic"转移到"agentic 层的定位与目的"（见 Q2 修订版）。

## Q2 · agentic 层的定位与目的（核心争议题，08-11 修订）

所有者指正：它的价值不只是"把标题追成全文"的补丁——**自由搜索和调研能力本身就是目的**，可以让事件层更全面（类比 Kimi Deep Research）。

~~老报告 §4.3 八类材料~~ **（08-11 所有者裁定：八类只是老报告的举例，不作 canon；第二层该有什么材料，从第一性重新推导——见 Q2+）**

三档定位（累进关系，不是互斥）：

| 档 | 定位 | 干什么 | 成本/风险 |
|---|---|---|---|
| 一档 · 流水线体检 | 确定性采集的三性过堂（08-11 所有者重定义：不是给流水线打补丁，是先审流水线本身） | 逐源审三性——**靠谱**（来源是否官方/一手）、**必要**（是否回答四类问题之一，见 Q2+）、**可死板拿**（格式稳定、确定性可得）；三性不过的源**撤出流水线**，转 agentic 或弃用 | 低；结果可能是砍源而不是补源 |
| 二档 · 扩编层 | 八类材料的补全者 | 主动覆盖产业周期、卖方观点、市场叙事、制度语境、历史语境——按宪章定期巡逻 | 中；需议程纪律与精力分级 |
| 三档 · 研究部 | Deep Research 式专题调查 | 对重大问题（如"AI capex 叙事是否动摇"）出专题研究包，作为假说线索交 IA | 高（多代理 ~15× token 量级）；质量方差大，需对账机制 |

**不变的红线（任何档位都适用）**：产出永远是**材料**（候选事实卡 / 假说线索），不是判断——全部流向 IA，由 IA 裁决；不作因果断言；事实/解读/观点三分；全程留痕；来源分级。三明治结构保证：它再强也污染不了第一层。它与 Deep Research 类消费产品的本质区别也在这里：那是"直接给答案"，我们的 agentic 层是"证据治理系统内部的材料生产者"。

**研究议程的三个来源**（建议并存）：① 静态宪章（八类材料的常备职责）；② 缺口驱动（底账的 needs_data_confirmation、IA 的 adjudication_gap 消息——老报告 §5.2 早留了这个通道）；③ 所有者临时命题。

**产出形态**（建议分级）：巡逻产出 = 事件卡（现有九字段格式）；专题产出 = 研究包（事实/解读/来源分级/反证/未解释项齐全）；两者都进统一事件底账，原始抓取永远保留、只追加不改写。

**我的倾向**：一档必做；**二档是主体**——这才是"让事件层更全面"的正解；三档保留为**按需触发**（只对所有者命题或 IA 的重大缺口开火，配精力上限），避免把三档的成本和质量方差常态化。

**待你裁**：定位档位组合；议程三来源是否认可；三档的触发权（IA 缺口可自动触发专题，还是必须经你）。
**已裁（08-11）**：一档+二档+三档按需；议程三来源认可；三档暂时必须经所有者。

## Q2+ · 第二层到底是什么（第一性推导，08-11 应所有者要求）

不从老报告的八类出发，从"第三层要干活缺什么"出发：

**第一层管测量**：正式数据能说"世界现在是什么样"。但数据有四样东西**永远说不出来**——

1. **为什么**：数据说信用利差走阔了 30bp，说不出是因为关税新闻还是盈利下修——**原因候选**在数据之外；
2. **接下来**：数据全是已发生的；下周的 FOMC、财报、指数再平衡这些**已排期的催化**在数据之外；
3. **人们在想什么**：价格不仅反映事实，还反映参与者的信念和叙事（反射性）——**被相信的事**本身就是市场现实的一部分，但不在任何指标里；
4. **数据该怎么读**：指数方法学改了、监管规则变了，同一个数字的含义就变了——**规则语境**在数据之外。

第三层要做对质和竞争假说，四样缺一不可。**第二层 = 为裁决补全"数据说不出来、但会改变判断"的那部分外部世界。** 由此推出四类材料（按"对质要回答的问题"分，不按来源分——老报告八类里"主流报道"是渠道不是类别，属分类错误）：

| 类 | 回答的问题 | 实现分工 |
|---|---|---|
| ① 已发生的事（候选原因） | 数据异动的解释候选 | 流水线为主（官方源/EDGAR/主流订阅），agentic 做全文升级与发现 |
| ② 将发生的事（日程与催化） | 数据还没反映什么 | 流水线为主（日历高度结构化），agentic 补"未排期的待决事项"（ pending 监管、诉讼） |
| ③ 被相信的事（叙事与观点） | 市场现在信什么、分歧在哪 | **agentic 为主**——叙事和观点无法死板采集；卖方观点、社媒叙事默认弱来源标签 |
| ④ 规则语境（制度与方法学） | 数据该怎么读 | 低频维护的"制度档案" + agentic 监听变化（再平衡规则、SEC 新规） |
| ⑤ 历史语境（参照物） | 这种组合以前出现过吗 | **三档专题个案处理（必须经所有者）**；"历史上像今天"引擎重建在不做清单里继续冻结，另行决策 |

**第五类（所有者 08-11 裁定立类）**：历史语境立为第五类材料。注意它是分析参照物而非事件材料，且引擎重建继续冻结——所以初装形态只做"经你点头的专题个案"，不建常设引擎。

**镣铐跟着材料走**（任何一类、任何档位）：事实/解读分离、来源等级、时间戳、needs_data_confirmation 钩子。

**一档的正确形态（流水线体检）**：三性全过的源才配留在流水线——这条从一次性体检变成**常驻规则**：新增采集源先过三性审查，现有源逐个过堂（Wind 需登录、浏览器采集仅审计附件等已有裁决自动代入）。体检产出 = 每个源的三性判定表，而不是补丁。

**待你裁**：四类分法是否认可；第五候选（历史语境）的处理；③的弱来源默认标签是否照老报告 §3.3 执行。

## Q3 · 不做回测，靠谱性怎么验证（替代手段清单）

回测的目的是验证靠谱性，但靠谱性可以拆成几个可独立验证的子问题，每个都有比回测便宜的手段：

| 靠谱性子问题 | 替代验证手段 | 成本 |
|---|---|---|
| 它说的是不是原文说的 | **主张-原文对账**（CitationAgent 模式：独立一步把每条主张对回原文位置，机器跑 + 抽查） | 低，可机器化 |
| 它是不是在拿弱来源充硬事实 | 来源分级纪律的**机械检查**（等级标签 vs 实际来源） | 近零 |
| 它说"数据能确认我"是不是真的 | **needs_data_confirmation 与第一层数据对质**——第一层数据就是裁判，不用回测 | 中（IA 侧已有钩子） |
| 它有没有系统性漏事件 | 渠道真空核查的回看抽查 + 你每周抽 N 张卡人审 | 低 |
| 它前瞻性判断靠不靠谱 | event_challenge 观察清单的**事后兑现检查**（轻量复盘，不是回测） | 低，穿插做 |
| 改造工程有没有让它变好 | **约 20 条真实升级任务的测试集**（LLM 初评 + 你抽查），Anthropic 研究系统的现成模板 | 一次性 |

**我的倾向**：六件全要，没有一件需要回测。**待你裁**：抽卡人审的频率（每周 5 张？）和你愿不愿做这件事。

## Q4 · 时效纪律（不做回测后的简化版）

- 补采层只服务**实时 run**，"锁死历史信息窗口"这个最硬的问题随之消失（调研 §五 坦承它本无现成答案）；
- 但每条材料仍必须记录 `published_at` / 信息可见时间——为未来留重建能力，也为快照场景留过滤依据；
- 第一层回测纪律（effective_date、兜底路径）**不受影响，照旧**（T39 该修还修）。

**我的倾向**：照此。**待你裁**：无（这是逻辑推论，除非你预见要做第二层历史研究）。

## Q5 · "第二层成熟"的定义（IA 门脸复议的触发条件）

不定死阈值，先定**度量**，跑几次拿基线，再定达标线：

1. 全文率（仅标题事件占比 ↓）；
2. 来源等级分布（官方/主流占比 ↑）；
3. 主张-原文对账通过率；
4. 渠道真空核查覆盖率（已登记采集源中，本次运行有明确"有/无新事件"答案的比例；登记了却静默无记录的就是真空。注：08-11 更正——原稿括号误写成"九渠道"，"九渠道"是事件卡里金融传导渠道的枚举，不是采集渠道，采集渠道以代码注册表为准）；
5. IA 对质时事件侧引用可用率（IA 引用事件卡时，卡片字段完整的比例）。

**我的倾向**：五项全收，基线测量先行。**待你裁**：度量清单是否增减。

## Q6 · 实现路径（建议暂缓裁，原型先行）

- **为什么不拿 PI 当整个项目的脚手架**（所有者 08-11 问）：层不对。PI 是"自主工具调用 agent"的运行时（TypeScript/Bun，交互式编程助手赛道）；我们系统的资产恰恰是**相反的东西**——固定编排、合约校验、代码强制的隔离与供给设计（contracts.py / schema_guard / packet_builder / 证据注册表），PI 一样都不提供；且全库 Python（Wind/pandas/数据工具链），换 TS 等于重写。PI 值得借的是**范式**（技能三层披露、按需加载、上下文预算帽），这些我们在自己的 orchestrator 里就能实现。
- **补采层若做 agentic 循环**：原型阶段建议自建小循环（我们已有 llm_engine 的多模型路由与重试），几百行内的事；真长到"需要持久会话、自主探索半小时"的程度，再评估 PI SDK / Claude Agent SDK 这类 harness——到那时它是**一个层的候选组件**，不是系统架构。

**待你裁**：认可"原型自建"即可，harness 选型留到原型之后。
