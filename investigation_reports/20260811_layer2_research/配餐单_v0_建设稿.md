## 〇、三条原理（本文每次"必须给 / 不给"都由这三条推出）

- **P1 第一性原理：这四站是治理链，不是重新分析原始数据的分析员。** 上游 L1-L5 五层已分析，桥接已把层间结论接好；治理链引用上游结论时，只需要能定位证据（引用名 + 该证据的结论级读数），不需要重新拿到全量原始数值。依据：`系统说明书.md` L136（反方只能看桥接摘要与证据清单）、L152（论点"你不是重新分析原始指标的人"）、L166（critic 不能重新调用原始数据源）、L180（risk 只能条件语言）。
- **P2 金融学原理：critic 要能检验"论证是否选择性引用"——它需要论证全文 + 压缩证据包；risk 要列"论证之外的盲区"——它看论证会被带走（论证盲），所以要压缩证据包 + 冲突清单 + 各层摘要。反方/论点只是把桥接结论转成对抗/综合判断，不许重新算原始指标。** 依据：`investigation_reports/20260813_architecture_northstar_revisit/06_六问定案_定案与施工说明.md` L76-98；`src/agent_analysis/prompts/critic.md` L68-72（选择性引用检查）、`src/agent_analysis/prompts/risk_sentinel.md` L119-127（边界横跨五层）。
- **P3 LLM 作用原理：材料越长，注意力越被稀释、成本越高、越容易幻觉；但"引用的名字必须真实存在"——所以证据引用名清单（约 94 个、共约 3.4KB）不能删，evidence_index 的 ref key 不能删（引用合法性校验靠 key 存在），可以瘦的是 field_value 原始数值本体。** 依据：`06_六问定案_定案与施工说明.md` L76-82（56 万→约 15 万、field_value 占反方 73.5%/论点 75.8%、94 个名字 3.4KB）；`investigation_reports/20260725_thesis_counter_thesis_slimming/PROPOSAL.md` L49（94 条 ref）、L66（合法引用只到 parent#field 一层）、L76（ref key 集合不能动）、L120-124（压缩后 key 100% 不变）。

## 一、counter_thesis 配餐单

### 职责一句话

在 Thesis 生成之前，只回答一个问题：如果主线解释不是最好的解释，还有哪一种替代解释能更好地解释当前证据；至少一条做方向对抗，不做最终裁判（`src/agent_analysis/prompts/counter_thesis.md` L5、L7、L13-17）。

### 必须给

| 字段 | 为什么离不开 | 提示词/代码原文支持 |
|---|---|---|
| `bridge_v1_structure`（代码取第一条非 feedback_bridge_v2 摘要） | 反方必须知道桥接主线姿态，才能做"方向对抗"：主线谨慎就必须构造最强建设性解读，主线进攻就必须构造最强看空解读 | `counter_thesis.md` L13-17："如果 Bridge 主线姿态是谨慎/防守，你必须构造当前证据所能支持的最强建设性解读……如果主线姿态是进攻/建设性，你必须构造最强的看空/防守解读。" |
| `bridge_v2_feedback_summary` | 反方需要知道桥接第二轮反馈解决了什么、留下什么未解决张力 | `counter_thesis.md` L27 输入边界逐字列出 `bridge_v2_feedback_summary` |
| `non_stub_investigation_reports`（非兜底调查报告） | 反方被允许使用真实调查报告作为反方解释的弹药；没有就不能编造 | `counter_thesis.md` L28 输入边界；L37："如果没有真实调查报告，不能编造'调查发现'。" |
| `synthesis_packet_without_self_reference`（瘦身后，含 `layer_summaries`、`bridge_summaries`、`high_severity_conflicts`/`high_severity_typed_conflicts`、`principal_contradictions`、`objective_firewall_summary`、`synthesis_guidance`、瘦身 `evidence_index`） | 反方被允许"基于 synthesis_packet_without_self_reference……提出反方解释"，并必须承认它来自现有 evidence_index 的重新解释；冲突与主要矛盾是替代解释的素材 | `counter_thesis.md` L25、L37；`系统说明书.md` L136（反方资格：桥接摘要 + 非兜底报告 + 允许引用的证据清单） |

| `forbidden_context_refs`（`thesis_draft.json` / `analysis_revised.json` / `final_adjudication.json`） | 独立性边界：反方必须在主论点之前跑完，物理上不能看到主论点再假装反对 | `counter_thesis.md` L31-35；`系统说明书.md` L138 |

### 不给

| 现打包内容 | 拿掉后会不会编造或漏判 |
|---|---|
| `evidence_index` 每条子引用的 `field_value` 原始数值本体（raw_series、constituents、flagged 等逐票/逐日明细，以及聚合原始数值） | 不会。反方没有合法引用路径指向 field_value 内部——合法 sub-ref 只到 `parent#field_name` 一层（`PROPOSAL.md` L66）；引用合法性校验只看 key 是否存在，与 value 内容无关（`orchestrator.py` L2756-2772；`PROPOSAL.md` L76）。反方要的"读数"来自父级 `current_reading`/`normalized_state` 与 `layer_summaries.key_evidence`（`orchestrator.py` L4610-4612），拿掉原始数值不会使它漏判；若某条证据的结论级读数不足，反方按提示词只能承认"来自现有 evidence_index 的重新解释"，不许自己补算（`counter_thesis.md` L37）。 |
| `competing_hypotheses` / `hypothesis_competition_summary` / `adjudication_history` / `counter_thesis_boundary` | 不会。这四者是与反方自己参与产出的竞争结果（自我循环），现有代码已在 payload 构造时 pop 掉（`orchestrator.py` L2730-2735）；拿掉是为了防止反方读到"自己的输出被如何裁决"。 |

### 禁止碰的东西

- `thesis_draft.json`、`analysis_revised.json`、`final_adjudication.json`（`counter_thesis.md` L31-35）。
- 原始数值本体 / 重新计算原始指标（P1/P3；`06_六问定案` L78-79）。
- 事件材料（`系统说明书.md` L378）。
- 自行拼接不在 `allowed_evidence_refs` 里的 `parent#field` 子引用；不得输出 artifact 路径当 evidence ref（`counter_thesis.md` L41）。
- 编造"调查发现"（`counter_thesis.md` L37）。

### 最小充分证据形态

**引用名 + 父级一句话读数；子引用只留身份 + 发言权标签。不需要完整 field_value。**

- 每条父级 ref 保留：`metric` + `current_reading` + `normalized_state` + `permission_type` + `mixed_field_authority` + `source_tier`（这些就是 `orchestrator.py` L4570-4590 构造的"结论级字段"）。
- 每条 `parent#field` 子引用保留：`field_name` + `parent_evidence_ref` + `permission_type` + `field_authority`（发言权规则），删 `field_value`（`orchestrator.py` L4596-4607 现构造中含 `field_value`，C2 施工删这一项）。
- `allowed_evidence_refs` 是纯名字清单（约 3.4KB），一字不删（P3）。

### 回退条件

- 结构校验拒绝率上升（`support_evidence_refs must not be empty` / `contains refs outside evidence_index` 增多）→ 说明模型没有足够信息选对 ref：先加回父级 `narrative` 全文；仍不行再加回 `field_value` 的聚合字段（`value`/`unit`/`coverage`/`windows`），但**不**恢复逐票/逐日审计明细。
- 方向对抗消失（`principal_counterargument` 退化为"证据不足"、所有假说都是同一方向）→ 加回 `bridge_summaries` 完整版与 `bridge_v1_structure` 全文，让反方重新看见主线姿态细节。
- 终审质量闸门出现"反方漏判主要冲突"（quality_gate 显示反方未覆盖高严重度冲突）→ 加回 `high_severity_conflicts` / `high_severity_typed_conflicts` 的完整描述字段。

- 姿态校准失真（一边倒证据输出骑墙结论）→ 不是加料问题，是提示词问题；但若因 `objective_firewall_summary` 被误删导致，恢复它全文（v0 未删，无需动作）。
