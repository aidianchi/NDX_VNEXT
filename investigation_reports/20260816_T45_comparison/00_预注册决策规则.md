## 一、第 0 问的判定规则

已知五缺陷（幽灵许可 / 预算截断 / PIT 泄漏 / L3-L5 零登记 / 严格模式不留痕）逐一做根因映射：

- 根因落到 **自有编排/拼装代码、数据层、合约层、自家产物层** → 记"非 harness 层"。
- 根因落到 **当前运行 harness 本身**（即：不改自有代码、只换 harness 就能修）→ 记"harness 层"。

结论规则：

- 若五条根因 **harness 层计数为 0** → **不建议迁移**；重建部分的第 3/4 问按任务书终止展开，最终报告只回答第 0、1、2 问 + 说明终止依据。
- 若 harness 层计数 ≥1 → 迁移进入第 3/4 问评估，但最终是否建议迁移仍由下面第二节的迁移规则决定。

## 二、迁移（重建）建议规则

只有**同时**满足以下 5 条，才允许最终建议"迁移到外部 harness 重建"：

1. 第 0 问 harness 层根因 ≥1；
2. 目标 harness 所有会自动向上下文注入内容的机制（跨 agent memory / auto-compaction / retrieval / shared state 及同类）都能**全部关闭**，且每一机制都有官方文档/源码级证据，不允许"应该能关"这类推测；
3. 关闭上述机制后，目标 harness 仍保留至少 3 项对 NDX 项目有实质价值的增益（成熟重试、并发、可观测性、工具生态、隔离等），否则判定为"关完只剩进程管理器"；
4. 能保留等价于 `prompt_audit/**/*.prompt.txt` 的字节级可审计落盘物，且层间隔离继续由"机械构造"实现（能事后证明，不是只能口头声明）；
5. 预计迁移 + 重建总成本 ≤ 留在现架构做所选变体成本的 **2 倍**，且迁移不削弱北极星三支柱（事实扎实 / 证据面均衡 / 校准闭环后置）。

不满足任一条 → 最终建议"不迁移，留在现架构"。

## 三、变体选择规则（A / A′ / B）

候选定义以 HANDOFF 第五节为准：
- **A**：代码侧检索——编排代码在组装提示词之前按该站声明的问题做相关性排序；
- **A′**：代码侧深度分档 + 站点输出 schema 里加必填 `unmet_information_needs`（ref 枚举），零往返、零新增失败面、严格模式可强制；
- **B**：模型侧按需取用——模型自己发起取用调用，单次调用改成循环。

逐条规则：

1. **A′ 优先于 A**：只要 A′ 的必填 `unmet_information_needs` 枚举能放进现有输出 schema、不增加调用往返、不新增失败面，最终建议就不得落在 A 而不提 A′。
2. **B 的高门槛**：只有同时满足以下 4 条，才允许建议 B（或含 B 的组合）：
   - (a) 有证据证明"模型**事前**主动要了哪几条"的审计价值，无法被 A′ 的"事后缺料回报 + 代码筛选留痕"组合替代；
   - (b) `tool_choice="auto"` 下模型不走工具通道的失败概率，能被代码/严格模式约束到可忽略，且有官方文档或实测证据；
   - (c) B 的循环化增量成本，比当前"全量推送"的输入成本至少省 **20%**（用 token 实测或可靠估算）；
   - (d) B 不破坏五层隔离与 `prompt_audit` 字节级审计。
3. 最终报告**只给一个主建议**（迁移或不迁移 + 选哪个变体），并附证据与代价；不同时给老板摆三个"都行"。
4. 任何外部事实必须带来源 URL 与日期；任何代码事实必须带 `文件:行号` 且可复跑；拿不到证据的写"未证实"，不得按印象下结论。
