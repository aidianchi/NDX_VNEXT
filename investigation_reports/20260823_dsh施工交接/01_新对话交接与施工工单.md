## 〇、给老板的人话版：我们准备干什么

**一句话：给系统的事件层装一个"研究部"。**

现在的系统像一个纪律严明的体检中心——每次跑都是同一套固定项目，查得细、可复查，但只会查套餐里的项目。你要的"与时俱进的探索能力"（比如自己去把"AI capex 叙事动摇没有"这种问题查到底），体检中心干不了，得有一个能出门调研的研究部。

研究部怎么建，方针已定：

- **底盘用现成的（dsh），不自己造**。调研已证实它"一切皆插件"、有官方 Python 接口、能锁 flash——自己造等于重复造轮子，还造得不如它。
- **但研究部的"规矩"是我们自己的，三圈制度不变**：
  1. **谁出题**——议程账本：常驻巡逻职责、系统缺口、你临时命题，三个口子汇进同一个账本；
  2. **给多少钱**——每次调研带经费卡（token 上限），花完代码硬停，产出如实标"半成品"；
  3. **写完谁核**——每条"事实"必须指回抓到的原文位置，对不上的降级标注，不许编。
- **它产出的是材料，不是判断**——研究部写的东西全部交给综合裁决（IA）过目，永远进不了数据主链。

**新对话里会发生什么**：先把 dsh 在本机点亮（官方 Python 接口，Mac 有现成支持），再把三圈制度逐圈装上，最后用"AI capex 叙事"跑一次真巡逻验收。施工中有 5 个细节点需要你现场拍板（见第四节），都是一句话的事。

## 三、施工范围（一期 = 二档地基）

1. **点亮 dsh**：Python SDK 在本机跑通一个最小任务（环境事实见第七节）。
2. **议程账本**：`output/state_ledger/event_agenda.jsonl`（只追加），三来源汇入；每条议程带 budget_cap。
3. **经费卡**：dsh 侧自写预算插件（几十行 TS，或经 hooks 桥用 Python 写——优先试 Python 桥）——调用前查余额、耗尽硬停。老板已确认 dsh 可自配模型、可锁 flash。
4. **对账器**：读 dsh 的 session 落盘日志，对每条产出 fact 做"指回原文"校验；对不上降级标注（不打回）。对账通过率即五项度量第 3 项。
5. **搜索腿**：挂 dsh 的 web-search/fetch 工具 + 自写域名白名单策略插件（白名单范围见第四节待拍板点 1）。
6. **镣铐承接**：四条镣铐（事实/解读分离、来源分级、时间戳、needs_data_confirmation）——工具边界靠插件代码强制，语义层进 system prompt 的 prompt section。
