卷宗 01

全局流水线：这台机器造什么

系统只做一件事：把纳指100（NDX）相关的多方数据，变成一份可以逐条追溯来源的投资判断书。五个分析员各自独立看自己那摊数据——利率与宏观、信用与波动、资金行为、盈利与估值、结构与叙事——然后跨层对质找冲突，正反双方拿同一份"证据菜单"（这次可以引用哪些证据的清单）辩论，终审写成判断书。判断做完不是终点：它还要在事后被打分，打分结果反过来修正方法。（出处：现在.md「三十秒看懂全局」）

五层互相看不见，是刻意设计，这条边界叫层间隔离。 L1-L5 只共享静态规则——五层框架各自的职责、纳指怎么定义、本层指标该怎么判读——不共享"这次谁看到了什么、判断了什么"。这不是写在纸上的承诺：审计时用真实提示词逐层核对，五层"是否出现跨层信号"的字段全部为空，跨层的函数名只出现在格式示例里、从不带数值。（出处：ARCHITECTURE.md 3.2「静态规则可以共享，运行时状态不能共享」；HANDOFF.md 第六节「层间隔离（干净，是资产）」）

正反双方拿的是同一份证据菜单。 代码层面做不出"给反方少发材料"这种事——"菜单先天偏科"这种失败模式，实测不存在。（出处：《人话进度报告》第22封信；WORK_ORDERS.md 第二节总结论）

发布闸门是判断书出口的一道关卡：产物一旦被判定 blocked 或 unpublishable，就不能再被当成可发布结论继续使用。（出处：CLAUDE.md 常驻边界「发布闸门」）

事后打分回环是校准闭环：判断做出之后，等一段时间检查它对没对，再把结果用来修正方法——这是判断质量能不能"随时间可测量地变好"的关键一环。（出处：现在.md「三十秒看懂全局」）

卷宗 02

一站的解剖：事故为什么会发生

系统里大约有十六种"站点"（L1-L5、跨层对质、正反方论证、终审……），每一种本质上都在重复同一个四步循环：代码把材料装进一个"信封"交给模型，模型只看信封里的东西答题，代码检查交回来的东西合不合规，合规的就写入正式产物。多数事故，不是任何一步"做错了"，而是发生在两步之间那道没人守的缝上。

① 代码拼"信封"
每次提问前，代码要准备好四样东西：题目本身、这次能引用哪些证据的"证据菜单"、每条证据"这一站可以用"的引用许可证（代码里标注"这条证据在这一站可以被引用"的许可标记）、以及证据的数值内容本身。这四样理论上该是同一份东西的四个面，但写"许可证"清单的代码，和真正把数值内容装进信封的代码，是两段互不知情的独立代码。
② 模型答题
模型只能看到信封里装的东西，看不到别的层这次看到了什么、判断了什么，也看不到系统全貌——这是刻意设计的层间隔离。但反过来，信封里没装的东西，模型永远看不到，哪怕它就在系统别处完整存在。
③ 回程闸门
模型交卷后，代码只检查"形状与身份"：能不能按格式解析、引用编号对不对得上清单。这是刻意设计——宁可要一段没有完美索引的真思考，也不要一片空白。但它不判断内容对不对、全不全，所以"内容诚实但材料给得不全"这类问题，闸门天生拦不住。
④ 落盘存档
通过闸门的产出写入正式产物文件，成为下一站的输入，或最终判断书的一部分。

"闸门不判意思：校验器只判形状与身份——能不能解析、编号对不对得上。凡是要比对两段模型自己写的话才能判定的规则，都是设计出了问题。"

—— CLAUDE.md 常驻边界

放大①：为什么"许可证"和"数值"会脱节

最近四起真实事故，标在它们各自发生的位置

① 拼信封

综合裁决站：VXN 有名无实

报告里"综合裁决"这一节——终审写完判断书之后，另一个专门整合总结的环节，消费的是终审已经写好的 final_adjudication.json，不是终审本身——题目要求核对"实际利率、VXN 和信用利差有没有同步支持"。发给这一站的材料里，VXN 的引用名在、引用许可在，数值本身出现 0 次。模型据实回答"本轮输入未提供 VXN 指数数值和分位，无法验证"——它说的是准确的实话。同一份报告的信用与波动层（L2）却完整显示 VXN=30.84，10年百分位87.2%。

扫全站后发现这不是孤例：综合裁决这一站被允许引用的 26 个指标里，20 个都是"有名无实"（L1×4 / L2×4 / L3×3 / L4×3 / L5×6）。根因是两段代码各拼各的：一段扫描完整对象、按全量清单发许可证，另一段只挑 7 个叙事字段真正装进信封，两边从未对齐。终审判断书原文共 47,282 字符，其中 86.2%（40,762 字符）根本没传到综合裁决这一步，最大的一块是 24,978 字符的证据台账（占 52.8%）——那 20 条"幽灵引用"，恰好都采自这没传过去的部分。

出处：WORK_ORDERS.md 第三节 3.1
① 拼信封

受控调查：预算截断砍掉唯一带数值的材料

另一个不走主流程的调查环节——"受控调查"——有一次题目问"半导体链条、AI权重股和盈利预期有没有同步改善"，代码声明可以引用 4 份材料，唯一带真实数值的跨层备忘录排在第 4 位。系统又硬编码"最多只发 3 份"，而且按位置砍、不按相关性重排——第 4 份材料被无条件砍掉。这一站因此只拿到 3 份纯事件摘要，零 L1-L5 数值，最终因材料不足降级交白卷。

出处：WORK_ORDERS.md 第三节 3.1b
③ 回程闸门

半角引号，让表单从内部断裂

系统要求模型按固定表单交卷，闸门只检查表单格式对不对，这是刻意设计。但模型有权选择不走表单、直接交一段普通文字——这不是故障，是模型厂商的思考方式和"强制走表单"本身不兼容，系统只能允许它自选。有一站——"事件总结"——连续两次都选了不走表单，正文里出现一处没有转义的半角双引号（写在"这为AI投资究竟是价值破坏还是生产性资本支出这一竞争假说"这句话里），这个符号恰好是格式里的特殊字符，整段就此读不出来，那一节因此连续空了多次。

出处：《人话进度报告》第21封信
②③ 答题 / 闸门

"必须填满清单"逼着模型硬凑

早期合约要求某些清单字段（比如"共振链""传导路径"）必须填出内容，不许回答"没有"。两次不同行情、不同数据的跑，条数却纹丝不动地停在3条和4条——这种整齐反而是危险信号：内容像真的，但"到几条为止"这个停点是格式定的，不是数据定的。后来把这些字段改成"可以如实回答没有"，同一跑里模型也真的用上了这项新权利，共振链和传导路径的条数在有权说"没有"的情况下依然填满——这一次才有理由相信是真实结论，不是硬凑出来填格子。

出处：《人话进度报告》第20/21封信

四起事故里三起发生在①，一起发生在③——①正是"拼信封"这一步。所以当前的主方向 T38，就是把上下文供给从"预先塞满"改成"渐进披露、按需取用"，先把这个环节重修一遍。（出处：现在.md；WORK_ORDERS.md 第三节）

卷宗 03

保护分布图

八条常驻边界没有一条是纸上空文，每条都能在代码里找到真的在拦的那一行。但保护的力度不是均匀分布的——同一个形状反复出现：结构最硬的地方，恰好保护得最严；越软的地方，越是靠"目前还没人想到怎么绕"撑着。

维度硬的部分软的部分
权限校验 硬最终 8 条可发布结论 软二十万字级支撑叙事
边界牙齿 硬层间隔离、弱来源不进主链（未找到现实绕过路径） 软其余五条常驻边界部分强制
证据精度 硬L1 / L2 / L4 有字段级登记 软L3 / L5 零登记，永远只能整体引用
时点纪律 硬原始数据日期越界会被硬拦 软模型自身的后见之明拦不住（项目已如实登记）

而你平时读判断书的路径，恰好落在软的那一边：通读全篇、L1-L5 常看、审计区不看。保护最严的 8 条结论只是判断书的结尾；你实际花时间读的二十万字支撑叙事，权限校验从未覆盖到。

出处：WORK_ORDERS.md 第二节总结论、教训2；《人话进度报告》第22封信
