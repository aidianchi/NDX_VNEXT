## 第 22 封（2026-08-04）：七路同时体检，地基比我预期结实——但系统这次是被模型的诚实救的，不是被机制救的

### 先说总结论

你要求全面排查，我拆了七路并行去查。**结论是好消息**：你那八条铁律**没有一条是写在纸上没人管的**，每一条都能在代码里找到真的在拦的那一行。测试大部分是真闸门。密钥和你的钱没泄漏。正反双方拿的是同一份材料——**你最担心的"菜单先天偏科"那种失败模式，代码层面就做不出来。**

问题不在"哪里烂了"，在**保护的分布不均匀**。一句话概括：

> **这个系统保护得最严的地方，恰好不是你眼睛看的地方。**

最终那 8 条结论（包括"维持防御性低配"那句直接告诉你怎么动手的）每条都过了权限校验；而 L1-L5 各层叙事、正反双方的论证，二十万字，没有任何越权检查。**而你自己说过，你通读判断书、L1-L5 常看、审计区不看。**

### 这次挖到的最重要的东西

报告里有个自相矛盾：综合裁决那一节写"**VXN 数据缺失，无法验证**"，但同一份报告的 L2 层明明白白写着 `VXN=30.84，10 年分位 87.2%`。

我去查发给那一站的材料，发现里面有三样东西：VXN 的**引用名**、引用它的**许可证**、一道**必须用它回答的题**——**唯独没有 VXN 的数字**。

**模型说的是实话，而且是准确的实话。它没编、没糊弄，它诚实地报告了自己的处境。**

然后我扫了全站，发现这不是一个案例：**那一站被允许引用的 26 个指标里，20 个都是"有名无实"——给了名字、给了许可，没给数值。**

**VXN 之所以被发现，只因为它恰好是一道直接提问的主语，模型不得不当场交代。另外 19 条没有同等力度的追问兜着。**

**换句话说：系统这次是被模型的诚实救的，不是被机制救的。** 这是我这次最不安的一句话。

根因也找到了：有两个函数各自独立决定"该给这一站看什么"，一个按完整清单发许可证，另一个只挑七个字段发内容，**两边从来没对齐过，也没有任何一处代码检查"发出去的许可证，对应的东西是不是真给了"**。

### 你提出的那条路，我认为是对的

你说这件事"像 Skill 的核心思想"——**我认为这个类比抓得很准，而且它正好化解了 T37 卡住的那个两难。**

T37 卡在哪：菜单 102 条，68 条从没人引用过。想砍，但按引用率砍会把菜单固化成这一跑的视角，下次行情反转时反方需要的材料可能已经被砍了——而"菜单不得先天偏科"是你的铁律。

Skill 的机制是三层的：常驻的只有名字和一行说明；判断"这次用得上"才加载完整内容；再往下还有更细的材料，需要时才读。

**搬到证据菜单上，那个两难就不存在了**：一条都不砍，常驻的只有编号和一句话，完整记录按需再给。**广度和成本解耦了。**

**但这里我要当场更正自己一句话。** 我先前写的是"哪一站要用，**它自己开口要**"——**在现在的结构下这做不到**，是外部调研纠正我的，我去核了代码，它是对的：现在每一站都是**问一次、答一次**，中间那个"工具"通道是用来**交答卷**的，不是用来**要材料**的。Skill 那种"AI 自己决定读哪个文件"，前提是它能一边做一边反复取东西，而我们的站点没有这个能力。

所以这条路有两个版本，**得你选一个**：

- **版本 A：我们的代码先挑。** 在把材料发出去之前，代码按"这一站要回答什么问题"先筛一遍，只发相关的。改动小、不新增出错的地方。**但审计上拿到的是"代码按什么规则筛的"，不是"它想要什么"。**
- **版本 B：让 AI 自己要。** 这才是真正的 Skill 那一套，也**只有它能给出"模型主动要了什么"这个我们现在完全拿不到的信号**。代价是把"问一次答一次"改成来回多轮，多了出错的地方，还会把省钱的另一条路（缓存）拆掉。

我倾向 **A 先落地、B 作为后续可能**，但这是判断题不是技术题，你来定。

**还有一条外部调研查出来的陷阱，必须避开**：有个同类框架的做法是给多空双方**各自独立的材料库**。**那会直接违反你"菜单不得先天偏科"这条铁律。** 我们的做法必须是：正反双方用**同一次筛选、同一份结果**，只有立场措辞不同。

按你的要求，这一条我只写了方向和思想，没写代码。

### 我这次的三个失误，摆出来

**第一个，也是最该记的：我在只收到六路报告的时候，宣布"七路全部收齐"，然后给了一份自称收敛的最终建议。** 那份建议缺了整整一个方向，而那个方向里有一条 P0。如果你当时照着那个顺序去做，会先去修成本和边界，**而把你自己提过的需求漏掉**。原因很简单：前一路回来时我看到"信息量最大"就默认收尾了，没回去核对还剩几个在跑。**核对清单比感觉可靠，这次感觉赢了核对。**

**第二个：七路里有三路把严重度报高了，我逐条改判。** 但这不是它们能力差——数据层那路报的 P0，是因为它只看数据层，看不到下游有道闸门把脏数据整个挡住了。**这正好说明拆七路的价值和它的代价：单路看会给错答案，必须有人在上面把它们接起来。**

**第三个：我的拆分方式本身漏了一站。** 综合裁决那一站不走主流程，恰好掉在七路的缝里。是两路各自**如实交代了自己的边界**，我才把线接上——**如果它们含糊其辞，这条就漏了。**

### 我否决了什么

**否决一：不把"来源信息"塞进判断书的抽屉。** 这是你拍板的，我记下了。我原本认为读者在判断书里点开数字看不到来源、却又觉得"我已经核实过了"，这个假象比信息藏在别处更糟。你判断加进去会增加视觉冗余和阅读阻力——**这是你的判断，我照办，不再提。** 残留影响我只说一次：时间戳改完之后你能看到"什么时候的"，但仍然看不到"谁给的、什么口径"。

**否决二：不照搬那 48 个时间戳。** 配套文件里每张卡都挂一个日期，但**它们基本都是同一天**——48 处版面占位换来 48 次"对，还是那天"。改成只在数据陈旧时才出现，版面成本是零，信息量反而更大。

**否决三：不建议照抄顶级 AI 系统的做法。** 你问要不要参考 Claude Code 这类系统，我的答案是"参考，但主线不在那儿"。它们解决的是"会话无限长、下一句问什么完全未知"，而你是固定流水线、十几个站点、每站有写死的合约。**真正能搬的估计不超过三条**，而最该做的那件事其实是你自己已经写下、但还没贯彻到底的一条原则：**代码能导出的，根本别让人手工拼。**

**否决四：不认同 TradingAgents 那类框架当模板。** 我要求调研的 AI 独立验证或反驳这个判断、不许附和我，**它查完给的答案比我原来的说法更硬**：

它把论文全文和代码都读了，发现那些框架里**多方和空方读的是完全一样的材料**（字符相似度实测 42%、骨架 100% 相同），另一个框架的 8 个子 agent 收到的是**一模一样的提示词**。**也就是说，它们和我们犯的是同一个病**——而**那篇论文全文对这件事只字未提**。

**结论反过来了：不是我们落后，是我们已经注意到了，而它们还没有。** 你那条"拆分的理由是上下文隔离，不是模仿人类职位"的原则，在这次调研的 6 个框架里**一个都没做到**。

顺带两条同样反直觉的：① 有个顶级 AI 公司十个月内**推翻了自己**——原本主张"子 agent 应该共享完整历史"，后来发现**完全干净、不继承上下文的评审 agent 表现更好**。**这等于从外部验证了你的层间隔离不是过度设计。** ② 学术界目前**没有**任何公开方法能自动推导"每个 agent 的最小充分上下文"这件事——**这块没人系统解决过，我们不是落在后面。**
