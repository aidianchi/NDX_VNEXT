# Q-E：一个机制算"废物"的判定标准，以及 30 条疑似废物的裁决

> 本文是研究战役第六层 Q-E 的交付物。读者是总研究员，最终读者是老板。
> 证据边界：全部关于系统行为的论断以 `src/` 源码为准，行号对应 2026-09-15 工作区快照；普查事实来自 `research_fundamental/src_maps/gate_census.md`（89 个机制的普查表），编排事实来自 `research_fundamental/src_maps/orchestration_map.md`。两个仍在拦截位的机制（orchestrator.py:2864 与 7034-7046）由本研究员在源码中逐行复核，复核范围：orchestrator.py 2430-2547、2768-2894、6904-7075、8005-8037、935 行。

## 一、先解释本文要用的四个词

这四个词有公认出处（项目宪法或研究战役内部约定），第一次出现时配一句人话：

- **闸门**：代码里的校验点。AI 的输出送到下一站之前，闸门先检查一遍；检查不通过的处理方式只有两种——把错误原因喂回给 AI 重写，或者给产物打上降级标记。
- **拦截位与留痕位**：闸门所处的位置。拦截位的闸门失败会打回重试、阻断流程或降级产物，一次失败烧掉一整次 AI 调用；留痕位的闸门只在报告里记一笔，不拦任何东西。
- **身份比对与意思判断**：两种性质不同的检查。身份比对不看内容就能机械完成——编号在不在清单里、枚举值合不合法、日期超没超过截止日。意思判断必须读懂散文才能完成——这段话是不是夸大了材料缺席、措辞是不是把证据缺失当成了看空理由。项目宪法规定"闸门不判意思"：凡要读懂两段散文才能判定的规则都是设计错误（AGENTS.md 常驻边界）。
- **形状代理语义**：一种典型的设计错误。做法是拿能机械检查的表面特征——某个词出没出现、某段字符串一不一样、某个数字逐不逐字——去代理一条需要读懂意思的规矩。表面特征和规矩之间只要存在一个反例，这道闸就会打错人。

## 二、判定标准的推导（道层）

判定标准由四块原料合成，每块原料推导出流程图里的一部分。

**原料一：闸门六原则**（AGENTS.md 常驻边界，2026-08-31 老板批准入宪）。六条里与"废物判定"直接相关的是四条：②注意力优先——每次 AI 调用只干本职深度分析，所以让 AI 自查"输出是不是有效 JSON"这类代码零成本能查的事，本身就是浪费，与检查得准不准无关；③不埋没人才——不让分析师背字段名、填编号；④仆从——代码为 Agent 服务（递材料、簿记、排版），材料组装对了闸门自然失业；⑤报刊——文章让专家写，代码只排版装配。④⑤合起来给出改造方向：能由代码在输入侧装配忠实的，就不要在输出侧设闸惩罚。

**原料二：第一性判定**（六原则第⑥条）。一个限制的存废只问一个问题："不这样，深度分析还能被信任地交付吗？"能答"能"的，默认可删。这条把举证责任放在了机制一边：机制必须能说出自己防的具体事故，说不出就是没有存在的理由。

**原料三：道器分界**（总研究员补充）。道是意思层的规矩，例如"数字必须有依据"；器是形状层的检查手段，例如"数字必须逐字出现在材料里"。废物机制的典型成因是把道强行压成器：压出来的手段既不是道的必要条件（合法行为不满足手段），也不是道的充分条件（违规行为照样能通过手段）。终审数字核对器（orchestrator.py:7034-7046）就是这个病灶的实例——它惩罚的是"做了算术"这个行为，而算术恰恰是分析师的本职。

**原料四：成本核算**。每个闸门的账要两侧都能算：误伤成本是一次误伤烧掉一整次 AI 调用，在拦截位耗尽重试后还会烧掉整站产物（终审降级为 rejected 兜底，orchestrator.py:6943-6953；调查退成 stub 占位，2535-2547）；漏检收益是它真能拦住的那类事故乘上事故发生频率再乘上事故损失。两侧都可比较，才允许谈"宁可错杀"。

合成后的总规律：**废物只有两种形态。第一种是道器错配——把意思层的道压成形状层的闸，产生误伤和漏检双反例；第二种是分工错配——把代码零成本能查的事派给 AI 自查，纯收注意力税。** 判定流程就是按顺序把这两种形态识别出来。

## 三、判定流程图（文字版）

拿到任何一个机制，按以下顺序问问题。每问都给出明确的判定依据，答完即落档，不许含糊。

**第 0 步 · 定位。** 先记录两件事：这个机制检查的对象是什么（AI 写的散文 / 项目自家的静态文件与模板 / 代码生成的数据与落盘产物）；它处在拦截位还是留痕位。判定依据：对象决定审查入口——对自家文件和代码生成物做词表、键集检查是合法的（对象不是散文，不存在"读懂意思"的问题，普查表 #1、#43、#69 均属此类）；只有对 AI 散文的检查才进入后续废物审查。

**第 1 问 · 第一性之问（决定废除候选）。** 没有它，深度分析还能被信任地交付吗？判定依据：要求机制一方写出它防的具体事故场景——有历史 run 号最好——并指出没有它时谁来兜底。写得出事故且找不到兜底者的，答"不能"，进第 2 问；写不出事故、或者事故已有等效兜底的，答"能"，直接落**废除**档。

**第 2 问 · 道器之问（决定它守的是什么）。** 它守护的"道"是哪一条？用一句意思层的话写出来，例如"调查员不得谎称材料没有数据"。判定依据：写得出道的，进第 3 问；写不出道的，说明机制无的放矢，落**废除**档。

**第 3 问 · 分界之问（决定手段合不合法）。** 它的检查手段是道的充要条件，还是道的形状代理？判定方法是构造两个反例：（a）找一个合法行为会被它命中的案例（误伤案例）；（b）找一个违规行为能逃过它的案例（漏检案例）。判定依据：两个反例都构造不出来的，手段≈充要条件，属于身份比对，进第 4 问；任何一个反例构造得出来的，属于形状代理语义，跳过第 4 问直接进第 5 问找替代——形状代理语义没有资格谈成本，因为它的账永远算不平。

**第 4 问 · 成本之问（决定去留的最后一道）。** 误伤成本与漏检收益相称吗？判定依据分位置：拦截位的机制，误伤面必须为空或近零才配留在原位，因为一次误伤就是一整次调用，耗尽就是整站降级；留痕位的机制，误伤成本只是审计噪音，但如果命中率高到读报告的人学会无视它（狼来了），信号价值归零，等同废除。两侧相称的落**保留**档；不相称的进第 5 问。

**第 5 问 · 替代之问（决定改造方向）。** 这条道该由谁守？三个出口按优先级排：
- （a）代码能确定性判的，改造成身份比对后留在代码里——schema 锁枚举、编号插回比对、白名单核验，拦截力保留；
- （b）代码不能判、需要判断力的，道归提示词原则（写明条款编号），代码侧只留痕不拦；需要执法背书的走两个既有样板——"代码核验来源 + 模型判实质"分工（PC-28，persistent_checks_b.py:1206-1257），或者"代码自己重算、不要求 AI 自证"的重算带（src/recompute_belt.py:237-1813）；
- （c）根因能被代码消除的，消灭检测对象本身——例如徽章由代码从判决机械导出之后，"徽章与正文不一致"在物理上无从发生，检测器随之删除。
判定依据：改造方案落定后回到第 4 问复核一次成本；三个出口都不通且风险小的，落**废除**档，由发布闸门（blocked/unpublishable 不得当可发布结论）兜底。

**三档输出的义务**：落"保留"档要写清现状为何合理；落"改造"档必须写明方向（a/b/c）和接手者；落"废除"档必须写明这条道的接手者（提示词条款 / 某站职责 / 发布闸门），或者写明"防的风险不真实"——道不许悬空。

## 五、两个仍在拦截位的 B 类：深度分析

全系统 20 个 B 类里只有这两个还在"打回重试"的拦截位，所以它们的误伤成本最贵，逐条拆透。

### 5.1 `_validate_investigation_limits_against_materials`（orchestrator.py:2864-2894）

**机制实况（本研究员源码复核）**。受控调查站的重试循环是 `for attempt in range(1, 3)`（2430 行），最多两次尝试；每次尝试在引用校验之后调用本函数（2502 行）。本函数先用正则 `\d+(?:\.\d+)?\s*(?:%|％|倍|点|分位|亿美元|万亿美元)` 扫全部材料文本（2869-2874，materials_text 由 2417 行把所有允许材料拼接而成），材料里出现任何一个带单位数字，就启用第二组正则扫调查员 limits 字段的散文（2878-2889），命中"没有定量数据""不包含实际市场数据"这类措辞即 raise ValueError（2890-2894）。错误喂回模型重写；两次都失败，真调查被 stub 占位报告整个替换（2535-2547），finding 变成"本轮未执行真实调查"，limits 里追加 `llm_investigation_failed_fell_back_to_stub`。

**它防的真风险**。调查员在 limits 里声称"材料没有定量数据"而材料里实际有——即调查员夸大材料缺席。这条道是真的：limits 是数据边界声明，下游 bridge_v2、thesis、第三层裁决都会把它当真缺口对待，谎报缺口会污染整条推理链。

**误伤的合法行为**。三层误伤叠加。第一，正则不查相关性：材料讲人口结构附带一个 2.3% 的失业率，问题问的却是企业盈利，调查员如实写"材料未包含本问题所需的定量数据"就命中第一条正则（2880）被打回——"材料里有没有数字"是代码能查的，"数字与问题相不相关"是意思判断，代码判不了。第二，执法口径只惩罚措辞碰巧的人：写"没有……量化指标"必被抓，写"未提供""缺乏""见不到"就逃过去，同样的行为不同的措辞结果相反。第三，成本档位：一次误伤烧一整次调查调用；两次耗尽后损失的不是一次重试而是整条调查的内容——真调查被一句"本轮未执行真实调查"的占位文字顶替。

**正确的替代机制**。按第 5 问三个出口排：（a）代码能做的部分是把 limits 从纯自由散文改成"枚举标签 + 自由文本"——枚举值如 no_quantitative_data / no_price_series / no_confirmation_data，代码只查枚举合法性（身份），不扫散文，这符合"轨道 > 导出 > 规矩"的约束顺序；（b）"材料里有没有回答问题所需的数字"这个意思判断归提示词原则——controlled_investigator.md:6 已有"只能依据材料"的逐字纪律，补一句"声明缺口时点明缺的是哪类数据"即可，不需要代码执法；（c）代码侧若还想保留信号，把本函数从 raise 改成写 semantic_warnings 留痕，进 run_review 供人事后抽查——这与 2026-08-31 T69 把同类语义闸降级为留痕的先例一致。**裁决：改造——撤出拦截位，降级留痕；limits 结构化是根治方向。**

### 5.2 `_validate_reasoned_verdict_refs` 的数字存在性比对子条（orchestrator.py:7034-7046）

**机制实况（本研究员源码复核）**。终审站的 validator 链在 6926-6941 行组装，本函数以 `source_text=final_source_text` 接入；final_source_text 是终审实际收到的全部 payload 序列化后的文本（935 行 `json.dumps(final_payload, ensure_ascii=False, default=str)`）。数字子条提取判决正文里所有百分数和小数 token（提取正则在 7071 行，纯整数被故意排除以免误伤"三条理由"这类行文数字），任何一个 token 不在 payload 文本里逐字出现就返回校验错误（7034-7046）。错误进入重试反馈；耗尽后终审降级为 approval_status=rejected 的兜底裁决（6943-6953），发布闸门随之转 audit_only，第三层不再裁决。同函数另外两道闸——零引用拦截（7012-7016）和引用逐字 ∈ 证据索引（7023-7033）——是身份比对，不在本裁决范围。

**它防的真风险**。终审判决正文里的数字是 AI 编造的。这条道是宪法级边界（"不得编造"），而且风险真实：同函数零引用闸对应真实事故 run 20260725_232410——一份 514 字、数字详实的判决正文零处引用，报告照常发布（docstring 6983-6989）。数字一旦编造进终审正文，污染的是老板看到的最终结论，事故损失是全部机制里最高的一档。

**误伤的合法行为**。合法分析师行为里有一整类会产出不逐字出现的数字：两个输入数字的差值（payload 有 2.7% 和 2.3%，正文写"较上月回落 0.4 个百分点"）、单位换算（payload 写 0.023、正文写 2.3%）、四舍五入、多来源合计。"逐字出现"既不是"有依据"的必要条件（推导数字有依据但不逐字），也不是充分条件（逐字抄来的数字照样可以张冠李戴）——它惩罚的是"做了算术"这个行为本身。docstring（7002-7005）自辩这是"身份比对不是语义判断"，但按老板标尺，"推导数字能不能在材料里逐字找到"恰恰被明列为意思判断的例子。成本档位：一次误伤烧终审重试；耗尽后整份终审判决降级为 rejected 兜底——一次误伤的最终代价是整份裁决失去可发布性，而它拦的合法行为（算术）是分析师本职。

**正确的替代机制**。三层夹击，前两层代码已能做或已在做。第一层在输入侧：T70 P-B 事实卡 `_build_fact_card`（8005-8037）从证据索引装配"本段允许出现的数字"菜单，每条带 ref、指标名、数值原值、权限档，提示词侧明示"数字若与卡不符是装配的 bug，由系统修管道，不由你凑对"（final_adjudicator.md:119）——这是"构造即忠实"，在输入侧就把数字收敛成一张菜单，是闸门六原则第④条"材料组装对了闸门自然失业"的正解，保留并继续加强。第二层在事后侧：学重算带的模式（src/recompute_belt.py:237-1813）——代码自己拿证据索引核对终审正文数字，数值等值换算（2.3% 与 0.023 相等）代码能判，判不了的"差值、合计是不是合法派生"记 findings 清单交人复核，不打回模型。第三层在输出侧：数字子条撤出拦截位、降级为黄灯留痕，与 narrative_check.py:8-12 的自知设计对齐；拦截位只保留同函数的两道引用身份闸——它们有真实事故背书且是身份比对，恰好满足第 4 问"拦截位误伤面近零"的门槛。**裁决：改造——数字子条降级黄灯，拦截力留给引用身份闸；长期由事实卡（输入侧）加重算式代码自核（事后侧）夹击，而不是靠输出侧逐字比对。**

## 六、自检程序：防止这套标准被滥用成"新一轮凭感觉砍机制"

判定标准本身也是一条"机制"，同样要过第一性判定。给它配六条自检纪律，每条对应一种滥用方式：

1. **证据锚点强制**。每条裁决必须带 `文件:行号`；凡主张"会误伤"的，必须附一个具体构造的误伤案例（散文样例 + 命中路径），写不出案例的不许落"废除"档，只能标"待验证"。这条防的是凭感觉指控。
2. **道不落空**。每条废除或改造裁决必须写出这条道的接手者——提示词条款的文件位置、某个站的职责、发布闸门，三者至少居一；接手者写不出的，默认降一档处理（废除改成"降级留痕观察"），不许让道悬空。这条防的是把真规矩连同坏执法一起扔掉。
3. **辩护程序**。每条废除裁决必须经过一次反向辩护：由另一名研究员或 agent 扮演机制辩护人，回答"删了它什么会坏"，辩护词与回应记进裁决表。本次裁决的示范：#18 的辩护词是它 docstring 的自辩加真实事故 run 20260725_232410；回应是——那个事故由零引用闸防，不是数字子条防的，数字子条没有自己的事故记录。
4. **双侧成本**。误伤成本与漏检收益都要给出数字，给不出数字的明确标"待验证假设"；只列一侧的裁决作废重写。这条防的是只算误伤账、不算漏检账的单边裁决定。
5. **两步走纪律**。拦截位机制的处置分两步：先撤拦截、降级留痕，观察至少一个真实 run 周期确认没有事故反弹，再删代码。直接删除仅限本来就没有拦截力的噪音发生器（#4、#48 一类）。这条防的是矫枉过正制造新事故。
6. **年度复盘挂钩**。废除清单挂进 AGENTS.md 已有的年度复盘机制，一年后回看被废机制有没有事故反弹；有反弹的把机制请回来并把教训写进复盘。这条让废除决定永远可被事后评分，与项目"校准闭环后置"的支柱一致。
