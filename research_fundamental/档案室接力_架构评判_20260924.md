# 「档案室接力」架构评判（2026-09-24，独立评估，不顺手附和）

## 老板的设想

主链接力从"填表接力"（每岗填一张 JSON 大表单，代码装配进下一岗提示词）改为"档案室接力"：每岗产出写成有名字的文件上架，下一岗拿到的提示词是一张阅读清单，自己读文件、写文章。

## 总判

方向成立，但最终形态大概率不是二选一，而是老板自己命名的"回执单"混合体：**散文归档案室，机器要啃的归缩水的 JSON**。三堵墙全部属实；另有三坑老板未提到。节奏上"验证期内不动主链"我同意，且有一条比他说的更硬的理由。

## 三个优势的成色（逐一点名，含泼冷水）

1. **可观察：真，但是三个优势里最弱的一个。** 每个岗位实际收到的提示词现在已逐字落盘（prompt_audit），可观察性不缺存在、缺可读——几十万字符的归档载荷没人翻得动。文件清单确实一眼可读。但要补一层：清单在提示词里 ≠ 模型真读了。档案室形态下，可观察性的真身是**工具调用轨迹落盘**（它实际打开了哪些文件）。dsh 落盘 session 日志已有此能力（事件层对账程序就在读它）。
2. **模块化：真，但注意改的不是"写文件"，是"推变拉"。** 各岗产物现在本来就落盘（层卡、桥接备忘录等 28 项落盘产物）。真正的改变是：下一岗的上下文从"代码装配好推给它"变成"给它菜单让它自己拉"。
3. **治填表病：部分真。** 终审、正方这类"读大堆材料写文章"的岗位，稿纸形态确实断掉填表腔的传染源。但回执单 JSON 仍在，字段腔会缩进回执单里继续存在——说明书禁令那套不会失业，只是战场变小。更深的提醒：这两轮实锤的病根不只是格子，是"提示词里任何上口的短语都会被复读"。档案室里的样板文件若写得差，传染源只是换个宿主——"示例按发布物管理"这条原则在档案室形态下更重要，不是更不重要。

## 三堵墙核实（全部属实）

1. **机器要吃的那片不消失——属实，已逐项核实。** 报告页直接读结构化字段：姿态徽章与标题兜底读 final_stance、改判条件卡读 invalidation_items（direction 枚举+text，代码装配）、portfolio_actions、confirmation_cost、state_diagnosis；运行时校验核 evidence_refs 存在性、正文数字 token、冲突回应。代码读不懂散文这件事不因接力形态改变，所以 JSON 缩成回执单：枚举、编号、要害清单归它，散文归文件。
2. **隔离从物理降成纪律——属实，且比现在更脆弱。** 一个此前没说透的事实：主链岗位现在是**单发结构化调用**，模型手上根本没有读文件的工具（引擎用"强制指定单个函数"的方式收 JSON，唯一可调用的函数就是输出契约本身）。所以今天的隔离是物理的——没有通道。改成能读文件后，隔离变成工具白名单策略（每岗只挂一个只读目录）。策略就有执行不到的 bug 面，这是真实的降级。缓冲：阅读清单由代码按岗位生成（菜单即合约），文件系统层再卡一道只读目录。
3. **漫游病——属实。** 补一刀量化：阅读清单生成器就是新的装配器，"代码选材料"换成了"代码选菜单+模型选材料"，选错的责任从代码挪给了模型。菜单设计的纪律因此和今天装配器的纪律同级重要。

## 老板没提到的三坑

1. **与"flash 一次跑通"标准冲突——最实际的成本。** 主链每站现在是一次调用；档案室形态是 agent 循环（读清单→读文件→写稿），每站变多轮。flash 在多轮工具使用上的翻车率显著高于单发补全——"flash 一次跑通全链"的合格标准会变成"flash N 轮跑通"，轮数每加一，失败面乘一次；延迟与费用同乘。
2. **时点纪律与可复现。** 回测要求晚于 effective_date 的材料不得进上下文。现在装配器按日期过滤，是物理保证；档案室的目录里同时躺着各期文件，模型自己读就可能读到"未来"。解法：目录按回测日生成快照——档案室其实是"每期一间快照室"，不是常设大阅览室。
3. **审计与重放的锚变了。** 现在提示词逐字落盘=完美重放。档案室形态下提示词只有清单，正文取决于模型读了什么——必须同时落盘三样：清单、读文件的工具轨迹、被读文件的内容哈希。缺一样，事后对账对不回去。好在这三样都是代码能做的形状检查，不违反少闸门原则。

## 可行性：dsh 复用的真实成本

事件层已在 dsh 底盘上跑自主调研（组合渲染、经费卡、来源白名单、session 落盘日志对账），"读文件+写文件+落盘轨迹"整套机制现成。主链引擎本来就讲函数调用（结构化输出即靠它实现），加"读文件"工具在协议层面不难。真正的成本在三处新工程：每岗位工具白名单与只读目录策略；菜单生成器（按岗位+回测日出清单）；回执单 schema 与闸门重指向（身份校验从 JSON 字段改到"文件锚+回执字段"）。估量：新器官级别的活，不是补丁；单站试点可控。

## 节奏评判

老板的排序（不混进验证期、原则先进理想版说明书定稿、试点选终审或正方、L1-L5 最后动甚至不动）我同意，补一条更硬的理由：验证期正在测量新教材的语言表现，中途换接力机制等于一次实验改两个变量，五期数据全部作废。试点首站我轻微倾向**正方先于终审**：终审产出直面读者、下游无闸门兜底；正方的输出还要过批评者、修订者、终审三道，翻车有缓冲。L1-L5 不动同意，且判据可以写成一句原理：**推还是拉，取决于载荷是否超过优雅投喂的尺寸**——层站载荷是一小包指标，推既充分又必要；辩论与终审载荷大到装不下（反方假说站 32.4 万字符），拉才有意义。两端分治是"注意力优先"原则的推论，不是妥协。
